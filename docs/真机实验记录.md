# 控制记录与数据采集状态

当前新栈使用有界异步原始 ROS 日志，见 [journal_node.py](../ros2_ws/src/rm65_servo_teleop/rm65_servo_teleop/journal_node.py)。它用于审计输入、控制和反馈，**还不是完整训练数据集**。旧 ExperimentSession/HDF5 结构保留作历史，不是新入口的运行依赖。

## 1 文件在哪里

仿真与设备模式默认记录。每次启动创建唯一 UTC 会话目录：

```text
Linux项目/build/experiments/<UTC时间_随机号>/
  session.json      模式、完成状态、写入计数、丢失/错误与topic覆盖
  records.jsonl     原始消息和接收单调时间；正常封存含log_end
```

Docker 内对应 `/data/experiments`。WSL 本机模式的目录直接位于当前 Windows 仓库；远程模式通过 SSH 查看不等于记录已下载。当前启动器尚未实现远端自动回收、哈希清单封存或 LeRobot 导出。复制目录后需另行校验文件与会话状态，不沿用旧五文件封存器。

## 2 记录语义

记录原始 XR、目标位姿、Grip 使能、PoseTracking/Servo/运输状态、JTC 轨迹/状态、模拟或真实反馈，以及原生发送结果。每条包含 topic、ROS 原始字段及本机接收单调时刻；设备时钟仍保留在消息内。

- `sim` 关节是 GenericSystem 输出，不能标成实测机械臂；
- `hardware-dry-run` 有真实反馈，但没有真实执行指令；
- `hardware` 轨迹目标、SDK 接受和实体执行反馈分别解释，不能把目标当 observation；
- 日志线程不阻塞控制回调，队列满/写失败会使会话无效，并终止当前采集图；设备停止仍依靠接入层和原生 watchdog。

未知的可选 effort/状态加速度以 `null` 保存，`quality.nonfinite_fields` 保留字段路径和 NaN/±Inf 种类；不会改成0。位置、速度、目标或命令轨迹的非有限数使 `quality_valid=false` 并终止采集。ROS String 内部原始 JSON 不在这层递归数值检查范围内。

`complete=true` 仅表示规定 topic 覆盖、数值质量门控与写盘结束条件满足，不证明设备同步、绝对时间精度、轨迹正确或任务成功。2026-10-26 本机仿真已实际验证记录完整落盘，详见[工作日志](logs/2026.10.26.md)。

## 3 距离采集标准还差什么

1. 本机 ROS 编译/模拟输入仿真已通过；继续完成真实 PICO、板端部署、只读状态、现场控制与停止验证。
2. 已有 D435i RGB-D 与 ROH 独立驱动/采集、时钟来源、逐帧缺口及全文件校验，见[外设说明](外设驱动与采集.md)；仍需现场设备验证、同步误差评估、标定与实际任务数据。
3. 明确 action/observation、相机—机器人配对误差、缺失处理、任务/成功标签、Grip 分段与 Episode 边界。
4. 实现可回收校验、Episode 导出及 LeRobot 转换；用多次真实完整任务评估数据质量。

当前只具备控制链记录基础，不能把“日志能写”当作“已经达到模型训练数据标准”。修改和本轮测试证据见[当日日志](logs/2026.10.26.md)。
