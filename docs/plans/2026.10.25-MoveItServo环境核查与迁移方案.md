目标是用 MoveIt Servo 接管连续运动、IK、平滑及模型约束，最终只保留一条正式控制链。仿真与真机切换执行接口；原 `RM65ControlCore` 在迁移验收后退出正式运行。此前“长期保留自研核心，只补 LeRobot 数据工具”的建议不再作为目标架构。

## 2 部署方式

以官方 `ros:humble-ros-base-jammy` 构建干净环境，沿用 Ubuntu 22.04 / Humble 版本组合，舍弃旧镜像里的 Conda 和控制依赖。官方镜像清单包含 amd64 与 arm64v8；板端架构、内存/磁盘、SDK ABI和厂商固件兼容恢复联网后核实，再固定实际镜像 digest 和安装版本。当前不需要为了迁移先升级宿主系统或安装 Isaac Sim。[官方镜像清单](https://github.com/osrf/docker_images/blob/master/ros/ros)

最终运行一套 XR 服务和一套 Servo 控制链。仿真阶段使用隔离的执行端，不能让旧 Python 控制器与新驱动同时连接并指挥机械臂，也不能让两个接收器争用 UDP 8089。

ROS 节点和构建工具统一使用 Ubuntu 系统 Python `/usr/bin/python3`。启动 shell 只加载 `/opt/ros/humble/setup.bash` 与工作空间环境。C++ XR 节点复用原生 SDK，PC Service 按已核对的发行包重新安装到新镜像，避免为读取手柄继承旧 Python 控制包。旧环境仅在切换前保留原样，不是新栈的运行依赖。

候选基础依赖为 `ros-humble-ros-base`、`ros-humble-moveit`、`ros-humble-moveit-servo`、`ros-humble-ros2-control`、`ros-humble-ros2-controllers`、`ros-humble-xacro`、`ros-humble-robot-state-publisher`、`python3-colcon-common-extensions`、`python3-rosdep`。这是待安装清单，须以目标机架构、软件源和实际缺项确认版本并锁定；本轮未安装。

本轮新增 [Dockerfile.moveit](../../docker/Dockerfile.moveit) 和 [compose.moveit.yml](../../docker/compose.moveit.yml)，只准备上述环境，不复制旧控制源码，不启动厂商驱动、XR服务或回位。Compose 默认无网络、无硬件设备映射，命令为等待；后续硬件运行配置必须另经实际接口核对。包版本会在成功构建的镜像内记入 `/opt/rm65-environment-packages.tsv`，该清单不能代替首次成功构建后的版本锁定。

新工作空间中的 ROS 源码计划放 `ros2_ws/src/`，依赖清单纳入版本控制；基础镜像准备阶段 Compose 暂将生成目录 `build/moveit_ws` 挂到 `/opt/rm65_ws`。进入正式包开发时明确挂载源码和生成目录，不能把正式源码只留在被忽略的 `build/` 中。

ROS 控制环在板端运行，Windows 不参与逐周期下发。RViz 可选；无桌面/GPU时优先运行无显示的仿真与记录，不以远程图形转发作为实时控制前提。

## 3 唯一控制链

```text
PICO → XRoboToolkit PC Service
          ↓ 官方 picoxr / xr_msgs
薄输入适配层：有效性、时间戳、Grip、既有侧装映射与锚点
          ↓ target_pose：位置(3,) + 四元数(4,)，m / xyzw
MoveIt Servo PoseTracking（Humble 现成组件）
          ↓ 内部 TwistStamped → Servo IK / 平滑 / 限位 / 碰撞与奇异处理
JointTrajectory：六轴位置，rad，带时间语义
          ↓ 唯一连续指令适配端
仿真执行器 或 rm_driver → RM65
          ↑ /joint_states：实测 q(6,) / qdot(6,)

状态、Servo 状态、提交指令、XR、相机、手反馈
          ↓ 独立记录与 Episode / LeRobot 导出
```

原 `RM65ControlCore`、`damped_ik.py`、Placo IK 和官方 IK 分支都不作为新路线的在线运动生成器。可保留离线回归材料，迁移完成后从正式入口移除选择。输入适配端不重新实现 IK、奇异判据或逐关节轨迹平滑。

模型加载和状态发布必须采用同一组关节名、安装坐标、工具坐标及单位。MoveIt 模型须在多组姿态下与官方 FK/实测 UDP TCP 核对；历史 5 mm / 2°门槛只用于排除明显不一致，不是插接任务的精度认证。

## 4 可以复用的上游代码与接入缺口

### XR 输入

[XRoboToolkit-Teleop-ROS](https://github.com/XR-Robotics/XRoboToolkit-Teleop-ROS) 已有 `ros2/picoxr` 与 `ros2/xr_msgs`，使用 `/opt/apps/roboticsservice/SDK`，发布 `xr_pose`，消息包含设备时间戳、头显、手柄、Grip 与 Trigger。

不能原样认定为板端可用：其 [CMake](https://github.com/XR-Robotics/XRoboToolkit-Teleop-ROS/blob/main/ros2/picoxr/CMakeLists.txt) 把库目录写为 `SDK/x64`。若板端为 ARM64，需按真实路径选择库并核对 ABI。其 [publisher.cpp](https://github.com/XR-Robotics/XRoboToolkit-Teleop-ROS/blob/main/ros2/picoxr/src/publisher.cpp) 在长度异常时仍继续复制 pose，且手柄 status 写为常数；集成时须补齐长度/有限值/四元数和实际状态检查，设备时间停滞不得通过重打主机时间戳变成新输入。

### Servo 与位姿跟随

[Humble Servo](https://moveit.picknik.ai/humble/doc/examples/realtime_servo/realtime_servo_tutorial.html) 的常规输入是 `TwistStamped` / `JointJog`；不能照搬 main 分支的直接 Pose 接口。[PoseTracking](https://github.com/moveit/moveit2/blob/humble/moveit_ros/moveit_servo/src/pose_tracking.cpp) 是该版本现成的位姿误差到 Twist 的组件，可接 `target_pose`，无需再写一套 PID 或微分 IK。

Panda 示例只用于参数结构。机器人组名、TCP、planning_frame、关节限位、控制周期、超时和平滑参数须替换为现场 RM65 配置；官方示例奇异阈值不是旧 SVD 的 `0.04/0.01`，不能按数值直接搬用。

### RM65 执行

[官方 ros2_rm_robot](https://github.com/RealManRobot/ros2_rm_robot/tree/humble) 提供 `rm_driver`、模型和 MoveIt 配置。其 [rm_control](https://github.com/RealManRobot/ros2_rm_robot/blob/humble/rm_control/src/rm_control.cpp) 主要接 `FollowJointTrajectory` action；Servo 连续发布 `JointTrajectory` topic。需要一个有界、只保留最新有效流的指令适配端，按关节名和执行时间映射到官方 `movej_canfd_cmd`，不能每帧塞入一个完整 action，或任取第一/最后一点忽略时间语义。

官方 RM65 [ros2_control xacro](https://github.com/RealManRobot/ros2_rm_robot/blob/humble/rm_moveit2_config/rm_65_config/config/rm_65_description.ros2_control.xacro) 使用 `mock_components/GenericSystem`，源文件明确注明仅仿真。不能把它当成已具备真机硬件插件。仿真可使用该模拟接口；真机按已核对的官方驱动接入。

驱动状态与停止适配属于设备连接职责：输入/输出过期、断连、控制器错误须阻断新指令并执行已验证停止；保存停止请求与实测速率，满足明确释放/重新使能条件后才能恢复。此层不再调用自研 IK。具体超时、阈值、停止和恢复差异要在实施前列出旧/新行为及验证结果，不暗中放宽。

## 5 参数与行为迁移

| 当前行为 | 新路线的处理原则 |
| --- | --- |
| 50 Hz；平移1.0、旋转0.25；冻结的侧装映射 | 作为初始对照条件，全部由同一份配置解析；新求解器最终周期以板端测量确定 |
| Grip 0.2/0.15；新段以实测状态重建锚点 | 薄输入适配层保留同样操作语义，重建前不下发追赶旧目标的运动 |
| TCP 0.05 m/s、0.25 rad/s；关节型号速度10% | 显式约束 Servo 输出并实测。MoveGroup 的 `default_velocity_scaling_factor=0.1` 不能直接当作 Servo 已限至10%的证据 |
| 自研方向判据、局部步长、加速度规则 | 由 Servo 及其标准插件替换；算法和数值行为不承诺与旧实现逐帧等同，比较安全拒绝、连续性和任务表现 |
| 松 Grip、故障、输入掉线与 UDP 失效的停止/锁存 | 逐项建立行为对照与真机验证；Servo 的“停止发消息”不自动证明机械臂已经静止 |
| B/Home 与启动回位 | 纳入 MoveIt 执行与唯一命令所有权；保留既有操作要求，并单独验收路径、取消和故障。不能在新链旁边偷跑旧直发分支 |

仿真和真机加载相同控制配置与模型。模型参数可以来自启动时只读查询或已校验快照，但进入求解器后的内容必须相同；设备地址、传输与显示开关属于执行适配配置。

## 7 恢复联网后的只读检查

本轮新增 `scripts/tools/inspect_moveit_environment.py`。它经 SSH 在内存运行诊断代码，查询系统、Python、ROS安装前缀、选定的软件包、SDK目录、Docker元数据和相关监听端口。不会启动 `ros2` discovery daemon、ROS节点或容器；不会导入/初始化硬件 SDK，不连接机械臂，不读取整个环境变量或凭据。

在 Windows 仓库根目录执行，输出文件须使用一个未存在的路径：

```powershell
python scripts/tools/inspect_moveit_environment.py --ssh-host rm --sudo-docker --output build/validation/moveit_environment_after_power_on.json
```

默认先尝试普通 Docker 读取；`--sudo-docker` 仅在失败后尝试非交互的 `sudo -n docker` 只读命令。脚本不安装依赖、不修复权限，也不启动离线容器。缺 Docker/权限/容器时保留对应错误。SSH失败退出码为2，不能误读成ROS已缺失或机器人控制失败。

本机检查可用 `--local`。报告只描述执行时实际读到的环境；容器中的系统 Python 与 Conda 版本分别记录，包可见性不等于库 ABI、设备通信或运行周期已经通过验收。
