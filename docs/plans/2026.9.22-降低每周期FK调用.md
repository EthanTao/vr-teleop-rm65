# 降低每周期 FK 调用：三个核心思想的落地设计（2026-09-22）

状态：**历史设计提案；2026-09-23 已落地更保守的 bounded-search 版本，并通过目标容器 1000 周期 Dry Run 计算/准入时序验证；真实 `movej_follow`、XR 主循环、机械臂跟踪与物理安全仍待验收**。

> 当前代码没有引入本文 §3.3 的零空间自运动，也没有在危险区退回昂贵的四点精确搜索。实际实现采用一次数值 Jacobian + 常数时间 J3/J5 局部门控；SVD ratio 单独进入硬区且无法廉价证明改善时直接保持。默认硬上限为 18 ms、16 次 FK、3 个局部候选；离线计数为无输入 13、正常 14、结构最坏 16。目标容器 1000 周期完整 `_send_motion` Dry Run 为 median 10.169 ms、P95 11.782 ms、max 14.397 ms。详见 `docs/2026.9.23.md`。下文保留为历史方案与归因依据，不再代表当前调用链。

依据的既有实测（全部来自 [../决策与结论汇总.md](../决策与结论汇总.md) §2.10；原始日志见 `docs/archive/2026.9.22.md`）：

- 每周期 FK 位姿数：正常跟踪 **74**、空输入 **13**、最坏（多因子重试）**222**；容器上 `DampedIK.step` 整步 **89–110 ms**，预算 20 ms。
- 容器单价：组合调用约 **1.2 ms/次**（裸官方 FK 0.147 ms），Python 级 numpy 原语约 **40 µs/个**；一次周期 559 个原语运算。
- 归因：**逃逸相关 60/74 = 81%**（路径过滤 48 + 逃逸探测 12），DLS 本体只有 13（雅可比 12 + 种子 FK 1），候选步 1。
- 数学上限：即便每次调用压到裸 SDK 成本 0.147 ms，`20 ms / 0.147 ms ≈ 136` 次是绝对上限，而最坏需要 222 次 → **必须降次数，不能只降单价**。

| 阶段 | FK 次数 | 代码位置（`hardware/damped_ik.py`） | 判据真正需要的信息 |
| --- | --- | --- | --- |

| 种子位姿 | 1 | `step()` L241 | 末端参考位姿 |

一句话：**5/6 的雅可比与 SVD 是为「奇异保护」付的**，而其中 48 次是为「沿路径逐点重算整个雅可比」付的。

## 2. 三个核心思想 → 三处乘数

| 思想 | 对应的浪费 | 目标 | 降次数 |
| --- | --- | --- | --- |
| ① Singularity Avoidance（提前知道危险） | 用 6 次完整雅可比去**发现**危险，而不是用廉价信号提前预警 | 危险信号改为角域/结构量预测 + 雅可比低频刷新；只在真正需要时付费 | −60 |
| ② Velocity Scaling（防止突然炸） | 逃逸探测为回答"要不要提速"付 12 次 FK；`scale` 每周期独立取值，可来回跳 | 一个平滑、单调、有变化率限制的标量替代探测 | （含在上行） |
| ③ Null-space Optimization（根治 74 次搜索） | 4 因子 × 4 采样点的搜索，是在用数值方式"找"一个本来就存在的方向 | 用 SVD 域直接选步（最小范数 + 可证单调的零空间修正），一次通过，不再搜索 | 因子重试 222 → 单次 |

三者不是三个并列优化，而是**同一个乘数的三处**：把"用完整雅可比判"换成"用一阶预测判 + 关键点精确核"。

## 3. 逐项设计

### 3.1 ① Singularity Avoidance：抓 48 次里的 47 次

**现状**：`path_allowed` 对 `fraction ∈ {0.25, 0.5, 0.75, 1.0}` 每个采样点都调用 `metrics()`，而 `metrics()` = 12 次中心差分 FK + 1 次 SVD。

**事实**：一次周期的关节位移是有界的（`|Δq| ≤ 速度上限 × dt`，且候选已按 `speeds*dt` 缩放），四个采样点都在**同一条极短线段**上。因此

```
J(q + αΔ) ≈ J(q) + α · (J(q + Δ) − J(q))
```

在 0.05 m/s、20 ms 的量级上完全成立（Δ 量级 1e-3 rad）。

**改法（判据不变，只是不再逐点重算）**：

1. 端点雅可比照旧精确算 **一次**（候选步终点本来就要 `forward`，顺带取一次 `metrics`；只需补 12 次 FK，或直接复用 §3.3 的"刷新"雅可比）。
2. 中间采样点的 `σ` 用 **J 的一阶变化 + 奇异值一阶扰动** 预测：
   - 对 `(J + αΔJ)` 用 `σ_i(α) ≈ σ_i(0) + α · u_iᵀ ΔJ v_i`（`u, v` 取自端点/种子 SVD），或更省：只维护 `ΔJ` 的 Frobenius/行范数代理；
   - ratio 预测 = `σ̂_min / σ̂_max`，同样只用标量。
3. **J3/J5 零位符号判定完全不变**（本来就是标量读关节角，零成本）。
4. **安全兜底**：只要 `severity > 0`（已在减速区）或 `σ̂_min/σ̂_max < slowdown_ratio`，该分支**退回原精确判据**（逐点重建雅可比）。也就是说：清晰区省 48 次，危险区一分不省——危险区本来就已经被速度缩放压到低速，20 ms 预算更宽裕。

**代价**：`path_allowed` 48 → **1～13**（仅端点精确）。

### 3.2 ② Velocity Scaling：抓 12 次，并顺手修掉"来回跳"

**现状**：`improving` 是一次完整雅可比（12 次 FK）换来的布尔值，只用于决定 `scale` 是否抬到 `escape_speed_scale`；而 `scale = max(min_speed_scale, 1 - severity)` 每周期独立重算。

**改法**：`improving` 改为一阶量，零 FK：

```
预测 ratio 变化  Δ(σ_min/σ_max)  ←  同一端点一阶预测（§3.1 已算出）
预测 J3/J5 是否有界改善          ←  纯标量
```

再把 `scale` 变成显式的一阶平滑 + 单调：

- 降速立即生效（`scale_new = min(scale_pred, ...)`）；
- 升速有变化率上限（例如每周期不超过 `+0.1`/`dt`），避免日志里 `tracking scale=0.194` 与 `severity=1` 交替；
- `slowdown_ratio / stop_ratio / 15° / 5° / 0.05 / 0.1 / 0.08` **阈值一个不改**，改的只是"何时允许回到高速"。

**收益**：−12 次 FK；手感上消除"忽快忽慢"，同时不降低危险区的保守性。

### 3.3 ③ Null-space Optimization：把最坏 222 拉回单次

**现状**：因子循环 `{1.0, 0.5, 0.25, 0.125}` 逐个试，每个候选都要付 4 采样点路径过滤；最坏 4 次全试 = 222 次 FK（与日志 `period_max=280.35ms` 吻合）。**这是在用数值搜索代替解析选择。**

**观察**：RM65 在奇异附近雅可比降秩，`J` 的零空间维度 ≥ 1。此时**存在一族不改变末端位姿的关节自运动**（典型：J4 与 J6 的耦合）。现有的"逐个因子试探"实际上是在用 4 个尺度去碰这个方向。

**改法**：在 SVD 域直接构造步长，不再搜索：

```
Δq = V · diag( s / (s² + λ²) ) · Uᵀ · e        # 现有 DLS，最小范数解
   + N · k                                      # N = 零空间基（σ ≈ 0 的右奇异向量）
```

- `k` 的选取只依赖**已算出的 SVD**：在零空间里找"最能把 `σ_min` 抬起来且不增加末端误差"的一小步（一阶即可，`k` 有界且要过现有速度/加速度限幅）；
- 因为零空间分量**在数学上不改变末端误差**，候选步天然满足"末端误差不增"，因子循环的多次重试不再必要 → **搜索 4 次 → 1 次**；
- 危险区的严格"只能改善"判据不变，只是不再靠穷举来满足它。

验收必须逐位对拍：同一批位形上比较新旧 `step` 的返回（关节角、`ratio`、`status`），差异只允许出现在"旧的被拒、新的通过"这一侧，且必须逐条人工核对是否真的在改善。

### 3.4 并入：把精确核放在"最关键的一次"，而不是"每一次"

统一后的每周期结构：

```
① 廉价预警  结构量 / 一阶预测        → 0 次 FK          （提前知道危险）
② DLS 本体  1 次精确雅可比 + SVD     → 13 次            （唯一必需）
③ 步长平滑  标量变化率限制            → 0 次            （防止突然炸）
④ 候选选择  SVD 域构造 + 零空间修正   → 0～1 次          （根治搜索）
⑤ 端点核验  精确 ratio + 可达位姿     → 0～1 次（复用）
⑥ 危险兜底  退回原逐点精确判据        → 仅危险区付费
```

**典型跟踪**：约 **13～15 次 FK**（现在 74）。按容器 1.2 ms/次折算约 17 ms，叠加已完成的运算层重写（559 运算）后应显著低于该值；**最坏情况与典型情况同阶**（不再有 222 次），这是与当前实现最本质的差别——现在的 20 ms 锁存正是被最坏情况触发的。

## 4. 分阶段实施与验收

| 阶段 | 内容 | 每周期 FK | 风险 | 验收 |
| --- | --- | --- | --- | --- |
| **S1** | 逃逸探测复用 `step` 已算出的 `u, s, vt` 做一阶估计（只在 `severity>0` 时启用，清晰区保留精确判定） | 74 → 62 | 低 | `count_dls_fk_calls_by_outcome.py` 计数；随机位形上 `improving` 布尔值新旧对拍 |
| **S2** | 路径过滤：端点精确 + 中间点一阶预测，危险区自动退回精确 | 62 → 14～26 | 中（**改保护判据，需用户明确批准**） | 同批位形上 `path_allowed` 判定逐位对拍，逐条列出差异；[../真机安全与故障处理.md](../真机安全与故障处理.md) 边界不变 |
| **S3** | `scale` 变化率限制（只改"何时允许回到高速"） | 不变 | 低 | 长时 dry-run 日志：`scale` 不再来回跳；危险区行为逐条比对 |
| **S4** | 零空间修正 + 取消因子重试 | 最坏 222 → ≤ 20 | 中（**改搜索形式，需单独评审**） | 新旧 `step` 返回值对拍；最坏情形计数从 222 降到 20 以内 |
| **S5** | 环境侧并行排查：容器「单次 numpy 运算 40 µs」的根因（`--micro` 的纯 Python 对照行 + `cpu/wall`） | — | — | 若为整机算力问题，则上述次数目标必须更激进 |

每一阶段的硬性要求（沿用项目纪律）：

1. 先写对拍脚本、**看它失败**，再接线；
2. 对拍用例按真实调用序列构造（不是随机均匀采样——第九轮的教训）；
3. 任何"未通过逐位对拍"的数值路径一律回退，不留在产品路径里；
4. 阈值、锁存、20 ms 超时、发送策略在 S1–S4 中全部不变；
5. 改完在 `docs/` 下按日期追加工作日志（改了什么、验证状态、未验证项），并同步 [../决策与结论汇总.md](../决策与结论汇总.md) §2.10 的数字。

## 5. 必须由用户先确认的三件事

1. **S2 改 `path_allowed` 的判据形式**（采样点由"精确重算"改为"一阶预测 + 危险区退回精确"）。这是保护判据改动，本提案默认不做。
2. **S4 引入零空间修正**（会在危险区产生新的关节运动方向，虽然理论上不改变末端误差）。需要明确"允许机械臂在危险区做自运动以脱离奇异"这一行为是期望的。
3. **危险区是否允许"更慢但完整"**：即在 `severity>0` 时接受典型 74 次（约 35–50 ms）并放宽 20 ms 判据为"仅清晰区要求 20 ms"，还是坚持全场景 20 ms。这决定了 S2 是否需要"危险区退回精确"这条兜底。

## 6. 本提案明确不做的事

- 不用 URDF / 结构链的雅可比批准任何真机运动（[../真机安全与故障处理.md](../真机安全与故障处理.md) 与 CLAUDE.md 第 11 条）。
- 不改 `slowdown_ratio=0.04`、`stop_ratio=0.01`、`15°/5°`、`min_speed_scale=0.05`、`escape_speed_scale=0.1`、`max_damping=0.08`。
- 不改 20 ms 超时拒绝语义、故障锁存与解锁流程、关节/速度/TCP 边界、锚点与 seed 策略、发送策略。
- 不在本提案中触碰「批量帧合成」（已三轮未通过对拍，正式停止）。
