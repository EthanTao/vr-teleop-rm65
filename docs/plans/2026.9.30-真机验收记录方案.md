# RM65 真机验收记录方案

原始日期：2026-09-30。范围更新：2026-10-02。

2026-10-26 路径说明：下文旧 Python 记录实现、测试和分析脚本已移入[源码归档](../archive/2026-10-26-legacy-control/README.md)。本文保留历史设计；当前记录行为见[实验记录](../真机实验记录.md)。

状态：记录功能设计草案。第一版定为原始数据归档、事件与简要 Markdown 摘要；HTML 报告暂缓。2026-09-30 的合成交互演示保留用于说明，尚未接入真实记录链路。

## 1. 要解决的问题

验收结束后，需要回答四个问题：操作者做了什么，程序如何处理，向机械臂发送了什么，控制器反馈发生了什么。再把这些记录与操作者看到的现象对上时间。

第一版的目标是：启用记录后从启动自动记录整场实验；自动保存状态事件；人工标记可选；退出后拿到完整实验目录与简要 Markdown 摘要。即使操作者只描述某段现象，也能按时间核对相关数据。

## 2. 当前基础与需要补齐的地方

已检查当前工作区源码，已有：

- 推荐真机入口的 `--motion-log-path`，开启后记录逐控制周期 JSONL。
- `hardware/motion_diagnostics.py` 的有界队列、后台写盘、丢行/写入错误统计和 `log_end` 收尾。
- XR 位姿、Grip、目标/候选位姿、微分 IK 与奇异保护诊断、关节候选/准入状态、发送结果、UDP 末端反馈等字段。
- `scripts/debug/analyze_motion_log.py`、`estimate_teleop_mapping.py`、`report_teleop_acceptance.py` 三个离线工具。

需要补齐：自动建立实验目录、完整运行配置、事件时间线、反馈样本关联、可选人工标记、简要摘要，以及容器日志持久化和本地取回。交互图表不在第一版范围。

旧的 `common/data_collector.py` 与归档采集方案面向 Grip 分段的模仿学习数据。验收记录应覆盖启动、空闲、回位、保持、故障与停止，不应仅在 Grip 按住时保存。

### 必须先明确字段语义

当前遥操作分支的 `target_xyz` 来自映射后的目标，位于笛卡尔限速之前；`command_xyz` 在 `_send_motion()` 的 `finally` 中填入，是限速后的候选位姿，拒绝或保持时也会出现。

因此，不能把 `command_xyz` 非空解释为“已下发”，也不能把发送函数返回成功解释为“机器人已经运动”。新报告统一按以下阶段说明：

| 阶段 | 记录 | 可支持的判断 |
|---|---|---|
| 操作者输入 | 原始 XR 位姿、Grip、XR 时间戳、实际用于控制的样本标志 | 手柄输入是否变化，是否被本周期使用 |
| 映射与限速 | 映射目标、限速后候选位姿 | 输入如何变为候选目标，限速压缩了多少 |
| 微分 IK 与准入 | 关节候选、被接受关节目标、保持/拒绝原因、已有求解诊断 | 本周期哪些目标获得准入 |
| 本机发送 | 发送尝试、结果、传输完成时间 | 本机是否完成对应发送；不证明远端执行 |
| 控制器反馈 | UDP 关节角/速度、TCP 位姿、错误码、样本接收时间 | 控制器上报的实际状态及新鲜度 |

不改旧字段的历史含义；增加格式版本和明确的新字段，离线兼容旧日志。TCP 反馈是控制器上报的位置，不是外部视觉测量的真值。

### 当前算法的名称

报告统一称为“基于 SVD 的微分 IK 链路”。当前核心使用带数值下限的奇异值倒数计算关节步长，随后经过方向可行性、速度/加速度、跟随余量和路径准入检查。经典 DLS 的 `σ/(σ²+λ²)` 权重已不参与步长计算；`damping` 仅作诊断。源码中的 `dls_*`、`damped_ik_movej_follow` 等名称属于历史接口，记录原值便于核对，不把它们解释成当前仍使用阻尼最小二乘。

## 3. 现场使用流程

1. 启动现有 Dry Run 或真机模式时，增加一个拟议的 `--record-session` 选项，自动创建实验目录。明确显示本次模式、目录、记录状态；不需要手写 JSONL 路径。
2. 启动前填写可选的一句话，例如“验收上下方向跟随”；实际生效配置、代码版本和坐标系信息自动保存。
3. 从启动检查到退出持续记录。Grip 按下/松开用于划分操作段；回位、重新使能等另有事件，不截断整场记录。
4. 人工标记可选：看到卡顿、抖动或方向异常时，可用控制台 `m` 键留书签。按键不是开始记录的条件，不按也持续保存。只记录编号与时间，说明在安全停止后补写。实施时先确认与现有键盘调参不冲突，并限制为支持的 Linux TTY；没有 TTY 时仍能完整记录及事后添加标记。
5. 故障锁存、微分 IK 保持、发送失败、XR/UDP 过期等由程序自动标记，无需操作者察觉后才保存。
6. 正常停止后完成日志收尾，生成简要 Markdown 摘要。随后由现有启动器取回本地，显示取回状态和目录路径；取回失败可重试，保留远端原文件。

`--record-session`、`m` 标记及自动报告均是拟议接口，目前尚未可用。真机原有启动、运动与停止流程不因记录选项增加额外动作。

## 4. 第一版记录内容

### 2026-10-02 最终字段范围

记录完整的“手柄输入 → 映射目标 → 限速候选 → 微分 IK/准入 → 本机发送 → UDP 反馈”链条。下面列的是功能设计要求，不表示当前日志已全部具备。

| 数据组 | 第一版必须保存 | 记录频率与用途 |
|---|---|---|
| 实验信息 | 实验 ID、开始/结束时间、目的或备注、真实运行/Dry Run、控制频率、实际生效参数、代码提交与指纹、型号/SDK、坐标系和 DH/工具帧快照 | 启动/退出时保存；解释是哪份代码和参数产生的现象 |
| 周期时间与状态 | 周期编号、单调时间、周期开始/结束或耗时、控制状态、当前 Grip 段/锚点 ID | 每周期；将不同层的数据放到同一条时间线上 |
| 手柄输入 | 原始 SDK 位姿 `(7,)`、Grip 值、XR 时间戳、读取有效性、新鲜度、样本是否进入控制计算 | 每周期保存本周期已取得的输入；保留原格式并注明 XYZW 顺序 |
| 锚点与映射 | Grip 建锚时手柄和控制器 TCP 位姿；映射后的目标 XYZ `(3,)` 与 WXYZ 四元数 `(4,)` | 锚点建/重置时存事件快照，周期引用其 ID；目标每周期存 |
| 限速候选 | 限速后 XYZ `(3,)`、WXYZ 姿态 `(4,)`、限制器线/角速度 | 每周期；区分映射目标与真正交给求解器的候选 |
| 微分 IK 与准入 | seed 六轴角度、候选六轴角度、通过准入的六轴目标、是否接受、保持/拒绝状态和原始原因；方向可行性指标、奇异指标、速度缩放、跟随余量缩放 | 发生对应计算的周期；解释目标为何缩小、保持或被拒绝 |
| 命令发送 | 本周期是否尝试发送、实际传入发送层的六轴目标、命令类型、开始/结束时间、发送结果、最终编码目标/载荷（复用已有发送诊断） | 每次发送尝试；区分获得准入、进入发送和本机传输完成 |
| UDP 反馈 | 同一数据报的六轴角度 `(6,)`、角速度 `(6,)`、TCP XYZ `(3,)`/WXYZ `(4,)`、错误码、接收时间/样本 ID，以及控制用与周期末观察用反馈的关联 | 每周期引用最新已有快照；同一个旧包再次使用时保留相同样本标识 |
| 时序与完整性 | IK 耗时、FK 调用数、候选尝试数、发送耗时、实际周期/错过周期、反馈年龄；丢行/写入错误、退出原因和正常收尾 | 周期或汇总；区分计算阻塞、反馈过期和记录本身不完整 |

关节角统一为 rad，角速度为 rad/s，位置为 m；摘要可转换为度和毫米。记录格式明确每种姿态的四元数顺序和坐标系。

某周期没有求解/目标/发送时，对应字段为 `null` 或显式“未发生”，不复制上一周期的结果冒充新结果。若保留上一已接受/已发送参考，使用单独字段并附关联周期。未完成发送的目标不写作“已发送目标”；本机完成发送不写作“已执行”。

同时保存状态事件：启动/预检结果、Grip 按下/松开、锚点建立/重置、回位请求与开始/结束、保持进入/退出、故障锁存/解除、软/硬停止请求及确认/失败、退出、记录器异常。事件至少含时间、类型、关联周期和原因；人工备注按“操作者观察”存，不替代程序原因。

第一版不要求保存每周期完整 Jacobian/SVD 矩阵、每个候选的全部中间计算、原始网络报文、相机视频或音频。保存已有计算结果和必要诊断即可，避免为记录增加 FK 或设备查询。

### 整场元信息

保存实验 ID、北京时间、运行主机、真实运行/Dry Run 标志、完整解析后的配置、Git 提交号与相关控制代码指纹、工作区是否有修改、模型/SDK信息、DH/工具帧与坐标变换快照或可核验引用。

只存提交号不足以复现有未提交修改的运行；代码指纹与配置快照应对应实际运行端。对未读取到的信息写明未知，不猜测。

### 控制周期数据

按现有控制频率记录，入口当前默认 50 Hz。保存周期编号与采样时间，以及上述五个阶段的可用数据。关节角为 `(6,)`，位置为 `(3,)`，姿态为 `(4,)`；格式中明确单位、坐标系、四元数顺序。原始 XR 格式与控制器 WXYZ 姿态分别注明。

优先复用已经读取和计算的数据；不为了记录额外调用 SDK FK、主动查询机械臂或重复取一份 XR 样本作为“本周期使用输入”。诊断用观察样本和控制实际使用样本需要区分。

### 反馈关联

同一份 UDP 快照的关节角、速度、TCP 位姿、错误码和接收时间一起保存，用接收时间或样本序号识别重复使用。

当前 TCP 记录在周期结束时另取最新反馈，不能直接假定它与周期中使用的关节反馈来自同一数据报。新记录需要分别标注“控制使用的反馈”和“周期末观察到的反馈”，或明确对应的样本 ID。

使用同一进程的单调时钟计算间隔，记录时间原点对应的北京时间用于阅读。XR 设备时间戳、远端容器时钟与本地摄像时钟不能直接相减；没有校准的时延不标成实测端到端延迟。

### 事件与主观观察

自动记录启动结果、Grip 边沿、锚点建立、回位开始/结束、保持状态切换、故障锁存/解除、停止及退出原因。事件包含时间、关联周期、原始原因和可读说明。

人工标记保存编号和时间，备注保留为“操作者观察”。报告把它与“日志证据”“待验证解释”分别展示。

## 5. 输出与报告

生成物遵循仓库约定，放在 `build/` 下。拟议结构：

```text
build/experiments/20260930_153000_<session-id>/
  session.json       # 配置、版本、坐标系、时间原点
  motion.jsonl       # 原始逐周期证据
  events.jsonl       # 自动事件与人工标记
  console.log        # 启动失败、异常堆栈与现有终端输出
  summary.md         # 时长、操作段、事件、保持原因和数据完整性摘要
```

`console.log` 由启动器或独立输出链路保存，不在实时控制循环中同步写文件。元信息和启动事件先建立，再进入控制器启动，避免启动预检失败时毫无记录。

第一版摘要包含：

- 模式、配置摘要、实际记录时长和证据完整性；缺收尾、丢行、写入错误明确显示。
- 每段 Grip 的手柄位移、映射目标变化、接受命令变化与反馈运动，保留方向和单位。
- 各类保持时间占比、故障事件次数、反馈重复/过期情况及控制周期统计。
- 对异常给出证据，例如“输入持续变化，连续若干周期的关节目标未被接受，原因是方向保护”；不足以区分通信、执行或外部阻挡时保留待验证项。

PNG 曲线按复盘需要离线生成，不作为第一版采集流程的必需产物。交互式 HTML 和标记点击跳转均暂缓，原始字段保留后续绘图所需的时间与关联信息。

不能只用净位移跟随比判断体验：往返运动的净位移接近零，即使跟随良好也会出现失真的比值。保留已有指标，并补充有效运动区间、轨迹误差和足够激励下的滞后估计；没有可用样本则显示“证据不足”。

比较机械臂跟随误差时，优先比较实际被接受的关节目标与反馈；若需要对应 TCP 目标，使用已有最终 FK 结果或依据本次模型快照离线计算。限速候选 TCP 不自动等于微分 IK 最终接受目标的 TCP。

已有验收判据继续作为单独的离线 CLI 工具使用，显示采用的阈值及适用条件；结果区分“达到选定判据”“未达到”“证据不足”。保护功能的专项试验允许预期保持/锁存，不直接按普通跟随试验的零故障条件判失败。

## 6. 实时性、故障与保存边界

- 复用现有有界异步写盘；控制线程只复制必要数据并做非阻塞入队，图表和报告在停止后生成。
- 高频周期数据和重要事件设独立容量或预留空间；容量耗尽时记录丢失计数与时间范围，不静默声称事件完整。
- 写盘失败和磁盘满应让记录状态变为失败，并明确提示；记录器不阻塞控制循环、不屏蔽控制故障，也不替代现有停止链。
- 增加定时刷盘，建议目标间隔不超过 0.5 秒，结合吞吐实测调整。进程强杀或断电仍可能丢失尾部；缺少正常收尾时只提供可恢复部分，不判为完整验收。
- 当前仓库 Compose 文件没有实验目录的持久化挂载。实施时检查真实运行容器的挂载，再配置可写的宿主机目录或卷；不能仅保存在会随容器重建丢失的位置。
- 本地取回后核验清单与校验和。保留远端原件，避免将传输失败当成采集失败。

## 7. 分期实现

第一期：复用现有 JSONL 链路，明确字段语义，补配置快照、关联反馈、启动/状态事件、自动目录与持久化取回；先让一次运行留下完整证据。

第二期：增加可选人工标记、Markdown 摘要，并复用现有离线分析工具；让时间和事件能对应原始记录。HTML 暂缓。

第三期：按实际需求加入相机视频或手机视频导入。固定机位拍全机械臂、工具端和任务区；采集独立运行，记录帧时间戳/丢帧。手机视频使用共同可见事件人工对齐并标注精度，未经校准不声称毫秒级同步。视频用于观察接触、遮挡和机械抖动，不能替代遥测。

第一版优先完成前两期的数据记录与摘要；人工键盘标记为可选增强。视频、HTML、训练数据导出和实时 3D 重放均留待后续明确需求。

## 8. 完成条件与分层验证

1. 主机离线：用录好的输入分别开启/关闭记录，检查接受/拒绝结果、目标命令、停止和锁存逻辑一致。构造保持、发送失败、反馈过期、写盘错误、队列溢出和截断日志，验证报告没有假“完整”或假“执行”。
2. 目标容器：检查目录可写、持久化、停止收尾、取回与配置指纹；测量记录入队开销及整个周期的 p95/p99/max。建议记录开销 p99 不超过 0.5 ms，作为待验证的设计目标，不能替代整周期截止时间检查。
3. Dry Run：确认输入、目标、保护与事件能记录，并始终标注“不下发运动”；固定反馈不被解释为运动跟随失败。
4. 现场低速真机：按现有验收流程收集一次已授权实验，核对一个人工标记和一个自然出现的状态切换。无需专门制造危险故障来验证记录器。
5. 操作者只需提交整个实验目录和标记编号，复盘者能说明输入、准入、发送和反馈各自发生了什么；记录不足时能指出缺失证据。

实现代码时按 `CLAUDE.md` 要求追加当日工作日志，分开报告主机测试、容器检查、Dry Run 和真实运动验收结果。
