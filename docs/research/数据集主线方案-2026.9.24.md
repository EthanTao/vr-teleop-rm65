## §1 定位：不拼规模，拼"唯一性"

### 1.1 先说清楚规模差距（这是残酷事实）

| 数据集 | 规模 | 出处 |
|---|---|---|
| AgiBot World | **1,000,000+** 轨迹 / 217 任务 | arXiv:2503.06669 |
| RoboMIND | **107k** 轨迹 / 479 任务 / 4 本体 + 5k 失败演示 | RSS 2025, DOI 10.15607/RSS.2025.XXI.152 |
| DROID | **76k** 轨迹 / 350 h / **13 家机构** | RSS 2024, p120 |
| Open X-Embodiment | 汇聚 **60 个数据集** / 22 本体 / 1M+ 轨迹 | ICRA 2024 最佳会议论文 |

**本项目现状**：`DataCollector` 只写 HDF5（关节 / 末端 / delta / grip），**仅仿真、无相机、无夹爪、无真机采集，episode ≈ 0**。

**差距是 2–3 个数量级。** 硬拼规模这条路不存在。

### 1.2 但有三条别人抄不走的差异化（已核实为空白）

**① PICO 是空白。** 已核实的头部数据集用的是：DROID → **Oculus Quest 2**；Fourier ActionNet → **Apple Vision Pro**。调研结论原话：**"仍无任何基于 PICO 的大规模数据集被核实"**。本项目用的 PICO + XRoboToolkit（SDK 本身已发表，SII 2026，DOI 10.1109/sii64115.2026.11404528）在这条线上是首次。

**② 安装朝向是空白。** 现有数据集的机器人全部是规范安装（Franka 在桌面、人形在地面）。RM65 官方支持"任意角度安装"，但**没有任何数据集把"底座朝向"当成一个受控自变量**。
- 相邻工作：Mobi-π（CoRL 2025，PMLR v305）研究的是**移动底盘的摆放位置**；Hierarchical Equivariant Policy via Frame Transfer（ICML 2025）是 frame 层面的方法。**都不是数据集，也都不覆盖安装朝向。**

**③ 运动学约束事件流是独有的。** 调研结论：**"绝大多数遥操作数据集仍只保留成功演示"**，采数时失败片段被丢弃，导致策略没见过失败、不会恢复（RoboMIND 的 +5k 失败演示是少数例外）。
而本项目手上有：UDP 实时遥测（关节速度 / 限位 / 跟踪误差 / 错误码）+ `damped_ik` 的逐步指标（SVD ratio、predicted_ratio、speed scale、damping）+ **故障锁存 / 解锁事件**。这意味着可以给**每一帧**自动打上运动学状态标签。**别的采集端没有这些遥测通道。**

### 1.3 一句话定位

> **「首个带安装朝向自变量与运动学约束事件标注的 VR 遥操作数据集」**

**核心科学问题**（数据集只是载体，这个问题才是论文）：

> **当机器人本体不变、只有安装朝向改变时，学到的策略会失效吗？如果失效，主因是视觉（看到的世界转了）还是动作空间（基座坐标系与重力方向变了）？**

这个问题：是新的、可答的（对照实验）、有工业动机（任意角度安装是现场现实）、且**必须依赖 ③ 的标注才能回答**（要靠运动学状态解释失败原因）。

## §2 数据规格

### 2.1 模态与字段

| 组 | 字段 | 频率 | 现状 |
|---|---|---|---|
| **观测 · 本体** | 六关节角、关节速度、TCP 位姿、跟踪误差、错误码 | 50 Hz（UDP） | ✅ 遥测已有，待落盘 |
| **观测 · 视觉** | 腕部相机（随 TCP）、第三人称相机 ×1–2 | 30 Hz | ❌ 待接入 |
| **观测 · 场景** | 场景描述、物体初始位姿、语言指令 | 每 episode | ❌ 待建 |
| **动作** | VR 手柄 delta 位姿、grip 值、**实际下发关节目标**、夹爪开度 | 50 Hz | 🟡 部分（无夹爪） |
| **🆕 运动学事件** | `ratio`(σ_min/σ_max)、`predicted_ratio`、`speed_scale`、`damping`、`status`(tracking/hold_singularity/escaping/hold_joint_margin/hold_at_target)、J3/J5 距零位、关节限位余量 | 50 Hz | 🟡 变量已在 `damped_ik.DampedStep` 里，只需落盘 |
| **🆕 安全事件** | 软停止 / 硬停止 / 故障锁存 / 解锁 / 看门狗超时 / 超速判定 | 事件流 | 🟡 状态机已有 |
| **元信息** | **安装朝向**（核心自变量）、映射矩阵、scale_factor、操作者 ID、时间戳对齐信息 | 每 episode | ❌ 待建 |

> **关键设计**：`DampedStep` 的字段是现成的（见 `xrobotoolkit_teleop/hardware/damped_ik.py`），落盘是**低成本高回报**的一件事，而且它是整个数据集差异化的来源。优先做。

### 2.2 时间同步（必须做对）

XR 时间戳（`timeStampNs`，已由 SDK 提供）、50 Hz 控制周期、相机帧、UDP 遥测必须**对齐到同一时钟**。
调研发现"遥操作专用时间同步 / 时钟偏移估计"在网络口径下是 2023–2025 的**空白**——所以这块做扎实，并在论文里单独成节写清楚，本身就是一个卖点。

### 2.3 存储格式

- **采集端**：保持 HDF5（`DataCollector` 现有结构），但拆分为 `obs` / `action` / `events` / `meta` 四组
- **发布端**：转 **LeRobotDataset 格式**或 RLDS，并提供 HDF5 原始版
- **元数据**：**Croissant**（NeurIPS D&B 硬性要求）

## §3 采集方案

### 3.1 规模目标（按"能回答科学问题"倒推，不按"对标 DROID"）

| 维度 | 目标 | 理由 |
|---|---|---|
| **安装朝向** | **3 种**（桌面水平 / 侧装 90° / 斜装 45° 或倒装） | 核心自变量，最少 3 个才能看趋势 |
| **任务** | **6 个** | 覆盖：纯平移拾放、需姿态对准的插装、需绕障、接触密集、长程多步、精细对准 |
| **每（任务 × 朝向）** | 50 条成功 + 15 条含失败/恢复 | 便于做筛选实验 |
| **合计** | **900 条成功 + 270 条失败恢复 ≈ 1,200 条** | |
| **总帧数** | ~30 s/episode @ 50 Hz ≈ 1,500 帧 → **~180 万帧** | 加 2 路相机后数据量可观但不夸张 |

**效率估算**（参照实测：UMI 手持 111 demos/h；SpaceMouse 35 demos/h；本项目 VR + 真机 + 复位 → 估 **20–40 demos/h**）：
→ 1,200 条 ≈ **30–60 小时纯操作时间**，摊到 3 个月、每周 5–8 小时，**完全可行**。真正的成本在调试与复位，不在操作。

### 3.2 采集协议（写进论文的 rigor）

- **操作者**：≥3 人，每人跨全部（任务 × 朝向）采集 → 以便分析操作者方差
- **物体初始位姿**：随机化，但记录真值；每种朝向用**同一套随机种子** → 保证跨朝向可比
- **成功判据**：客观、可自动判定（例如物体落入目标区 + 姿态误差阈值），**不用人工打分**
- **失败保留**：不丢弃失败片段，标注失败类型（碰撞 / 超时 / 掉件 / 安全停止触发）
- **每次采集**：记录完整 `meta`（安装朝向、映射矩阵版本、scale_factor、操作者、时间）
- **伦理**：涉及人体被试（操作者）→ **必须 IRB**；第三人称相机若拍到人 → 需知情同意

### 3.3 质量控制（提前防三类废数据）

1. **映射方向错**：先完成逐轴实测定案（`docs/RM65参数与坐标系.md` §14 的真机栏至今为空）。**方向没定案前采的数据全部作废。**
2. **事件标签错位**：采样频率不同（控制 50 Hz vs 相机 30 Hz）→ 必须有明确的重采样与对齐策略
3. **写盘拖垮实时性**：采集不能挂在 50 Hz 控制循环里 → **异步写盘 / 双缓冲**，并实测采集开启前后的周期时序（当前整链 median 10.2 ms / max 14.4 ms，预算 18–20 ms，余量不大）

## §4 评测与下游实验（数据集论文的命门）

> **没有下游结果的"数据集论文"必被拒。** DROID / OXE / RoboMIND / AgiBot World 全都训练了策略。

### 实验 1：跨安装朝向迁移（🔑 核心洞见）

- **训练**：朝向 A 数据 → **测试**：朝向 A / B / C
- **对照**：三朝向混合训练
- **分离变量**：把动作表示换成**安装无关表示**（相对轨迹 / 任务空间 / 重力对齐系），看能否恢复性能 → **回答"视觉 vs 动作空间哪个是主因"**
- **指标**：成功率 + **本数据集独有的运动学指标**（接近奇异频率、安全停止次数、平均 speed_scale）

### 实验 2：演示质量筛选（🎯 最容易出漂亮结果）

- 用 §2.1 的运动学事件给 1,200 条演示打分 → 按 100% / 50% / 33% / 25% 筛选
- 画"成功率 vs 数据量"曲线
- **对标 CUPID**（CoRL 2025, PMLR v305:2907–2932，**<33% 筛选数据即达 Robomimic SOTA**）
- **这个实验几乎不需要额外硬件，且直接命中 2024–25 最热的子问题**

### 实验 3：失败/恢复数据的价值

- 仅成功 vs 成功 + 失败恢复
- 测**恢复能力**：人为施加扰动后策略能否回到任务

### 基线与算力

| 项 | 选择 |
|---|---|
| 策略基线 | **ACT**、**Diffusion Policy**（标配、开源、算力友好） |
| 加分项 | π0 / openpi 微调（若算力允许） |
| 主结果 | **真机实验**（最强证据） |
| 仿真评测 | ⚠️ **不要只用 LIBERO** |

**关于基准选择的重要提醒**：调研核实到审计论文 *What Are We Actually Benchmarking in Robot Manipulation?*（arXiv:2606.04233）发现 **LIBERO 既是社区最常用、也最容易被刷分**——一个 **0.09B 且无语言编码器**的探针即达到/接近报告 SOTA，且多数报告的提升**无法证明统计显著**。
→ 若用仿真，选 **RoboCasa / RoboTwin 2.0**（诊断通过项更多），或在报 LIBERO 时**同时回答那四项诊断**。

## §10 与 IEEE VR 副线的关系

两条线**共用同一套基础设施**：真机验收、逐轴实测、相机接入、IRB。区别只在数据处理方式。

- **主线（本方案）**：采集 → 训练 → 数据集论文
- **副线（人因）**：用同一套设备与被试，在采集间隙做"模型-现实不一致"或"参考系"的用户研究 → IEEE VR 2028

**建议**：**先打通采集再开副线**，不要同时开工。副线可以复用采集数据里的操作者主观评分（TLX / SUS），边际成本很低。
