# 2026.9.27 工作日志

## 启动自动回位取消确认口令（默认），改为「打印偏差 + 目标 + 3 s 缓冲」

### 背景

现场启动真机入口时终端停在：

```
[INFO] 固定六轴 Home deg=[0.0, 0.0, -60.0, 0.0, 60.0, 0.0] 奇异比=0.09695 TCP_xyz_m=[0.1854, -0.0026, 0.8326]
[HOME] 请确认整条回程路径净空、急停就绪，且允许机械臂低速移动到 0 0 -60 0 60 0。
请输入 'HOME 0 0 -60 0 60 0'：
```

用户要求这里**不要再要口令**：初始位置本来就停在固定 Home `[0, 0, -60, 0, 60, 0]`，
每次启动都要手打一遍坐标没有必要。本次明确选择的是最彻底的方案 ——
**即使实测关节确实偏离 Home，也不要求任何确认输入，直接自动低速回位**。

### 旧行为 / 新行为 / 风险（改动仅此一处语义）

`RM65ControlCore.run()`（`xrobotoolkit_teleop/hardware/realman_rm65_safe_teleop_controller.py`）
里 `auto_home_on_start` 分支的判据是「实测六轴与固定 Home 的最大偏差 > `--home-joint-tolerance-deg`（默认 `1°`）」。

| | 旧行为（2026-09-24 起） | 新行为（2026-09-27 起） |
|---|---|---|
| 判据 | 同上，未改 | 同上，未改 |
| 人工输入 | `input()` 要求精确输入 `HOME 0 0 -60 0 60 0` | **默认不读 stdin**；打开 `--home-start-confirmation` 才恢复旧口令门 |
| 输错口令 | 打印「未收到确认口令；已取消启动回位」并 `return`，整个程序退出（既不回位也不进入遥操作） | 仅在新开关开启时保留该语义 |
| 回位前提示 | 只有口令行 | 打印实测偏差量（含容差）与目标角度，再按 `--home-start-delay-s`（默认 `3.0 s`）逐秒打印倒计时 |
| 缓冲期中止 | 无（在 `input()` 里等） | 倒计时期间 `Ctrl+C` → 外层 `KeyboardInterrupt` 分支 → `finally` 走 `arm.stop()` / 关闭（不会进入遥操作循环） |
| 回位本身 | `_start_reset` → 软停止 → 等关节静止 → 关节插值 `movej_follow` | 完全相同，一行未改 |

**未改动的语义**（复核过，不是本次改动范围）：偏差容差与判据阈值、`_start_reset` /
`_tick_reset` / `_send_home_joint_waypoint` 发送链、关节插值、回位时长下限
（`max(reset_duration_s, 2 × 限速行程)`）、逐周期 UDP 新鲜度 / 跟踪误差 / 关节限位 / 超速 /
控制器错误码检查、故障锁存、B 键复位路径、`--enable-home-path-preflight` 预检开关。

**风险（用户已知情并在本次明确选择）**：启动即运动 —— 程序不再等人工敲键盘，
所以净空与急停必须在**启动程序之前**就位；如果操作者还没准备好，机械臂仍会在
`3 s` 缓冲后开始低速回位。可用的现场手段：缓冲期内 `Ctrl+C` 或拍急停中止；
`--home-start-delay-s` 加长缓冲；`--home-start-confirmation` 恢复旧的精确口令门。
口令门原来附带的「迫使操作者读一遍目标角度」的效果由新打印行承担（会同时打印偏差与目标）。

### 未取证的现场数据（如实记录）

口令行被触发说明当时实测六轴与 Home 的偏差 **> 1°**，但用户本次选择「不用管」，
因此**没有**取到偏差数值，也没有排查这 1°~若干度来自重力下沉、上一次回位残差还是别的原因。
本次改动不依赖该数值：判据本身未动，下一次启动打印的
`[HOME] 实测关节偏离固定六轴 Home X.XXX°（容差 1.000°）` 会直接给出准确偏差。

## `teleop.py` 精简重写（纯重构，行为不变）

### 背景

用户要求「重写 `teleop.py`，让它变得更简洁」。这份脚本从 2026-07 的 rsync/scp 方案一路演进，
留下了一批**没人调用的旧包装**和三份**互相平行的模式表**（`MODE_SCRIPT` 容器命令、`TUNNEL_SPEC`
隧道端口、`show_menu()` 里手写的编号 `if/elif` 链）。三处都描述同一件事，改一个模式要动三个地方。
本次只做等价重构：**不改同步判据、不改启动命令、不改隧道端口、不碰任何运动/安全参数**。

### 改动内容

| 类别 | 内容 |
|---|---|
| 删死代码 | `run_step()`（旧 rsync 设计的通用命令包装，早已无调用）、`RSYNC_PATH`（只用于一句日志）、`PYPROJECT_REL` / `PYCACHE_REL`（`SOURCE_PATHS` 化之后从未被引用）、`_normalize_relative()` / `_matches_rule()`（并入 `_is_excluded()`）、`cleanup_and_exit()`（并入 `_on_signal()`） |
| 合并模式表 | 新增 `ModeSpec` dataclass + `MODE_SPECS`，一个模式一行：菜单短标签/标题/说明文案、容器内命令、隧道端口。原 `MODE_SCRIPT` + `TUNNEL_SPEC` + `show_menu()` 的手写分支全部由这张表派生；菜单文案逐字保留（编号、缩进、条目间空行、「机械臂 IP」行都一样，唯一差别是旧版 `[4]` 后面用来对齐宽标签的两个空格变成一个） |
| 收敛远端执行 | `_remove_remote_files()` 从 `Popen` + `communicate` 改为 `subprocess.run(input=..., stderr=STDOUT)`；`_read_remote_manifest()` / `_write_remote_manifest()` 的错误分支合并成「一次 try + 一次 returncode 判断」 |
| 内嵌脚本瘦身 | `_REMOTE_DELETE_SCRIPT`（在容器里跑的那段删除程序）用 `fail()` 收掉重复四次的三行失败分支，删/剪空目录、哈希校验、`CHANGED` 拒删语义一字未改 |
| 隧道全局态 | `start_tunnel()` 自己写入全局 `tunnel_process`（`run()` 不再需要 `global`）；`stop_tunnel()` 先把句柄取到局部再清空全局，进程已退出时直接返回（原来会把死进程留在全局变量里） |
| 健壮性 | `cleanup_container()` 加 `OSError`/`SubprocessError` 兜底（原来本机没有 `ssh` 时会抛异常打断启动），清理失败只跳过、不拦启动 |

**刻意保留、一行语义都没动的部分**：`SOURCE_PATHS` / `SYNC_EXCLUDE` 的取值与匹配顺序（`*.egg-info/`
这条规则本来就因为「先判 `/` 结尾」而匹配不到，本次**照旧不修**，避免顺手改同步范围）、本地缓存
`签名 → 哈希`、远端清单作准绳的「跳过上传」判据、上传用 tar 流经 ssh 直接解包（不落本地临时文件）、
`_REMOTE_DELETE_SCRIPT` 的「远端被手改过就拒删并失败」、`_resolve_local_cache()` 的 `build/tmp/`
改道、TTY 检测（`-t` / `-it` vs `-i`）、信号处理退出码 `0`/`1`、以及测试钉住的所有函数名
（`_file_sha256`、`_file_signature`、`_iter_source_files`、`_load_manifest`、`_save_manifest`、
`_read_remote_manifest`、`_write_remote_manifest`、`_upload_changed_files`、`_remove_remote_files`、
`_REMOTE_DELETE_SCRIPT`、`_resolve_sim_home_joint`、`SSH_PATH` / `TAR_PATH` 等）。

规模：`teleop.py` **840 → 750 行**（`black --line-length 120`）。行数只降约 11%，因为大头是同步链本身的
逻辑；真正的收益是三份平行表合成一份、旧包装清零、每处远端调用的错误分支从两套变一套。
