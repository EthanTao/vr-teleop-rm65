# PICO 手柄仿真操作手册

当前日常仿真仅保留 PICO 手柄输入。2026-11-12 已删除键盘/按钮控制台、mock 自动轨迹及官方 IK 独立无手柄演示。Servo 与官方 IK 仍分别保留，能力范围见[双版本说明](双版本跟随说明.md)。

两版均已提供PICO + MuJoCo 4浏览器入口：`python start.py pico --browser --controller official` 或 `--controller servo`，网页 `http://127.0.0.1:8094/`。桌面及终端菜单提供两版选择，完整操作见[PICO浏览器双版本仿真](PICO浏览器双版本仿真.md)。下方不带`--browser`的命令仍对应原生3.12 Servo仿真。

## 1 启动

Windows 使用 WSL2 `RM65-Servo` 的 ROS2 Humble / MuJoCo 环境，不需要给机器人及配套板通电。配置见[本机部署](本机仿真部署.md)。

```powershell
python start.py pico --check-only  # 仅预览，不启动环境或配置网络
python start.py pico              # 实际启动 PICO / Servo 仿真
python start.py pico --rviz       # 可选 TF、模型和目标调试窗口
```

也可运行 `python start.py`，在桌面控制台选择 PICO 遥操作仿真。底层入口为 `python teleop.py --mode sim --input pico`，默认仿真输入也是 pico。`--input external` 用于接入已有 XR 发布者或测试夹具，不生成输入数据。

## 2 接 PICO

PICO 与 Windows 电脑需处于可互通的局域网。启动器校验本机 LAN 地址、准备专用 TCP63901 转发；头显按日志显示的地址手工连接 XRoboToolkit，开启 Controller / Send。多网卡时使用 `--listen-address` 指定本机地址。网络要求及排查见[部署页](本机仿真部署.md#真实pico输入)。

先释放右 Grip，再握住开始跟随，松开结束本段。新段以当前实测 TCP 和手柄位姿建立锚点；输入跳变、掉线、时间停滞或反馈失效后，须先释放再握住。当前没有 B/Home 或启动自动回位。

## 3 查看与复位

默认通过 WSLg 打开 MuJoCo，RViz 关闭。`--rviz` 仅用于 WSL sim，不能与 `--no-viewer` 同用；后者关闭 MuJoCo 窗口和 Foxglove。Foxglove 备用地址为 `ws://127.0.0.1:8765`，不提供键盘/按钮输入页面。

聚焦 MuJoCo 窗口按 R 可结束旧控制图并重建初始会话；重连后先释放 Grip。Backspace、终端或浏览器中的 R 不触发此复位。物理进度暂停或失效会结束控制图，不能恢复旧目标继续追赶。

控制配置来自 [teleop.yaml](../ros2_ws/src/rm65_servo_teleop/config/teleop.yaml)，执行器参数见 [mujoco.yaml](../ros2_ws/src/rm65_servo_teleop/config/mujoco.yaml)。MuJoCo 动力学尚未实机辨识，手、相机支架和插拔场景仍待完整建模。

## 4 排查与退出

- 收不到手柄数据：确认头显连接的是启动日志中的 Windows LAN 地址、Controller / Send 已开启，双方网络允许互通。
- 握 Grip 不跟随：检查 `/rm65/input_status` 的输入、反馈及 TF 年龄和故障原因，先释放 Grip；不通过放宽保护恢复。
- 结束会话：Ctrl+C 或桌面“结束当前会话”；进程结束不等于实体机器人停止已确认。

真机继续使用 `python start.py real`，按[真机安全与故障处理](真机安全与故障处理.md)完成现场验证。本轮移除仿真入口没有改动真机执行和停止规则。内部 ROS 测试使用 `python teleop.py --mode test`，合成输入只限隔离测试，不安装为用户运行入口。
