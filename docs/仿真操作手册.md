# 仿真操作手册

当前只有一条运动链：**InputAdapter → PoseTracking → MoveIt Servo → JointTrajectoryController（JTC）→ MuJoCo / 真机设备接口**。无手柄控制台和 PICO 只提供不同输入；GenericSystem 保留为控制图诊断设备。旧 Placo / official / shared-dls 已退出入口。验证范围见[当日日志](logs/2026.10.28.md)，软件仿真不替代实体 PICO 和真机验收。

10月28日跟踪已改善，但断流残余仍有1.322mm，超过原1mm筛查线，详见[跟踪验收](仿真跟踪验收.md)。当前MuJoCo前三轴执行器增益为未辨识假设；软件测试通过不能替代真机性能验收。

## 1 环境与启动

机器人断电时，使用本机 WSL2 `RM65-Servo`，ROS 在同一 Docker 中运行。根目录推荐先运行统一菜单，也可直接调用单个入口：

| 入口 | 输入和执行端 |
| --- | --- |
| `python 启动.py` | 交互菜单：1 无手柄仿真、2 PICO 仿真、3 板端只读、4 正式执行、5 高级设置、0 退出 |
| `python 启动无手柄仿真.py` | 浏览器键盘/按钮 → 本机 MuJoCo |
| `python 启动PICO仿真.py` | 真实 PICO → 本机 MuJoCo |
| `python 启动真机.py` | 交互终端无参进入真机子菜单；显式参数走同一板端链 |

两种仿真入口默认只打开 MuJoCo，RViz 关闭，可用 `--rviz` 或 `--no-viewer` 调整。`--check-only` 仅离线验证参数和预览，不启动 WSL、不枚举网卡、不请求提权；PICO 地址未指定时提示在执行时选择。自动演示 mock 仅保留下方原 CLI，无独立快捷入口。详见[本机部署](本机仿真部署.md)。

推荐终端用 `python` 运行；双击 `.py` 依赖 Windows 的 Python 文件关联，不保证一键可用。普通 CLI 默认退出不等待，`--pause` 显式等待退出按键；经 Windows 资源管理器（Explorer）启动的 Python 独立控制台会等待 Enter 防止闪退。启动器显示阶段状态并保存 `build/logs/startup/*.log`。

```powershell
python teleop.py --mode sim --input manual --print-command
python teleop.py --mode test
python teleop.py --mode sim --input manual
python teleop.py --mode sim --input pico
python teleop.py --mode sim --input manual --target wsl --rviz
```

第一条只打印。WSL 模式直接读取本机仓库，构建 `rm65-servo:humble`，没有 SSH 或远端同步；Linux 本机用 `--target local --no-sudo-docker`。远程模式才同步到板端 `vr-teleop-rm65-servo`，`--host` 修改 SSH 别名。

`test` 在无网络、无硬件映射容器中验证实际 ROS 图，需要观察模拟关节反馈变化和松 Grip 后稳定。自动演示仅保留为 CLI `python teleop.py --mode sim --input mock`：约15秒的小幅运动后释放 Grip 并保持。CLI 省略输入仍默认为 mock，无手柄 Python 入口则明确选择 manual。

## 2 无手柄控制台

运行 `python 启动无手柄仿真.py`，待服务就绪后点击终端地址 [http://127.0.0.1:8766](http://127.0.0.1:8766)。**入口不自动打开浏览器。** 保持控制页面处于前台，在显示就绪后再操作。

键盘需要持续按住 **Space + 对应字母键**；鼠标可持续按住页面方向按钮，无需同时按 Space。方向以 `base_link` 坐标系为准：

| 动作 | 正方向 | 负方向 |
| --- | --- | --- |
| X 平移 | Space + W | Space + S |
| Y 平移 | Space + A | Space + D |
| Z 平移 | Space + R | Space + F |
| 绕 X 旋转（RX） | Space + J | Space + L |
| 绕 Y 旋转（RY） | Space + I | Space + K |
| 绕 Z 旋转（RZ） | Space + U | Space + O |

目标增量速率为平移 **20 mm/s**、旋转 **0.12 rad/s**。这是输入目标速率，实际反馈受 Servo、执行器与物理计算影响。单次持续使能段的平移偏移上限为 **10 cm**，旋转向量上限为 **0.16 rad**；达到上限会撤销操作，须松开再按，不能持续按住追赶。每个新段仍由原 InputAdapter 以当前实际 TCP 重新锚定。

松开使能键/按钮、窗口失焦、页面隐藏或连接中断都会撤销操作；恢复后必须重新按下，不自动续动。Esc 或页面“停止操作”同样撤销当前输入，不执行 Home。页面未就绪、状态过期或出现须释放提示时，先松开全部键和按钮，检查状态后再操作。

页面分别显示：

- MuJoCo 的实际关节 `q/dq`（页面单位 °、°/s），及关节限位余量；不是把输入目标当成反馈。
- 根据反馈与 TF 得到的实际 TCP、目标 TCP、位置/姿态误差。
- 反馈年龄、InputAdapter/PoseTracking/Servo 状态及须释放/重启原因。

这些是物理仿真反馈，不是实体 RM65 数据。MuJoCo 执行器参数尚未辨识，手、相机支架与插拔场景尚未完整建模。manual 输入只允许 `sim`，不能用于真机或 Dry Run。

2026-10-27跟踪性能测量尚未通过：移动位置P95约12.1–12.3mm，部分固定目标保持6秒仍未到位，先改善响应再接真机。测试时方向归零但继续保持Space，才能观察固定目标收敛；松开Space会停止跟随。三次重复、停止与漂移结果见[仿真跟踪验收](仿真跟踪验收.md)。

## 3 接 PICO

选择 `--input pico` 时构建原生 XR SDK 适配节点，并启动 XR PC Service。本机 WSL2 使用[部署页](本机仿真部署.md)的 Windows 局域网地址及转发设置；板端运行时填写板端实际地址和 `63901`，开启 Controller + Send。ARM64/x64 库按构建平台选择；真实头显及板端 ABI 尚待确认。

Windows 运行 `python 启动PICO仿真.py`，检查 WiFi 地址并通过专用 `scripts/setup/connect_pico_wsl.ps1` 准备本项目 TCP 转发。地址有歧义时用 `--listen-address` 显式指定，WSL 名称用 `--distro` 指定。`--check-only` 不读取网卡、不启动 WSL 或请求提权；仅实际执行 PICO 模式时读取局域网并准备转发，manual 和 mock 均不需要。实体头显的无线连接、遮挡与方向仍需单独验收。

启动时先松开右 Grip；反馈和 TF 新鲜后按住 Grip 跟随，松开保持。每次新按 Grip 都以当前 TCP 重建锚点，避免追赶上段目标。发生输入跳变、时间停滞、掉线或反馈失效后，须先释放 Grip 再重新按住。

平移比例 `1.0`，旋转比例 `0.25`；使用既有侧装映射。显示中的竖立安装是候选值，方向判定仍需现场实测。**当前没有 B/Home 或启动自动回位。**

## 4 查看与参数

本机 WSL 默认通过 WSLg 只打开 MuJoCo，无需额外 Windows X Server，RViz 默认关闭。物理计算在 MuJoCo，运动跟随、IK 和模型保护由同一 Servo 控制节点完成。检查 TF、模型或目标时显式加 `--rviz`；仅支持 WSL sim，不能与 `--no-viewer` 同用。`--no-viewer` 关闭 MuJoCo 窗口和 Foxglove，manual 控制台仍由输入节点提供。

远程 viewer 会将 `8765` 转发到本机，manual 仿真另转发 `8766`。Foxglove 备用地址为 `ws://127.0.0.1:8765`，可查看模型、TF、关节和目标；它不同于 HTTP 控制台。

控制参数唯一来源：[teleop.yaml](../ros2_ws/src/rm65_servo_teleop/config/teleop.yaml)。关节控制器配置：[controllers.yaml](../ros2_ws/src/rm65_servo_teleop/config/controllers.yaml)。更新源码后重新启动，镜像摘要或SDK配置不匹配时重建；不支持旧终端热调参。

manual网页每10ms续租，租约为30ms；电脑卡顿、后台标签页限频或网络延迟会更早停止，须松开后重新按住。此项只用于无手柄模拟控制台，PICO与真机的200ms输入门限保持原值。

Linux 图形桌面可直接运行 `ros2 launch rm65_servo_teleop teleop.launch.py mode:=sim input_source:=manual mujoco_viewer:=true`；ROS launch 的 `rviz` 默认 false。无桌面时将 `mujoco_viewer` 与 `rviz` 均设为 false。`--simulator mock` 仅供 GenericSystem 诊断，如需窗口须显式加 `--rviz`。物理假设见 [mujoco.yaml](../ros2_ws/src/rm65_servo_teleop/config/mujoco.yaml)。

## 5 真机入口与退出

`python 启动真机.py` 共用 `teleop.py` 的原有板端路径。正式执行必须显式给出机器人可访问的板端 `--udp-ip`、有效 `--hardware-validation` 与人工 `--live-ack "RM65 LIVE VALIDATION"`。板端位置和控制器地址可用 `--host`、`--remote-dir`、`--arm-ip` 指定。交互终端无参（或仅 `--pause`）显示真机子菜单：1 只读、2 反馈查询、3 PICO 输入查询、4 正式执行、5 高级设置、0 退出。只读和查询直接使用已确认的默认地址与目录，不再逐项提问；选 5 才修改本次菜单参数，选 4 仅询问验收文件与人工确认，留空返回。只读与查询不要求手柄在线、不使能运动。非交互无参仍只列缺项并退出，不连接、同步或部署；`--check-only` 仅离线参数验证和命令预览。模板和口令不能替代现场证据。`--dry-run` 仍会连接真实控制器读反馈，须显式提供 `--udp-ip`；详见[真机安全与故障处理](真机安全与故障处理.md)。

## 6 排查

- SSH 失败：先确认板子供电、联网与 `ssh rm`；这不说明 ROS 包缺失。
- MuJoCo 暂停/重置：物理进度保护会结束当前会话；重新启动，禁止恢复暂停前目标继续追赶。
- 控制台打不开：等待本次 manual 服务就绪，确认地址为 `http://127.0.0.1:8766`，不要把 Foxglove 的 ws 地址当网页。
- 控制台已连接但不动：检查“未就绪/须释放/段限位”原因，先松开全部按键和按钮再重新按；不要关闭碰撞或放宽保护。
- 模拟不动：保留输入状态、PoseTracking/Servo 状态与关节反馈；检查模型碰撞、奇异区、TF 和时间戳，不先放宽阈值。
- WSL时间回退：若出现 `feedback_time_regressed` 且多个进程日志的时间同时倒退，按[本机部署的校时说明](本机仿真部署.md#环境维护)核对重复校时，不放宽反馈时间检查。控制台只保留一份，避免两个页面争用输入。
- PICO 无输入：确认镜像以 SDK ON 构建、服务只运行一份、63901 可达、头显发送正常。
- Foxglove 无连接：确认启动器启用 viewer，SSH 本地 8765 未被占用。
- 构建失败：保存 Linux 构建日志；Windows 静态检查不能证明 C++/ROS ABI 已通过。

Ctrl+C 中断当前会话并以 130 退出；这不证明实体已经停止，真机必须另行核对停止结果、真实反馈和实体静止。启动器日志保存于 `build/logs/startup/*.log`；本机 WSL 的实验记录直接写入当前 Windows 仓库 `build/experiments/`，远程模式才需要下载回收。详见[实验记录](真机实验记录.md)。
