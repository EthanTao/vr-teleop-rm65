### 通信参数、数据格式与寄存器

依据：[傲意 Modbus Gen1](https://oymotion.github.io/ROHand/ROH-Protocols/OHandModBusRTUProtocol_Gen1/)、[Gen2](https://oymotion.github.io/ROHand/ROH-Protocols/OHandModBusRTUProtocol_Gen2/)、[睿尔曼 JSON Modbus 指令](https://develop.realman-robotics.com/robot/json/modbus/)及上述 RM65 示例。

- RS485 通信参数：115200 bps、8 数据位、1 停止位、无校验。
- RM65 末端主站选择 `port=1`；官方示例从站 `device=2`，这是示例/出厂默认值，实际地址须核实。
- 配置命令为 `set_modbus_mode`，`timeout` 单位为 **100 ms**，最小有效值 `1`。即使设为 `0`，控制器也按 `1` 处理；不能误读为 1 ms。
- `write_registers` 每次最多写 10 个寄存器；六通道一次写入 `num=6`，JSON `data` 实际装 **12 个字节**，各 16 位值按高字节、低字节排列。RTU 帧及 CRC 由 RM65 转发层处理。
- 单寄存器读取使用 `read_holding_registers`；六寄存器读取使用 `read_multiple_holding_registers`，返回 12 字节，再按 `(hi << 8) | lo` 解码。

下表六通道地址在核对的 Gen1、Gen2 及官方 RM65 v1 寄存器定义中一致；其他能力仍需按实际版本选择，不能由此推定全部固件兼容。

| 内容 | 十进制地址 | 编码 / 作用 |
| --- | --- | --- |
| 协议、固件、固件修订、硬件、Boot、节点 ID | 1000–1005 | 启动身份核对；协议版本高字节为主版本、低字节为次版本；只读身份，不改写 ID |
| 六通道状态 | 1085–1090 | 包括运动、到位、过流、堵转；状态 5 表示堵转停止，不能直接标记“抓取成功” |
| 六电机电流反馈 | 1105–1110 | 电机侧状态；不等于指尖实测接触力 |
| 六通道逻辑速度 | 1125–1130 | 逻辑位置/秒；保守初值需要结合实机验证 |
| 六通道目标位置 | 1135–1140 | `uint16[6]`；五指弯曲 0 张开、65535 闭合；第六通道为拇指旋转 |
| 六通道实际位置 | 1145–1150 | `uint16[6]`，与目标位置分别记录 |
| 六通道实际角度 | 1165–1170 | `int16[6]`，单位为 0.01°；按标准二进制补码解码 |

**通道顺序**：`[拇指弯曲, 食指弯曲, 中指弯曲, 无名指弯曲, 小指弯曲, 拇指旋转]`。这是电机/主动自由度向量 `(6,)`，不是 11 个独立关节角，也不是机械臂六关节。采用通用 `set_hand_*` 便捷接口前必须另外核对支持的手型、固件和通道顺序，本方案使用已查证的通用 Modbus 路径。

### 当前源码中的实际接入点

- `scripts/hardware/teleop_realman_rm65_safe_hardware.py` 使用 `RealmanRM65SafeTeleopController`，该类直接继承 `RM65ControlCore`；默认 50 Hz。接入应落到此控制核心及独立手驱动，历史通用控制器的 gripper 占位并不自动覆盖当前真机路径。
- `xrobotoolkit_teleop/common/xr_client.py:get_key_value_by_name()` 已支持 `right_trigger`；当前核心 `_read_control_state()` 读取 Grip 和 B 键，没有读取手的目标或反馈。
- `_run_teleop_cycle()` 有未按 Grip、回位、故障重使能等提前返回分支。新增手状态处理必须明确各状态是否接受指令，不能简单加在“臂运动发送”之后。
- `hardware/interface/realman_rm65.py:send_movej_follow_joint_rad()` 当前只发送机械臂目标；没有 ROHand Modbus 封装。`send_json()` 同步等待响应并共享 socket timeout、`_recv_buffer`，没有并发锁和响应分发；不能让运动线程与手线程并发调用同一个接口实例。
- 当前 Grip 松开调用机械臂 `slow_stop()`；这不构成灵巧手停机或释放策略。机械臂故障锁存也不自动停止独立手驱动。

### 建议实现结构（尚未实现）

```text
XR 输入：Grip / B / Trigger
  ├─ 现有 RM65ControlCore → 映射、限幅、IK、准入 → movej_follow（50 Hz）
  │                                         ← 独立 UDP 实测反馈
  └─ 手状态机 → 有界目标映射 → uint16[6] → 最新目标槽 → 独立手通信模块
                                      ↓
                       JSON/Modbus → RM65 末端 RS485 → ROH-LiteS001
                                      ↑
                     时间戳 + 实际位置/电流/状态 + 通信结果
```

1. **先做独立、默认只读的预检模块**：显式指定协议/地址，读取身份与状态；禁止自动上电、复位、校准、张开或闭合。当前 Modbus 未配置时，启用模式属于单独的配置步骤，不能伪装成只读查询。
2. **新增 `ROHandRM65Modbus` 驱动与工作线程**：六通道范围、有限值、端序、响应类型/长度、`write_state/read_state`、异常及时间戳校验。仅一个未完成请求；目标槽只保留最新值，空间 O(1)，每包六通道编码 O(6)。请求超时后标记通信失效，处理迟到回复，禁止把旧回复当作下一次同名请求确认；重连不代表旧动作已取消。
3. **传输隔离需先验证**：优先评估手专用 TCP 连接，前提是现场控制器允许多连接，且 Modbus 请求/超时不会阻塞运动与停止命令。仅新开线程或给旧 socket 加锁不能解决最坏阻塞。若独立连接仍阻塞控制器，应调整通信方式或使用独立 USB-RS485；不能宣称现接法已满足实时性。
4. **初始调度建议**：手目标最多 10 Hz，位置/电流/状态各 2 Hz，变化过小不重复发送；这些是待验证的起始配置，不是设备实测能力。50 Hz 主循环只发布最新目标/读缓存，不等待手的通信。厂家对手端的命令处理频率说明不等于经 RM65 转发后的端到端频率。
5. **操作映射建议**：保留 Grip 控臂、B 回位；Trigger 输入通过已标定的张开/抓枪预设映射为六通道目标，拇指旋转使用独立预设并避免与手指碰撞。持物阶段保持抓取，使用显式释放动作；不因 Grip 松开、输入失联或程序重启自动张开。具体按键和手故障是否联动停臂需在实现评审中定案，不能替换现有安全判据。
6. **实验记录**：拟记录 Trigger、手状态、目标 `(6,)`、实测位置/角度/电流/状态 `(6,)`、采样时间、指令确认与时延；缺失反馈标无效，不填造“抓取力”。记录通信失败与人工标注的抓取结果，不由堵转直接生成成功标签。

- GLOBAL_TIME 是设备到 OS system clock 的转换，仍需桥接项目的单调时钟并评估机器人侧延迟；拟输出时间段、配对来源与不确定性，不以拟合残差代替绝对同步精度。
- 相机随法兰刚性运动，拟求 `T_flange_color`，用现场 work/base/tool 快照从真实 UDP TCP 还原法兰位姿；不使用目标或 URDF 显示位姿。采样、离线求解与留出验证均未执行。
