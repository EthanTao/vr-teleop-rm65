# 2026.9.26 工作日志

## 关闭固定六轴 Home 回位的路径预检（默认），回位改走关节空间插值直发

### 背景

现场按 `HOME 0 0 -60 0 60 0` 确认启动回位时触发：

```
[SAFETY STOP] 固定六轴 Home 路径预检失败：关节回位路径穿越 J3/J5 零位
（J5 起点=-112.682° Home=+60.000°）；
请先用示教器或拖动把该轴挪到 Home 一侧，再重试回位
```

机械臂当时停在 J5 负侧（`-112.682°`），固定 Home 在 J5 正侧（`+60°`）。任何连
续的关节回位路径都必须把 J5 扫过 0°，而 DLS 奇异守卫**禁止穿越 J3/J5 零位**，
所以预检直接拒绝。

现场两难：示教器开机麻烦，用户无法自行判断关节回位路径是否安全。用户决定
**先把这个功能关掉**，接受「起点不在 `0 0 -60 0 60 0` 也能回位」，后续需要时再开启。

### 只关掉"预检拒绝"是不够的（这是本次改动的关键判断）

预检（`_plan_fixed_joint_reset`）只是第一道门。真正挡住回位的是**逐周期**的同一
条规则，出现在两个位置：

1. 控制器 `_send_damped_motion` 里的两次 `self.dls.bounded_path_allowed(...)`；
2. `damped_ik.step()` 候选搜索内部的 `bounded_path_allowed(...)`。

两者都含 `if q3 * target3 < 0.0 or q5 * target5 < 0.0: return False`，外加硬区
"必须向外"判据。即使只去掉预检，回位插值到了 J5 零位附近也会被这两道门无限
`hold`，随后 `--reset-settle-timeout-s`（默认 3 s）超时锁存 `RM65 回位未在超时前
到达 Home`。**症状会从"拒绝启动"变成"走到一半停住并报故障"，比原来更难排查。**

因此关闭预检时，回位不再走 DLS 守卫路径，而是**按关节空间插值直接下发
`movej_follow`**（这也是 `movej` 类关节回零的标准做法：关节空间运动不关心笛卡尔
奇异）。关节速度仍有界：回位时长下限由 `2 × max(|Δ关节| / (10% 关节速度上限))`
与线/角速度项共同决定，且用 smoothstep 平滑，单周期峰值步长约等于限速的 0.75 倍。

### 保留与放弃的边界（必须记住）

- **保留**：回位前软停止 + 等实测关节速度低于 `1 °/s`；逐周期 UDP 新鲜度、跟踪误差、
  关节硬限位、关节超速（型号上限 10%）、控制器错误码检查；关节速度/时长下限。

  「这条路能不能过」的判断完全交给现场。因此 `[HOME] 注意：…` 只是提示，不是许可；
  按 B 前仍须确认整条回程净空与急停可达。

## 手柄无法驱动机械臂：真机停机定位与仿真待核实

### 现场证据与调用链

用户提供菜单 3 的 LIVE 日志：默认 `damped_ik_movej_follow`、`dry_run=False`，启动 UDP 奇异比 `0.09722`、严重度 `0.00`，J3/J5 约 -60/+60 度，已在固定 Home。多次成功按 UDP 重建 Grip 锚点，随后在最终发送准入阶段被拒：J1 `0.408/0.362/0.379/0.465 > 0.360` 度、J2 `0.377/0.362 > 0.360` 度。另一次 XR 旋转单帧 `0.334 rad > 0.26 rad`；另有 18 ms 或 16 FK 预算不足保持。汇总周期 p50=20.00 ms、p95=20.05 ms、max=40.07 ms，发送阶段 max=25.16 ms，UDP 反馈最大年龄 48.09 ms。

调用链：右手 Grip/位姿 → 锚点与坐标映射 → TCP 速度/加速度限制器 → 以上一已接受关节命令为 seed 的 DLS → 量化/FK/路径检查 → 更新最新 UDP → 同时检查相邻命令步长和相对实测位置的偏差 → movej_follow。此次主要拒绝发生在最后两项检查中的“实测反馈”比较，超限即硬停锁存。原始手柄数据已进入真机控制链，不能归因为手柄完全断连，也不是日志中奇异硬区阻塞。

J1/J2 的预算来自 180 deg/s × 10% × 0.02 s = 0.360 deg。代码将此同一预算同时用于相邻命令差和命令相对实测位置的差。后者包含跟随与采样/通信滞后，并非实际关节速度。DLS 从上一命令继续推进，最终才以最新实测做拒绝检查，未针对当前实测剩余裕量提前塑形候选目标。

## 分离「命令步长」与「跟随误差」两个预算，并给仿真补上关节速度约束

### 结论先行

真机反复停机不是硬件问题，也不是奇异保护的问题，而是准入判据本身用错了一个数：
`_send_damped_motion` 用**同一个每周期额度**（J1/J2 = 180°/s × 10% × 0.02 s = `0.360°`）
同时判「相邻命令步长」和「命令相对 UDP 实测关节的偏差」。第二项量的是伺服的跟随滞后
（现场 UDP 反馈最老 `48.09 ms`，发送阶段最长 `25.16 ms`），不是关节速度。所以命令每周期
只走 `0.188°` 也会在第 17 周期报 `0.365° > 0.360°`：它测到的是「手臂还没跟上」。

本轮把两个预算分开：**命令步长仍用 1 个周期额度（不改 `0.360°`）**，**实测偏差改用
3 个周期额度（`1.08°`，用户确认）**，并让命令在偏差接近上限时按比例减速、到保持线冻结
命令流、手臂跟上后自动恢复。持续恶化超过 `0.3 s` 才硬停锁存。

### 已证实的根因（源码行为 + 离线复现）

1. **共用预算**（源码事实）。`_joint_step_budget_rad = max_joint_velocity_rad_s ×
   max_joint_speed_ratio × dt`，在最终准入里被两个 `for reference, label in ((seed, "上一命令连续性"),
   (fresh.joint_rad, "实测反馈"))` 循环共用。前者是速度，后者是滞后。
2. **连续性判据抓不到真问题**（源码事实）。DLS 的候选步长已被
   `delta *= min(1.0, min(speeds × dt / |delta|))` 和加速度限幅约束，所以
   `|target − seed| ≤ 1 个周期额度` 是构造性成立的——唯一能做的是「对比实测」那一侧。
   换言之旧实现把**唯一的实测保护**放在了错误的量纲上。
3. **跟随余量本身有自限性，必须显式设保持线**（离线推导 + 实测）。按比例减速是自限的：
   平衡点超前量 `g* = L / (1 − m)`，其中 `m` 是减速系数。若保持线设在真正的余量
   `A` 上，`g` 只会渐近逼近而永远到不了，**持续恶化就永远检测不出来**。因此保持线取
   `A × (k−1)/k`（k = 周期数 = 3，即 `0.72°`），这正是「手臂完全不动」时的平衡超前量。
4. **减速判据要放在 DLS 预算窗口之外**（调试中发现的顺序问题）。`begin_cycle` 会把
   `now + 18 ms` 作为本周期计算预算的截止时间；如果先开预算窗口再算减速判据，一个只读
   标量的比较会消耗掉本周期已经用掉的时间，导致「FK 预算耗尽」保持。现改为先算判据。
5. **仿真确实没有关节速度约束**（源码事实）。仿真入口 `--enable-velocity-limit` 默认
   `False`，`JointConstraints.apply` 在没有速度限制时不保留任何历史，IK 求解结果直接成为
   下一帧关节状态。`_prev_q` 也从不因重新握 Grip 或回位结束而复位。
6. **仿真任务目标没有限速**（源码事实）。旧实现把 `ref_ee + filtered_delta` 直接写进
   IK 任务目标（绝对位姿）。`MotionFilter` 的死区是**逐分量**归零的，所以缓慢的连续手柄
   运动在目标上是台阶；IK 又在追这个台阶。本轮在目标与 IK 之间加了笛卡尔限速器。

### 尚未证实 / 不作为根因

- **仿真的「关节大跳变」具体分支未定位**。本机没有 placo、meshcat（`import placo` 失败），
  不能逐周期采「目标 / 求解结果 / 关节变化」。上面第 5、6 条是源码层面已证实的**不连续来源
  和速度约束缺失**，不是对现场那次大幅变化的唯一根因认定。30 秒关节范围大（各轴
  `356/208/267/356/256/438°`）只能说明「会动」，不能反推跳变机制——这一条维持原判断。
- **48.09 ms 是整段反馈年龄最大值**，不是某一次拒绝时的逐帧年龄；现场每次报错的延迟来源
  仍需逐帧 `--motion-log-path` JSONL 才能定量。
- 仿真映射矩阵、Home、Grip 阈值、Placo IK 参数、共享核心选择均未改动。

| 前后 | ∓Z | J2 1.29° + J3 4.44° + J5 3.15° | 向前 **6.5 cm** / 向后 23 cm | 沿臂自身轴线伸缩，向前很快顶到全伸直 |

- **左右能动是因为它是唯一不碰肘的基座方向**：整条臂绕 J1 摆，不改变「伸出程度」，永远不靠近 J3=0 奇异；上下与前后都要靠 J2/J3 把已经快伸直的臂折叠，几个 cm 内就把 |J3| 推向 0（+X 在 11 cm 处 |J3| 掉到 3.4°、ratio 0.0054）。
- **叠加 2026-09-26 取消的单次 Grip 平移包络**（`--max-offset-m None`，1:1）：手柄一秒可走 20–30 cm，目标立刻落到可达范围外，于是每周期 `hold_singularity`，表现成「手在动、臂不动」。
- 另一条**硬边界**：TCP 的 z 已 0.833 m，±1 m 工作空间盒在 **+Z 只剩 16.7 cm**，而 +Z 正对应手柄「向前」；再多一点就被 `_pose_is_within_bounds` 拒绝 → 硬停锁存。

### 关于「机械臂在自己探索逃出奇异区」

**代码层面不成立：真机这条链没有任何自走项。** 逐条核对：

- `DampedIK.step` 只做「朝操作者目标走一步」；误差≈0 时先返回 `hold_at_target`（`damped_ik.py:413`）原地不动，没有零空间/随机扰动/manipulability 项。
- 与「逃奇异」有关的只有两处，都只做**允许或禁止**、不生成方向：`improving` 把速度下限从 5% 提到 `escape_speed_scale=0.1`（仅当 |J3|/|J5| 已进 5° 硬区且这一步恰好往外）；`bounded_path_allowed` 拒绝任何穿越 J3/J5 零位的步、硬区内只准往外（`damped_ik.py:297-314`）。
- 四个候选因子（1 / 0.5 / 0.25 / 0.125）还必须满足 `‖error − achieved‖ ≤ ‖error‖`（`damped_ik.py:469`）——**不许为了逃奇异把目标误差做大**，因此不存在「为了脱困而偏离手」的动作。
- 每次保持都 `_hold_damped_motion` → `arm.slow_stop()` + 种子重置为实测关节 + 笛卡尔限幅器重设到实测位姿，命令流不累积。

观感上「像在探索」的三个真实来源（可从控制台区分）：

1. **阻尼最小二乘会改方向**：`delta = V(s/(s²+λ²))Uᵀe`。目标方向 σ 很小时，这一步主要落在*还能动*的方向上 —— 手往「外」推、末端往「侧」滑，看起来像它自己挑了个方向。
2. **一步之内停停走走**：候选搜索 + 路径守卫会连续几周期全拒（`hold_singularity`），再某周期放行，步长只有 0.36°/0.45° 量级。
3. **保持时手臂仍在走完已下发的轨迹**：`_hold_damped_motion` 冻结的是命令流，不是控制器里排队的那一小段。
   （若看的是仿真：`placo_teleop_controller._placo_setup` 的 `add_manipulability_task(..., "both", 1.0)` soft 权重 1e-2 是**唯一**会让「手不动、臂自己动去找更好位形」的项，真机代码没有它。）

分辨命令（不改安全门控、不连真机）：`--dry-run --log-motion-debug`，看第二行 `DLS=`：`hold_singularity`＝全拒冻结；`escaping 速度缩放=0.10`＝逃逸速度下限在起作用；`tracking`＝正常跟随；再看 `关节°=`/`步长°=` 判断是否真的在动。

## 奇异区保护改成「方向优先 + 单侧」：能按原方向走就降速走，不能就停，退出优先

### 用户要求（原话）

「奇异区域里机械臂很容易不跟随手柄移动。奇异点附近不要试图让 IK『聪明地猜一个还能走的方向』；应该保护操作者的运动意图——能按原方向走就降速走，不能按原方向走就停，离开奇异的命令优先放行。」

### 结论先行

现场那个「手在动、臂不动」是**三个独立机制**叠出来的，不是一个。本次三个都定位到并改掉，**没有改任何阈值**（`0.04/0.01`、`15°/5°`、`5%`、`10%` 全部原样），也没有改锁存、停止、发送与跟随余量语义。

| # | 机制 | 旧行为 | 新行为 |
| --- | --- | --- | --- |
| 1 | 阻尼最小二乘**改写方向** | `V·diag(σ/(σ²+λ²))·Uᵀe` 对弱条件方向衰减更大，末端实际运动被拧向「还能走的方向」 | 步长改为**最小范数解 `J⁺e`**：只把**不可达分量**投影掉，力度只由速度缩放与每关节预算决定，方向不被旋转 |
| 2 | 配置级硬停**冻结一切** | `ratio ≤ 0.01` 时 `bounded_path_allowed` 否掉**每一个**方向（含退出）；J3/J5 进 5° 硬区后还要求「必须严格向外」，切向运动一起被否 | 改判**方向**：新增 `σ_eff/σ_max = |e|/(|J⁺e|·σ_max)`，低于 `0.01` 才保持；硬区内只禁「更深」，**切向与退出放行**；进入硬区、穿越 J3/J5 零位仍拒绝 |
| 3 | 段首加速度限幅**按关节各自截断** | 快关节先削平，第一步的末端运动可被整体转向 → 候选以「可达误差反而变大」被拒 → 清命令流 → 同一拒绝逐周期重复 | 改为**公共系数**：任一关节 `|Δv| ≤ max_joint_acceleration·dt` 不变（其余关节更小），段首方向不被改写 |

用 `config/rm65_dls_calibration.json` 复原控制器运动学（与 `analyze_real_home_reach.py` 同一模型：`TCP=(0.1854, -0.0026, 0.8326) m`、`|TCP|=0.853 m`、DLS 奇异值 `[3.0167, 1.543, 1.1631, 0.5592, 0.3067, 0.2925]`、`ratio=0.09696` 对现场 `0.09722`），逐周期 1 mm 沿基座轴推进、姿态保持、手臂精确跟随已发命令：

±Z 那条旧行为是**冷启动死锁**，不是奇异区：第 0 周期请求 `e=[0,0,0.003333,0,0,0]`，未截断的期望步长 `[0,-0.002255,+0.007754,0,-0.005499,0] rad`（→ 速度 `[-0.113,+0.388,-0.275] rad/s`），旧实现按关节各自截到 `±0.01 rad/s` 后变成 `[0,-0.0002,+0.0002,0,-0.0002,0]`，末端实际运动 `[0.000325,0,-2.35e-6,0,0.0002,0]`——**与目标方向点积为负**（`e·a = -7.8e-9 < 0`，`|a|² = 1.45e-7`），于是 `‖e−a‖ > ‖e‖`、候选被「可达误差反而变大」拒绝；保持会清命令流与速度参考，下一周期从同一个初值重演，**机械臂在该方向永远不动**。新实现同一请求第 0 周期就被接受（步长 `0.011°`，末端方向偏差 `2.8°` 且逐周期收敛）。

> 这两个数字与现场口述「左右能动、上下前后不动」的**方向次序一致**，但机制与上一节（Home 几乎伸直 + 工作空间盒）不同：那一节是**扫描**上的可达距离，本节是**DLS 准入链**上的逐周期行为，只有后者能解释「一点都不动」。

- **失去**：「配置级全停」这一层保守余量——现在只有**方向不可行**才停。风险是机械臂可能在近奇异位形里以最低速度沿切向爬行；但每周期关节增量、命令连续性、跟随余量与全部锁存判据都在，属于**行为变化**，不是步长或速度上限的放宽。
- **仍未覆盖（不要当成已解决）**：一阶雅可比**分不清**沿同一条退化轴的两个相反方向（谁在深入、谁在退出），所以「退出优先」只在能取到**符号**的地方生效（J3/J5 结构判据）。配置级 ratio 进硬停线、而 J3/J5 都不在 5° 硬区（肩部奇异一类）时，沿退化轴的两个方向都会被保持——此时换个方向即可继续走，其余方向仍放行。彻底解决需要**多花一次雅可比**在预报位形上比奇异度（每周期 +12 次 FK），当前 16 次 FK 预算装不下，本轮未做。

1. **先看启动行**：`实测 UDP 位形奇异比=…`。若为硬停区，握 Grip 后**不应该**再表现为「完全不动」——切向与退出方向应以最低速度（`--singularity-min-speed-scale 0.05`）跟手。

3. **针对现场「前后不动」**：从 Home 出发先向 +Z 慢推，确认现在**会动**（预期约 6–7 cm 后按方向停止，而不是从第 0 周期就不动）；再向 −Z 推，预期能走约 20 cm 直到软限位余量。
4. **切向放行**：把某个轴开到接近奇异（不用主动推进去，只要停在启动时就是硬停区的位形），确认 ±Y 这类不碰肘的方向仍然跟手。
5. 手感仍嫌「滑走」或「爬行」时，先取 `--motion-log-path` 的 JSONL：`singularity_direction_ratio`、`singularity_direction_blocked`、`singularity_speed_scale` 三个字段即可区分「方向不可行」「结构守卫」「速度下限」三种情形，再决定是否调 `--singularity-min-speed-scale`（安全门控，需现场判据）。

## 仓库布局整理：清掉根目录的沙箱残留，生成物统一进 `build/`

### 用户要求（原话）

「整理一下整个仓库，使得整个结构更简洁易懂，而且这个是什么」——附根目录文件树截图，里面挂着 9 个 `tmpXXXXXXXX` 目录。

### 结论先行

那 9 个 `tmpXXXXXXXX` **不是源码，是受限沙箱里跑 pytest 留下的空壳**，成因是一条链：

| # | 环节 | 说明 |
| --- | --- | --- |
| 1 | 沙箱只允许写工作区 | `%TEMP%`、`C:\Windows\Temp`、`c:\temp`、`c:\tmp`、`\temp`、`\tmp` 全部不可写 |
| 2 | `tempfile` 顺位回退 | `tempfile._candidate_tempdir_list()` 的**最后一项是 `os.getcwd()`**；前面全失败时 `gettempdir()` 就返回仓库根目录 |
| 3 | 测试创建临时目录 | `tests/test_data_collector.py` 的 fixture 用 `tempfile.TemporaryDirectory()`（内部即 `mkdtemp()`），每个用例在仓库根建一个 `tmp` + 8 位随机串目录 |
| 4 | 同轮还写了一个缓存 | `tests/test_teleop_launcher.py` 的 `test_sync_code_skips_upload_when_remote_is_current` 没有打桩 `_save_manifest`，所以真的走了 `sync_code()` → `_save_manifest` → `LOCAL_CACHE.parent.mkdir()` + `write_text`，把同步清单写进仓库根（`vr-teleop-rm65.manifest.json`，mtime 14:17:56 落在目录创建窗口 14:17:54–14:18:02 内）。单说 `import teleop` 只计算路径、不写文件 |
| 5 | 留在盘上 | 会话结束后这 9 个目录仍在。现存证据分不清是「进程被中断、`TemporaryDirectory` 来不及清理」还是「沙箱 ACL 阻止删除」——机制上确定的是它们被建在了仓库根。8 个正好对上 `tests/test_data_collector.py` 的 8 个用例，第 9 个（`tmp12o4qn9u`）在生成清理清单前已被诊断性删除，故清单中标记为 `missing` |

复现：`python -c "import tempfile;print(tempfile._candidate_tempdir_list())"`——列表最后一项就是仓库根目录。`.gitignore` 里的 `/tmp*/` 是当时打的补丁，只让它们不入库，没解决它们还在文件树里出现的问题。
