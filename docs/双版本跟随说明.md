# 本地保留的两版跟随实现

2026-11-12 用户明确要求同时保留 MoveIt Servo 版与参照 `HDU-EILab/ur5-teleop` 编写的官方 IK 版。两版独立，不能同时成为运动发送者。当前没有把正式控制图切到官方 IK，未部署板端或执行实体运动。

| 版本 | 入口 | 当前可做的事 |
| --- | --- | --- |
| MoveIt Servo 原版 | `python start.py`，底层 `teleop.py` | 原有 manual/PICO 仿真、真机只读和受现有准入限制的执行；本轮未改其运动配置或停止规则 |
| 官方 IK 连续跟随版 | `python official_follow.py`；ROS `official_follow_shadow.launch.py` | 真实官方 FK/IK、JSONL 回放、独立 MuJoCo 4 浏览器物理仿真及只算不发观察；无真实执行入口 |

Servo 原版基线是 Git `3d8c6cc`；完整本地源码快照及 SHA-256 在忽略目录 `build/archive/control-versions-20261112/`。当前工作区中的 Servo 核心仍保留，本轮仅在构建安装清单中加入新观察程序与测试，不通过覆盖旧源码保存第二版。

## 复用和适配范围

- 直接复用 UR5 固定提交 `8691bfae256d9f48db60eeeca56e243b043d1fea` 的 `frames.py`，以及 `target.py` 中工作空间裁剪、旋转感知步长限制两个函数。MIT 归属与许可在[第三方说明](../THIRD_PARTY_NOTICES.md)和[随包许可](../ros2_ws/src/rm65_servo_teleop/licenses/ur5-teleop-MIT.txt)。没有复制 UR RTDE、URScript、自动 Home 或夹爪流程。
- RM65 适配以现有 InputAdapter 的固定侧装映射、Grip 和实测起点为输入；没有把 UR5 的头显映射叠加到这套坐标转换上，也未改变现有输入异常判据。
- 新计算链：已映射的末端目标 → XYZ 裁剪 → 相对上一候选和实测 TCP 的两级限幅 → 板端官方 Algo IK → 关节连续性/独立反馈领先预算 → 官方 FK 残差检查 → 候选诊断。不是旧 DLS 的恢复，也不是控制柜内部 IK。
- 首段以实测关节/位姿开始。孤立求解失败或关节跳变暂时保持上次候选；最多4次逐次减半笛卡尔步长的尝试，避免直接逐关节裁剪改变目标方向。持续拒绝120 ms后锁存，只有收到释放才重新建立起点；反馈长时间无进展也锁存。保持与“候选接受”均不代表真实发送或实体到位。
- 限速、机械范围、TCP参数沿用 `teleop.yaml`；[official_follow.yaml](../ros2_ws/src/rm65_servo_teleop/config/official_follow.yaml) 仅补计算策略和示例XYZ操作范围，不是现场校准或执行许可。未复制 UR5 的57°跳变阈值、宽松误差阈值、自动续跟、关闭看门狗和位移推断接触保护。
- 新计算版尚未接入 MoveIt 模型碰撞和奇异减速，不宣称它具备 Servo 的全部保护。没有新运行链向硬件发布指令。后续接管运动还需要候选接受与真实提交的关联、同一停止仲裁、模型检查、SDK周期/固件和实体试验。

## SDK 与离线运行

需要 RealMan 官方 **Python API2** 的 `Robotic_Arm` 包及匹配CPU架构的原生库。已有驱动镜像中的 C++ `libapi_cpp.so` 不等于安装了该 Python 包；程序缺包即失败，不连接机械臂、不自动回退假求解器。

本轮在 Windows x64 使用官方 `RealManRobot/RM_API2` 固定提交 `a810b9fdea29e3567c5e9155794e6ef9cc17be62` 的 Python 包和 `api_c.dll` 验证，原文件、下载清单和哈希留在本机忽略目录 `build/reference/RM_API2-a810b9f/`，没有将SDK二进制重新分发进仓库。ARM64板端仍需匹配SDK并实测，不能使用Windows耗时代替。

在本机项目根目录运行（输出路径必须尚不存在）：

```powershell
python -B official_follow.py --demo --sdk-root build/reference/RM_API2-a810b9f/Python --output build/validation/official-follow-local-demo.jsonl
```

演示用真实官方FK/IK，反馈则是明确标记的合成、理想单周期延迟反馈；依次输入±XYZ、±旋转方向小幅目标，最后释放。它验证算法和候选连续性，不是物理仿真、PICO实测或机械臂运动。代码只实例化 `Algo`，没有IP参数、`RoboticArm`、连接、上电、停止或运动调用。SDK Algo 的坐标设置使用进程全局状态，因此每个进程只允许一个算法上下文。

目标姿态用 `xyzw`，SDK边界转换为 `wxyz`；公共关节单位rad，SDK边界转换为度。工作坐标显式设置为单位基座，工具坐标和`d6_m`来自共享配置。SDK默认d6为144 mm，与本项目161.2 mm不同；新适配器显式设置并读回算法库的d6，使算法与仿真候选模型一致，未写入控制器或宣称现场校准通过。ROS观察时仍比较官方FK与反馈TCP，不一致即报告故障，不通过单姿态自动对齐掩盖差异。

## MuJoCo 4.0 浏览器物理仿真

本机已另装workspace内的MuJoCo 4.0.0环境，不修改Servo原有3.12.0镜像和配置。项目根目录运行：

```powershell
python -B official_follow.py --sim --web
```

打开 http://127.0.0.1:8094/ 。页面显示官方IK闭环控制的模拟机械臂，自动依次进行±XYZ和±旋转动作，再释放保持；橙色球是目标TCP，青色球是实际TCP。左键旋转视角、滚轮缩放、右键平移；页面支持暂停、继续和重新开始。这里的反馈来自MuJoCo实际模拟关节和TCP，不再是离线演示中的理想反馈，也不通过直接写qpos播放轨迹。重置只作用于这张独立仿真模型。

物理引擎和官方SDK在本机Python运行，浏览器通过本机HTTP读取模型和实时姿态并渲染。该页面是项目的轻量浏览器查看器，**不是官方Studio WebViewer**：实际安装的Windows 4.0 wheel缺少`headless_ui`和网页客户端资源，官方WebViewer启动失败；因此没有将其启动成功或浏览器内WASM计算作为本轮结果。浏览器3D库three.js 0.180.0下载到忽略目录，保留许可与文件哈希；所有脚本从127.0.0.1本机服务，页面运行时不请求外部CDN。

仿真仅监听127.0.0.1:8094，不创建ROS/SDK机器人连接；结束启动终端中的进程即可关闭服务。首次准备依赖在`build/runtime/official-follow-web4-ready`，官方URDF和7个mesh固定于驱动提交`61db3c3`并保留下载哈希。MuJoCo场景复用现有模型生成器及有限力矩执行器参数；新增本地package路径解析，不改变ROS默认模型解析。模型一致性、动力学与真实PICO仍是独立验收事项。

无窗口检查：`python -B official_follow.py --sim --headless-seconds 26`。本轮26秒六方向闭环：1300个控制采样，1199 tracking、1 anchoring、100 idle、无fault；位置误差P95约0.796 mm。四个姿态的官方FK/MuJoCo TCP差异约4.16–4.61微米、约1.01–1.04e-5 rad。它们验证共享候选模型的一致性和此次独立仿真，不证明实体标定、接触安全或与Servo版同条件性能优劣。官方IK仿真没有经过Servo/JTC，故不能把本次误差直接与此前Servo报告作算法排名。

读取已有JSONL数据时，每行提供完整目标和反馈，不会把上次候选伪造成实测反馈：

```json
{"time_s":0.0,"enabled":false,"target_pose_xyzw":[0.4,0,0.3,0,0,0,1],"feedback_pose_xyzw":[0.4,0,0.3,0,0,0,1],"feedback_joint_rad":[0,0,-1.0472,0,1.0472,0],"target_time_s":0.0,"feedback_time_s":0.0}
```

上述数值仅示意格式，不是已核对的FK匹配样本。`time_s`、两个可选源时间均用同一单调时间基准；源时间省略表示与该行采样时刻一致。使用 `--input <数据.jsonl>` 替代 `--demo`。首行必须包含有效释放，启动按着Grip不会激活。输出每帧的状态、拒绝原因、候选、是否接受、计算耗时及 `execution_authorized:false`；文件尾汇总状态和耗时。当前记录的是完整候选生成耗时，不是单次IK时间。

## 板端只算不发观察

构建安装后，在已有且已核对的只读图旁启动：

```bash
ros2 launch rm65_servo_teleop official_follow_shadow.launch.py sdk_root:=/path/to/RM_API2/Python
ros2 topic echo /rm65/official_follow/shadow
```

它只订阅现有 `/rm65/target_pose`、`/rm65/enable`、受检的 `/rm65/transport/joint_states` 和 TF；只发布字符串诊断，不创建运动、使能、停止发布器或服务客户端。目标、反馈、使能、TF过期都会拒绝计算。`compute_only:=false` 会被程序拒绝，不提供隐藏的live开关。该命令尚未在本轮板端/ROS中执行。

求解时间预算15 ms是在SDK返回后检查，不能抢占卡死的原生调用；当前隔离进程只算不发，不影响已有停止链。后续真实执行必须验证独立超时覆盖，不能把预算检查当作硬实时保证。完整六轴加速度/jerk和实体接触安全仍未验证。
