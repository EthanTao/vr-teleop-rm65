# ROH-LiteS001：先抓取，再人工操控插入

2026-10-28：已实现预设抓取流程、**右手柄 Trigger/A/B 映射**、ROS2 可选 mock 节点、记录及独立只读预检工具；随后补齐独立 RS485 通信驱动和外设采集进程，见[外设驱动与采集](外设驱动与采集.md)。真实写入由未完成的现场配置和显式授权锁住，2026-10-29已部署板端并通过ARM64隔离验证，未实测抓取或插入。用户不需要逐指遥控，只操作“抓枪、保持、释放”。手仍未加入 MuJoCo 接触模型；mock 只演练状态与通信数据结构。

## 操作流程

`启动（抓取状态未知） → 明确准备张手 → 抓取 → 等待反馈到位 → 人工确认握稳 → 保持握持 → 标记开始插入 → 人工操控机械臂 → 标记插入完成 → 明确释放`

- `prepare`、`grasp`、`release` 各发送一次 mock 六通道目标；保持和插入阶段不重复改手目标。
- 指令应答只代表 mock 接受请求；必须有发送后的新位置反馈和六通道停止状态才标记到位。到位后仍须 `confirm_grasp`，不推断已抓住物体。
- 插入阶段拒绝 `release`；先明确 `finish_insert` 再释放。插入完成也是人工标注，不是自动识别结果。
- 启动、重启、故障、缺反馈、退出均不自动张手、校准或复位。故障锁存，恢复反馈不会自动续动；新会话从“未知”开始。
- 本准备版把过流、力控到位、堵转及未知状态均作为异常处理。堵转不生成“抓取成功”；电流不是接触力。
- **阶段只标注任务，不改变机械臂准入。** 手节点不发布机械臂目标、关节指令或 `/rm65/enable`；插入仍由已有 Grip → Servo/JTC 链人工操作。没有自动对孔、推进、阻抗控制或插入成功检测，也没有新增 B/Home。

## 右手柄操作

| 操作 | 结果 |
| --- | --- |
| 启动后先松开全部按钮 | 接受后续新按键；启动不会自动张手 |
| 初次使用，松开 Grip 后长按 B 至少 1 秒 | 明确准备张手，等待状态 `ready` |
| 点按食指 Trigger | 发送一次抓枪预设，等待 `awaiting_grasp_confirmation` |
| 松开 Trigger | 保持原抓取目标，不张手 |
| 点按 A | 人工确认握稳，进入 `holding`；尚未到位则拒绝，不延后重放 |
| 再按住 Grip，移动/转动手柄 | 沿用原机械臂跟随；手保持抓枪，标注 `inserting` |
| 松开 Grip，再重新长按 B 至少 1 秒 | 明确标注本次人工插入操作结束并请求释放；不等于检测到实体插入成功 |

释放后可再次点 Trigger 开始下一轮。手只需张开和抓枪两个预设；预设内部仍包含六个执行通道，操作者不用调整每根手指。A 只记录操作者判断，不声称测得握力或自动验证防滑。

按住 Trigger/A 不连发；短按 B 不释放。**必须先松 Grip，再按 B**；按着 B 才松 Grip 不会释放，需松 B 后重新长按。Grip 在长按期间重新按下、任务阶段改变、无效输入或断流均取消本次长按。恢复后须先松开所有按钮再操作；失联不会自动张手。Trigger/A/B 同时按下也要求先松开再操作。

映射读取现有 `/rm65/xr/raw`，沿用原输入的跟踪有效性及设备时间戳校验；B 长按同时检查主机时间和持续前进的设备时间，重复旧帧不能完成长按。手任务与臂输入共用 Grip 阈值和输入过期时间。此处 Grip 释放是输入条件，不构成物理静止证明，真实写入开放前仍须验收臂停止时序和持物异常策略。

按钮字段依据 [XRoboToolkit 官方 PC-Service 协议](https://github.com/XR-Robotics/XRoboToolkit-PC-Service/blob/main/README-CN.md)：右侧 `primaryButton` 为 A，`secondaryButton` 为 B，`trigger` 为食指扳机。软件测试使用明确标记的合成输入；未验证现场头显实际按键。

## 本机离线演练

仓库根目录执行，完全不连接机器人：

```powershell
python -B scripts/tools/hand_control.py demo --profile ros2_ws/src/rm65_servo_teleop/config/hand_mock.yaml
```

加 `--output build/my_hand_demo.jsonl` 保存记录；文件已存在则拒绝覆盖。配置 `hand_mock.yaml` 的姿态和速度全部是**合成夹具**，不能作为真机抓枪预设。

记录区分 `candidate`、`accepted/rejected`、`sent`、`ack`、`feedback` 与 `stage`；全部 mock 数据带 `synthetic=true`，不生成抓取力、真实抓取成功或真实插入结果。

## 接到现有 ROS2 仿真

默认 `--hand off`；明确启用时仍走原有入口：

```powershell
python teleop.py --mode sim --input manual --target wsl --hand mock
```

这会按源码摘要构建/复用本机镜像。mock 手只输出数据和阶段，MuJoCo 中暂不显示可动手指。`hardware`、`hardware-dry-run` 拒绝 `--hand mock`，不存在 `--hand live`。

已有 PICO 连接条件时，使用 `--input pico` 替换 `--input manual`，即可在仿真会话中使用上面的右手柄按键；这仍只控制 mock 手。2026-10-29手改动已部署板端；真实主会话仍保持hand off，mock手仅限隔离或仿真演练。

在同一 ROS 容器中另开终端，加载其安装环境后逐步操作；**每步先查看状态再执行下一步**：

```bash
ros2 topic echo /rm65/hand/status
# 另一个终端逐条执行：
ros2 run rm65_servo_teleop rm65_hand_command prepare
ros2 run rm65_servo_teleop rm65_hand_command grasp
ros2 run rm65_servo_teleop rm65_hand_command confirm_grasp
ros2 run rm65_servo_teleop rm65_hand_command begin_insert
ros2 run rm65_servo_teleop rm65_hand_command finish_insert
ros2 run rm65_servo_teleop rm65_hand_command release
```

命令工具只接受明确标记的 mock 会话；携带会话 ID、递增序号和期望阶段版本。过期阶段、旧会话、重复请求被拒绝，超时不自动重试。`abort` 只锁存逻辑故障，**不代表实体手已停稳或握持得到保证**。

`/rm65/hand/command`、`events`、`status` 进入既有异步 journal；选择 mock 手时，记录完整性检查要求 hand status/events 均存在。它仍是原始控制记录，不是已验收训练数据。

## 现场只读预检准备

仅适用于已核对为 **RS485 Modbus** 的手；CAN 版不能使用此路径。先核对完整型号、接线、供电、协议主版本和从站地址。示例地址 `2` 不是现场实测值。

在能访问控制器的环境中，先预览（不打开网络）：

```bash
python scripts/tools/hand_control.py probe --arm-ip 192.168.10.18 --device 2 --protocol-major 1
```

待现场确认并允许只读通信后，追加 `--execute-readonly --output build/hand_readonly.json`。本轮未执行该联网步骤。

工具仅允许读取末端 `port=1` 的身份、状态、电流、位置和角度；身份不匹配立即结束。它不会设置 Modbus 模式、工具电源、地址、速度、位置、复位或校准。若尚未配置 Modbus，读取失败并退出，配置应另行现场执行。预检是独立进程，不能塞入机械臂 50 Hz 循环；也不要未经并发验证就与运动会话同时运行。

超时、坏包、错误命令、失败状态、字节长度错误均关闭连接，不重连重试；仅一个在途请求。各组读数保存独立主机收包时间，标记 `atomic_snapshot=false`、`host_receive_only`，不伪称设备同步采样。JSON 应答缺少事务 ID，当前策略不能证明所有固件的通信兼容或并发实时性。

## 数据与实现

通道固定为 `[拇指弯曲, 食指, 中指, 无名指, 小指, 拇指旋转]`，目标/反馈形状 `(6,)`。目标为 `uint16` 逻辑位置，六通道编码为 12 字节高位在前；角度为 `int16`，单位 0.01°。这些不是机械臂六轴，也不是 11 个独立手关节角。

| 文件 | 职责 |
| --- | --- |
| `hand_protocol.py` | 编解码、只读白名单及 RM65 TCP/JSON 预检；只读客户端不提供公开写接口 |
| `hand_driver.py` / `hand_runtime.py` | 独立、受现场配置门控的真实速度/位置写入与读取工作线程；本轮仅模拟器验证 |
| `hand_input.py` | Trigger/A/B 的单次动作、Grip 阶段标注、长按释放及断流重启用条件；没有逐指映射 |
| `hand_session.py` | mock 手、人工确认的任务阶段、反馈年龄与异常检查；时间/存储开销有界 |
| `hand_node.py` / `hand_command.py` | 可选 ROS mock 组件和单次显式命令；20 Hz mock 反馈，不等待网络 |
| `hand_tools.py` / `scripts/tools/hand_control.py` | 无 ROS 的离线演练、默认只预览的现场预检 |

六通道计算为 O(6)，事件缓存最多 128 条，目标槽只有一个，任务状态为 O(1)。真实通信延迟、手执行频率、故障停机与保持握力尚未实测；mock 性能不用于这些结论。

协议依据：[睿尔曼 JSON Modbus](https://develop.realman-robotics.com/robot/json/modbus/)、[傲意 Gen1](https://oymotion.github.io/ROHand/ROH-Protocols/OHandModBusRTUProtocol_Gen1/)、[Gen2](https://oymotion.github.io/ROHand/ROH-Protocols/OHandModBusRTUProtocol_Gen2/)。沿用已调研的 RM65 末端转发方案，未把直连串口 SDK 冒充 RM65 TCP 客户端；未执行厂商循环动作示例。

## 后续实机接入顺序

1. 现场确认型号后缀、供电余量、RS485/协议版本、地址、固件兼容；单独做上述身份与状态读取。
2. 现场验证已实现的独立真实手工作线程，先做空手低速动作及停机语义验收；标定张开、抓枪和拇指旋转预设，记录实际位置/电流/状态。当前合成预设一律不复制到真机。
3. 验证手通信与臂的发送/停止互不阻塞，测故障和断流行为，明确持物异常下的手/臂联动策略，再将已完成的 PICO 预设操作接到真实写入权限。
4. 验证握枪不滑移、抓取后的枪尖 TCP/负载和手/相机/枪的碰撞几何；再进行低速人工插入。机械臂原有跟踪与现场验收门槛继续适用。

本轮验证证据和剩余项见[准备日志](logs/2026.10.28.md#hand-preparation)及[按键映射日志](logs/2026.10.28.md#hand-buttons)。
