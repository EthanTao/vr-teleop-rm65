# 真机安全与故障处理

本页是**真机操作页**：默认真机控制链、DLS 奇异保护、故障解锁流程、上机自检清单。

> 适用入口：`scripts/hardware/teleop_realman_rm65_safe_hardware.py`（推荐真机入口）。
> 依据代码：`xrobotoolkit_teleop/hardware/realman_rm65_safe_teleop_controller.py`、`hardware/damped_ik.py`、`hardware/realman_udp_feedback.py`、`hardware/cartesian_command_limiter.py`。
> **代码为准，本页只做操作说明。**

> ⚠️ **本页描述的保护不等价于碰撞检测或现场安全认证，不能替代实体急停和现场安全管理。**

## 1. 默认真机控制链：`damped_ik_movej_follow`

2026-09-19 起默认真机模式已切换为 DLS 受限关节跟随。数据流：

```
手柄增量 → 侧装映射 + Grip 锚点 → TCP 速度/加速度限制
  → 官方 FK + 显式工作/工具帧变换 → 6×6 数值雅可比
  → SVD 风险检测 → 降速与 DLS 局部关节增量
  → 限位、局部路径、实际反馈、耗时检查
  → movej_follow 关节目标 → UDP 实测反馈
```

关键设计：

- **实际发送的是检查后的六关节目标 `(6,)`**，不是"给原始笛卡尔目标打个风险标签后照常下发"。这样才真正约束控制器内部的逆解分支。
- 首个目标从**实测关节**开始，后续从**上一已接受目标**继续，同时限制目标相对最新实测关节的偏差。**不会调用全局 IK 选择另一套肘部构型。**
- 实际可达的 FK 位姿用于更新限幅器，**避免目标在保护期间持续累积**。

### 1.1 启动门槛（fail-closed）

- 运行容器必须安装与控制器**兼容的睿尔曼 API2 Python SDK**，使用 RM65-B 官方 FK。缺少 SDK 时**直接拒绝启动，不回退到 `movep_follow`**。
- 启动时只读获取**实际 DH 与当前工具参数**用于本地官方 FK。显式 `--dls-flange-to-tcp` 优先；`--dls-work-from-base` 保持显式配置，**不按当前姿态自动拟合**。
- 读取失败、SDK 读回不一致，或 **FK 与同帧 UDP TCP 相差超过 `5 mm / 2°`** → 拒绝启动。
- 现场 RM65-BI 实测 **`d6 = 161.2 mm`**，区别于标准 SDK 默认的 144 mm；`finger` 工具也不是单位变换。该 17.2 mm 差值即当时 FK/UDP 位置偏差的完整解释。

> `5 mm / 2°` 检查能发现明显不一致，**不是标定正确性的充分证明**。

### 1.2 坐标系配置

```text
T_work_tcp = T_work_base × T_base_flange(q) × T_flange_tcp
```

`--dls-work-from-base` 与 `--dls-flange-to-tcp` 各接受七个数 `x y z qw qx qy qz`，**平移单位为米**。省略时为单位变换，即假设官方 FK 的基座/法兰帧就是控制器使用的工作/TCP 帧。装有灵巧手或使用自定义工作坐标系时，应填写现场已有的正确变换；**不要用单个位姿强行对齐来代替标定**。

官方 SDK 接口要求关节输入为**度**，`flag=0` 返回 `[x,y,z,w,x,y,z]`；内部控制与测试统一使用**弧度、米和 `wxyz` 四元数**。

## 2. 风险判据与停止行为

| 判据 | 降速起点 | 危险区 |
|------|---------|--------|
| 归一化雅可比 `σ_min/σ_max` | `0.04` | `0.01` |
| J3、J5 距零位 | `15°` | `5°` |

- 雅可比**平移部分先除以 `0.3 m`**，再计算 `σ_min/σ_max`。**这与旧版未归一化 URDF 雅可比的阈值不能混用。**
- 关节机械限位预留 `5°` 余量；**已在余量区内时允许退回**。
- **阻尼不再参与步长计算**（2026-09-26 起）：步长改走「方向保持的最小范数解」，奇异只决定**快慢**、不改写方向；`--singularity-max-damping` 保留兼容但仅作诊断。
- **加速度限幅是公共系数**（2026-09-26 起）：每周期速度变化的各关节按同一比例缩放，保证任一关节 `|Δv| ≤ max_joint_acceleration × dt`；旧版按关节各自截断会把指令方向拧歪。
- 危险区**阻止继续深入**：`σ_min/σ_max ≤ 0.01` 或 J3/J5 距零位 ≤ `5°` 时，只拒绝**会让情况变坏**的步——半径方向继续深入、J3/J5 继续靠近零位、穿越零位一律拒绝。
- **方向级判据**：「这个手柄方向还能不能走」用该方向的等效增益 `σ_eff/σ_max = |e| / (|J⁺e| · σ_max)` 判断（`σ_eff` 越大越容易走）。低于硬停线 `0.01` 就**保持不动**，而不是让 IK 换个还能走的方向；能走就按 `severity` 降速走（最低 `5%`）。
- **离开奇异优先放行**：结构性向外（受影响轴的 |J3|/|J5| 增大且不回退）的步即使等效增益落在硬停线以内也放行，速度下限取 `escape_speed_scale`（`0.10`）。硬区内的**切向运动**同样放行——这正是旧版会「手在动、臂不动」的地方。
- 上面两条是**遥操作**（手柄增量）的判据。**固定六轴 Home 回位**在预检开启时也用同一套判据做整条路径采样；预检关闭后回位改走关节空间插值直发，不再经过 DLS 奇异守卫（见 §5）。
- ⚠️ **不能承诺"任意手柄反向动作都能退出"** —— 精确奇异姿态存在无法实现的末端方向，且一阶雅可比**分不清**沿同一退化轴的两个相反方向（谁在深入、谁在退出）。因此「退出优先」只在能拿到**符号**的地方生效：J3/J5 结构判据。只有配置级 ratio 进硬停线、而 J3/J5 都不在 5° 硬区时（例如肩部奇异），沿退化轴的两个方向都会被保持——此时**换个方向**即可继续走，其余方向仍然放行。
- 这里检查的是**离散局部关节路径**。`movej_follow` 的实际插值与停止过程由控制器执行；**不提供碰撞检测、自动换肘姿态、全局绕路或实测停止距离保证。**

### 2.1 `[DLS] hold_*` 与故障锁存的区别（重要）

| 现象 | 性质 | 恢复方式 |
|------|------|---------|
| `[DLS] hold_*` | 请求**软停止**，清空已接受关节目标与限幅器速度，等待实测静止后重新计算 | **不需要按 B** |
| `[SAFETY]` 锁存 | 硬停止 `set_arm_stop` + **故障锁存** | 走 §4 Grip 释放流程 |

**单纯 HOLD 不锁存故障。** 但停止未确认、反馈失效、帧不匹配或计算超时**仍会锁存**。正常 B 回位、自检、故障解锁后重新握 Grip，都经过**同一发送门槛**。**松开 Grip 重新使能不会消除奇异姿态，也不会绕过仍然存在的控制器报警。**

## 3. 为什么会"卡死"

程序里有两类停止，表现完全不同：

| 现象 | 触发 | 恢复 |
|------|------|------|
| 松手就停，扣上还能动 | 正常松开 Grip → 软停止 `set_arm_slow_stop` | **不用解锁**，重新扣 Grip 即可（用最新实测位姿重新建锚点） |
| 怎么扣都不动，终端打 `[SAFETY]` | 安全故障 → 硬停止 + **故障锁存** | 走 §4 Grip 释放流程 |

触发硬停止并锁存的情况：UDP 反馈超时（默认 `0.20 s`）、关节超速/越界、控制器错误码、TCP 跟踪误差超限、XR 追踪超时或单帧跳变、目标越出 XYZ 边界、通信失败，以及**跟随余量持续恶化**（`跟随误差持续恶化`）或**命令流停滞后手臂仍未跟上**（2026-09-26 新增，取代原先「实测偏差超过一个周期额度即锁存」）。

> **注意不要混淆两组「误差」**：
> - `RM65 跟踪误差超限` 比的是**末端位姿**（TCP，`0.12 m / 0.80 rad`），是「机械臂有没有在跟」的粗判据。
> - `跟随误差持续恶化` / `跟随保持线` 比的是**关节超前量**（命令比 UDP 实测关节领先多少），是「命令有没有跑到手臂前面去」的细判据，且先在余量内降速、再有界保持，最后才锁存。

> **控制台语言**（2026-09-24 起）：运行期输出、安全报警原因、DLS 原因与启动信息均为中文；`[SAFETY STOP]`、`[DLS]`、`[RESET]`、`[HOME]`、`[TIMING]`、`[指令]` 等方括号标签、JSONL 字段名（`dls_status` 等）与参数名保持英文，便于与本文和日志字段对照。启动前的参数校验报错仍为英文（一次性、带参数名）。

**`RM65 跟踪误差超限：位置=…m，姿态=…rad` 在比什么**：拿「上一次下发的命令位姿」和「UDP 实测 TCP 位姿」比，超过 `--max-tracking-error-m`（`0.12 m`）或 `--max-tracking-error-rad`（`0.80 rad`）就锁存。它防的是「我们在发目标、机械臂没跟上」——控制器没进跟随模式、机械臂被卡住、急停/抱闸等。

区分两种情形：

- **刚重新握 Grip 就立刻报**：这说明在上一段结束（故障、松手）之后机械臂被挪动过——手持示教器、拖动，或按过 B。此时本段还没下发过任何目标，属于**误触发**；2026-09-24 已修：新一段的第一周期只用实测姿态重建锚点与命令参考，不做跟踪比对（`test_first_grip_re_anchors_instead_of_faulting_on_a_stale_reference` 锁住该行为）。修好后这种情形应能正常握持起步。
- **运动过程中报**：这是真实故障，机械臂没有跟随命令。停止操作、保持急停可达，检查控制器是否仍在 `movej_follow` 跟随状态、是否有报警/抱闸/被外力阻挡，再走 §4 重新使能流程。

> 修的是「新段起始的陈旧参考」，不是放宽门限：`0.12 m / 0.80 rad` 与运动过程中的每一周期检查都原样保留。

> **锁存 ≠ 只停一下。** 锁存后程序不再下发任何运动目标，锁一直保持到人工解锁为止。

## 4. 故障后重新使能：松开 Grip

故障锁存后程序停止发送运动目标。**B 键不再用于解锁**；锁存期间按 B 也不会开始复位。

1. 如果故障时正扣着 Grip，完全松开（反馈值 ≤ `grip_off_threshold`，默认 `0.15`）。如果故障发生时 Grip 原本已松开，先扣住再松开一次，防止锁存自行清除。
2. 保持 Grip 松开，等待 UDP 反馈线程正常、最新帧不超过 `0.20 s`、反馈无错误码、关节角在限位内、六轴速度均 ≤ `1°/s`。条件不满足时程序保持锁存，不发送运动目标。
3. 看到 `[SAFETY] 已解除锁存；请再次握 Grip 开始运动` 后，再扣 Grip。首个握持周期只用最新 UDP 实测姿态重建锚点（并同步命令参考），不立即发送运动目标。

重新使能只清软件锁存，不会消除控制器报警、恢复断开的 UDP/XR 或绕过原有 DLS、限速与跟踪检查。若根因未消除，重新握持后会再次触发保护；先检查 `fault_reason` 和控制器状态。B 键仅在无故障且完成重新使能后作为固定 Home 复位按钮。

## 5. ⚠️ 别乱按 B

**B 键只用于复位；故障锁存期间按 B 不会移动机械臂。**

- 推荐真机入口的固定 Home 为六轴角度 `[0, 0, -60, 0, 60, 0]`（度）。若启动时实测关节角与它相差超过 `1°`，控制器打印偏差量（含容差）与目标角度，并留 `3 s` 缓冲（`--home-start-delay-s`，期间 `Ctrl+C` 或拍急停可中止）后**自动**低速回位；**2026-09-27 起不再要求输入确认口令**，需要恢复旧的精确口令门（必须输入 `HOME 0 0 -60 0 60 0` 才回位）加 `--home-start-confirmation`。`--dry-run` 不执行这段回位。
- 按下 B 会尝试回到同一组六轴角度。控制器按关节插值生成目标 TCP，经原有笛卡尔限速、DLS 奇异保护、UDP 反馈与故障锁存链发送；只有 TCP 和六轴反馈都到位才报告完成。`--reset-duration-s` 默认 `3.0 s` 是最短时间，远距离回位会自动延长。
- 回位前先软停止，确认实测关节速度低于 `1 °/s` 后才开始；随后按关节插值采样路径。**2026-09-26 起真机入口默认关闭路径预检**（`--enable-home-path-preflight` 可重新开启）：
  - 预检关闭：关节插值**直发 `movej_follow`**，起点在 J3/J5 零位另一侧也能回位。J3/J5 零位穿越、奇异硬区、TCP 工作空间越界只作为 `[HOME] 注意：…` 提示打印，不再拒绝。逐周期的 UDP 新鲜度、跟踪误差、关节限位/超速、控制器错误码检查仍然生效；关节速度由回位时长的下限保证。
  - 预检开启：任一次采样点进入奇异硬区或越出 TCP 工作空间即拒绝；起点与 Home 在 J3/J5 零位异侧时直接拒绝，须先用示教器或拖动把该轴挪到 Home 一侧。
- 关闭预检**不等于路径安全**：程序不再判断这条路能不能过（也不会避障）。**数值奇异度合格同样不等于无碰撞**，每次按 B 前仍须现场确认整条回程路径的净空和急停。

> **结论：只在需要回固定 Home、且已确认回程净空时按 B；故障恢复使用 Grip 松开流程。**

### 6.2 运动幅度（2026-09-24 平移 1:1 当前默认）

| 参数 | 默认 | 含义 |
|------|------|------|
| `--scale-factor` | **1.0** | 手柄平移 → 目标平移比例（手柄 1 mm → 目标 1 mm，不再被固定 15 cm 包络截断） |
| `--rotation-scale-factor` | **0.25** | 手柄旋转 → 目标旋转比例（手柄 25° → 约 6.3°） |
| `--max-offset-m` | **不设限（`None`）** | 单次 Grip 平移包络（按三轴合成位移）。真机入口默认不夹；控制器库默认仍为 `0.15`，传数值即恢复截断 |
| `--max-rot-offset-rad` | **0.20** | 单次 Grip 旋转包络（约 11.5°），**未改** |
| TCP 线速度 / 线加速度上限 | `0.05 m/s` / `0.40 m/s²` | 每周期先过限幅器 |
| TCP 角速度 / 角加速度上限 | `0.25 rad/s` / `1.20 rad/s²` | 同上 |
| 关节超速阈值 | 型号最大速度的 **10%** | 超限即硬停止并锁存 |
| DLS 关节速度预算（交给 `dls.step`） | 型号最大速度 × `--max-joint-speed-ratio`（`0.10`） | J1/J2 `18°/s`、J3–J6 `22.5°/s`，**速度缩放 = 1**，不再按 `dwell/dt` 额外打折（2026-09-26 修正） |
| 工作空间 XYZ 边界 | 每轴 `[-1.0, 1.0] m` | **上机前应按现场收紧** |

> 2026-09-26 起真机入口的平移包络默认取消（用户要求，用于排查「幅度很小、速度很慢」）：手柄位移 1:1 直接进目标。**取消包络不等于没有边界**，一段 Grip 内仍受这些限制：TCP 工作空间盒（默认每轴 `[-1.0, 1.0] m`，上机前应按现场收紧）、XR 单帧跳变门槛（`--max-xr-step-m 0.05` / `--max-xr-rot-step-rad 0.26`）、关节硬限位与关节超速锁存、跟随余量调速器，以及 TCP 跟踪误差锁存（`--max-tracking-error-m 0.12`）。**失去的那一层是「累计漂移上限」**：长时间握着 Grip 时，手柄的缓慢漂移现在会 1:1 走成机械臂位移，跳变门槛只能拦住单帧突跳。要恢复夹断就显式传 `--max-offset-m 0.15`；首次上机验收仍建议 `--max-offset-m 0.03`。
> 注意 `--self-test-distance-m` 默认 `0.02`，启动校验为 `0.02..0.03`；包络不设限时跳过「≤ `max_offset_m`」这条子检查，把包络降到 `0.02` 以下仍会直接抛错。

### 6.3 奇异保护

| 参数 | 默认 | 作用 |
|------|------|------|
| `--singularity-slowdown-joint-deg` / `--singularity-stop-joint-deg` | `15` / `5` | J3、J5 降速起点 / 危险区起点（度） |

### 7.1 跑完怎么判定：一条命令出「过 / 不过」（2026-09-29 新增）

上面第 ② 步已经在往 `--motion-log-path` 写 JSONL。**录到之后不要靠回忆描述现象** ——
这几周的验收全部靠口述，所以每轮都说不清、每轮都要重开一轮讨论。
三条离线工具把日志直接变成结论（都可加 `--json`）：

```bash
# ① 完整验收判定：逐段跟随比 + 两类差距 + 两层映射判定 + 判据的过与不过
python scripts/debug/report_teleop_acceptance.py /workspace/logs/dls-dry-run.jsonl

# ② 只看方向定案：哪根手柄轴对应末端哪根轴、符号对不对
python scripts/debug/estimate_teleop_mapping.py /workspace/logs/dls-dry-run.jsonl

# ③ 只看「手动了多少 / 臂实际动了多少」
python scripts/debug/analyze_motion_log.py /workspace/logs/dls-dry-run.jsonl
```

`report_teleop_acceptance.py` 的退出码：**`0` = 判据全过；`2` = 未通过**，可直接用于脚本判断。

**默认判据**（工程约定、不是物理常量，可用 `--min-run-seconds` / `--min-follow-ratio` 覆盖）：

| 判据 | 默认阈值 | 含义 |
|------|---------|------|
| 跟随比中位数 | `>= 0.80` | 实测净位移 / 预期净位移；低于此值「手在动、臂不动」成立 |
| 最差段跟随比 | `>= 0.30` | 任何一段都不许基本没动 |
| 故障锁存次数 | `<= 0` | 一次锁存就要人工介入，不算可交付 |
| 整场时长 / 有效段数 | `>= 60 s` / `>= 3` | 避免几秒钟的偶然；有效段 = 连续有目标且 ≥ 50 周期 |
| 映射方向一致 | 必须 | 落点轴与符号须与代码期望一致 |
| 记录带实测末端位姿 | 必须 | 旧版本采集的日志没有 `measured_tcp_xyz_m`，算不了跟随比 |

> **方向定案不需要额外试动作**：真实运行时只要手柄在各方向都动过，
> `estimate_teleop_mapping.py` 就能从日志拟合出映射矩阵并给出落点轴与符号。
> 这正是 `docs/RM65参数与坐标系.md` §14 真机观测栏至今缺失的那类仪器读数 ——
> 而按数据集方案，「方向没定案前采的数据全部作废」。

**Dry-run 的预期现象**：真机保持不动时，连续远移手柄会先打印 `[DLS] hold_tracking_lag 原因=J<n> 命令超前实测 …° ≥ 跟随保持线 …°（跟随余量 …°）`（命令流冻结、机械臂停一下，**不锁存**），持续超过 `--tracking-lag-hold-dwell-s`（默认 `0.3 s`）才升级为 `[SAFETY STOP] DLS 拒绝本次运动：跟随误差持续恶化（超过 0.30s）：…` —— 这是**预期门槛，不表示映射失败**。

**这条门槛在比什么（两个预算，两个不同的数）**：DLS 每个周期算出的关节目标要过两道检查，它们用**不同的额度**：

| 检查 | 比哪两个量 | 额度 | 物理含义 |
|------|-----------|------|----------|
| 命令连续性（报文标 `对比上一命令连续性`） | 本周期目标 − **上一已接受命令** | `max_joint_velocity_rad_s × --max-joint-speed-ratio(0.10) × dt(20 ms)`，即 **J1/J2 0.360°、J3–J6 0.450°**（1 个控制周期） | 真·关节速度：命令流不许跳变 |
| 跟随余量（报文标 `对比实测反馈` 或 `跟随保持线`） | 本周期目标 − **UDP 实测关节** | 上述额度的 `--max-tracking-lag-cycles` 倍（默认 3），即 **J1/J2 1.080°、J3–J6 1.350°** | 伺服/通信滞后：命令允许跑在实测前面多少 |

**为什么第二个必须更宽**：UDP 报回的关节角是几十毫秒前的。现场实测反馈最老 `48.09 ms`、发送阶段最长 `25.16 ms`；手臂按 `18°/s` 走，`48 ms` 就自然落后 `0.86°`。如果这一项也用一个周期（`0.360°`）去量，那么「手臂还没跟上」会被读成「有人在下发跳变命令」——2026-09-26 现场反复出现的 `0.408/0.377/0.365° > 0.360°` 停机就是这么来的，当时相邻命令步长只有 `0.188°`。

**喂给 DLS 的关节速度上限（2026-09-26 修正，速度缩放 = 1）**：现在直接是 `model_spec.max_joint_velocity_rad_s × --max-joint-speed-ratio`，即 J1/J2 `18°/s`、J3–J6 `22.5°/s`。同一天早些时候的版本把它再除以 `dwell/dt = 0.3/0.02 = 15`，实际只给 `1.2°/s`，离线下单周期步长被压在 `0.024°`（`~1.2°/s`），是「能动但很慢」的根因；该夹子已移除，跟随超前量改由上面的调速器单独负责。离线差分（假臂 + 真 DLS）：同一请求下最大单周期步长从 `0.024°` 升到 `0.36°`，稳态从 `1.19°/s` 升到 `17.3°/s`。
> ⚠️ 副作用：命令速度上限现在与**关节超速锁存线**是同一个数（都是型号上限的 10%）。若真机在贴限速跟随时上报速度略超该值，会出现 `Jx 关节超速` 锁存。现场遇到时先记录该帧的 UDP 速度、命令步长与 `跟随缩放`，再决定是否给锁存留 5% 余量——**不要在未取到证据前放宽**。

**跟随余量内部的三段行为**（软线与保持线都是上面那套数值，按关节各自算）：

```
      命令位置
        │
  ── 跟随余量 A ─────────────  超过：理论硬上限（正常跟随时到不了这里）
        │
  ── 保持线 = A×(k-1)/k ──   达到：冻结命令流（软停 + 清命令参考位姿），
        │                        手臂跟上后自动恢复，不需要松 Grip
  ── 软线 = 1 个周期额度 ──   超过：按剩余余量成比例降速（只减速，不停车）
        │
  ── 实测位置 ──              以内：正常跟随
```

- **只降速不停车**是「保持线以下」的设计目标：正常跟随时最多损失速度，不会顿挫。
- **保持线设在 `A×(k-1)/k` 而不是 `A`**：按比例减速是自限的，超前量只会渐近逼近 `A` 而永远到不了，若把保持线设在 `A` 上，持续恶化就永远检测不出来。`(k-1)/k` 正是「手臂完全不动」时的平衡超前量，所以它是能触发的最小值。
- **持续恶化锁存**：保持状态连续超过 `--tracking-lag-hold-dwell-s` 才硬停锁存（报文 `跟随误差持续恶化`）。
- **命令流停滞锁存**：减速区把步长压到 `0.001°` 下发分辨率以下、而手臂完全没跟上的极端情况，由连续 6 个周期无进展判定（报文 `命令流停滞后手臂仍未跟上`）。纯粹的奇异/软限位保持不计数，不会误伤。

后果：dry run 下真机一动不动，实测关节冻结，命令却跟着手柄往前走，于是**探索范围只有约 `A×(k-1)/k`**——TCP 上仍是几毫米到一厘米量级。这不是故障，是「静止的真机无法支撑无界重放」这条设计约束。

处置：保持是**自动恢复**的，等机械臂把余量走回来即可继续；需要看更远的映射就落盘 `--motion-log-path` 分析，或分多次小幅移动。控制台预览第二行的 `超前°` 就是当前命令与实测的最大关节差，`跟随缩放` 是当前降速比例；`超前°` 逼近保持线（J1/J2 `0.720°`、J3–J6 `0.900°`）就会出现保持。

**日志字段语义**：

| 字段 | 含义 |
|------|------|
| `command_xyz` | 进入 DLS 的**末端目标**（**不是实际执行反馈**） |
| `joint_candidate_rad` | 检查后的候选关节 |
| `dls_achieved_xyz` | 候选关节的可达末端位置 |
| `joint_target_accepted` | **本地接受**，不代表机器人已执行到位 |
| `dls_status` / `dls_fk_calls` / `dls_candidate_attempts` / `dls_elapsed_ms` | 预算、候选和耗时核对 |
| `singularity_zone` / `sigma_min` / `sigma_ratio` / `severity` / `speed_scale` / `step_scale` / `inward` / `hold` | 奇异保护诊断 |
| `singularity_direction_ratio` | **该手柄方向的等效增益** `σ_eff/σ_max`；越大越容易走，≤ `stop_ratio` 即该方向不可行 |
| `singularity_direction_blocked` | 本周期是否因「方向不可行」而保持（与结构守卫无关） |
| `singularity_damping` | **仅诊断**：按配置级严重度算出的阻尼值；2026-09-26 起步长不再使用方向阻尼 |

**`--motion-log-path` 的 dry-run 观测字段**：`xr_delta_m`（轴映射后、未缩放/死区的手柄相对位移）、`target_delta_m`（缩放、死区及可选 XY 反向后的目标位移；仅当显式设置了 `--max-offset-m` 才含包络截断）、`target_xyz_m`（限速前目标）、`command_xyz_m`（限速后候选命令）、`udp_xyz_m`（实际反馈），单位均为米。`target_rotvec_deg` 是**相对旋转向量（轴×角度）非欧拉角**；绝对目标/命令姿态采用 wxyz 四元数。**候选命令预览发生在发送/官方 IK 检查前，不代表已接受或已执行。**

**`--log-motion-debug` 的控制台预览**（菜单 2 已默认开启）：握住 Grip 后最多每 `0.2 s` 检查一次，**只在内容变化时打印两行**；静止不动、位形不变时不会重复刷屏。行首 `DRY-RUN` / `LIVE` 标记当前模式。它补齐了「手柄动了之后到底算出什么」，不必再只看机械臂自身状态：

```
[指令 DRY-RUN] 握持=0.90 手柄位移mm=[0.0, 19.0, 0.0] 目标位移mm=[0.0, 1.7, 0.0] 目标旋转°=[0.0, 0.0, 0.0] 实测误差mm=1.7
  DLS=hold_singularity 奇异比=0.00255 方向比=0.00000 关节°=[-0.02, -16.87, 36.47, -12.43, -35.37, -0.06] -> 保持(该手柄方向不可行)
```

| 字段 | 含义 |
|------|------|
| `握持` | 当前 Grip 值；`旋转增益` 只在被平移降权（`--suppress-rotation-during-translation`）时才出现 |
| `手柄位移mm` | 手柄相对位移，已做轴映射、**未**缩放/死区。手柄静止而这里持续跳，说明是跟踪抖动而不是映射问题 |
| `目标位移mm` | 缩放、死区（以及显式设置时的包络）之后的目标位移。`手柄位移mm` 有值而这里是 0，就是被死区吃掉了；包络默认不设限，所以这两者现在通常接近 1:1 |
| `目标旋转°` | 目标相对旋转向量（度），不是欧拉角 |
| `实测误差mm` | 目标与 UDP 实测 TCP 的距离 |
| `DLS=` | 该周期 DLS 结论：`tracking` / `escaping` / `hold_at_target` / `hold_joint_margin` / `hold_singularity` / `hold_budget` / `hold_tracking_lag`（这些是代码里的状态标识符，保持不变），后接 `奇异比`、必要时附 `方向比`、`速度缩放` 与 `跟随缩放` |
| `关节°` | **算出来的关节目标**（度）；被接受时是最终下发值，被保持时是 DLS 拒绝的候选 |
| `步长°` | 相对上一已接受命令的单周期最大关节增量，只有被接受时打印 |
| `超前°` | 当前关节目标与 **UDP 实测关节**的最大差；逼近保持线（J1/J2 `0.720°`、J3–J6 `0.900°`）时进入保持，逼近跟随余量（`1.080°` / `1.350°`）时已经是硬上限 |
| `方向比` | **只在被降速/被保持时出现**：该手柄方向的等效增益 `σ_eff/σ_max`。它回答「我这个方向还能不能走」；降速线 `0.04`、硬停线 `0.01` |
| `跟随缩放` | 跟随余量降速比例；`< 1.00` 表示命令正在为滞后让出速度 |
| `->` | 本周期结论：`已接受` / `已接受(未下发)`（dry run）/ `保持(…)`（有意保持，不触发故障）/ `被拒绝`（进入重新使能）。`保持` 的原因：`该手柄方向不可行`、`无可用步`、`已到达目标`、`接近限位`、`计算预算不足`、`跟随余量用尽` |

详细原因（候选被哪一道门槛否掉）仍由两秒一次的 `[DLS] … 原因=…` 行给出；每周期的完整数值走 `--motion-log-path` 的 JSONL。

> 预览打印排在发送**之后**，因此不影响该周期的下发时序。`已接受` 只表示本地接受；dry run 下不会真正下发，屏幕上也不代表机器人已经到位。

**启动时的实测位形判据**：启动会打印 `[INFO] 实测 UDP 位形奇异比=… 严重度=… 区域=…`。固定六轴 Home 只是目标，机械臂实际停放位形可能完全不同：若这里是 `区域=硬停区`，说明**当前位形本身就在 DLS 硬停区**。2026-09-26 起这**不再意味着「握 Grip 也不动」**：只有「按手柄方向走不了」的命令会被保持，切向与退出方向仍会以最低速度放行（退出优先）。若手感仍嫌不动，可用手持示教器或拖动把机械臂挪出该位形，再重新握 Grip。`B` 键回 Home 在**预检关闭（默认）**时不受此限制：起点即使与 Home 分处 J3/J5 零位两侧，也会按关节插值直发走完；在**预检开启**时则会被拒绝，须先把该轴挪到 Home 一侧。

> ⚠️ 控制周期仍为 `20 ms`，DLS 默认在 `18 ms` 前 fail-closed。单帧超预算不发送新目标并保持上一已接受目标，连续 3 帧才 slow stop。旧 74-FK 路径实测完整周期 **38.2 ms**；降至正常 14 / 硬上限 16 次 FK 后，目标容器 1000 周期完整 `_send_motion` Dry Run 为 median **10.169 ms**、P95 **11.782 ms**、max **14.397 ms**，在该条件下满足 18/20 ms 时序预算。该 benchmark 禁止实际下发，不能外推为真实运动验收。

## 9. 已知边界（不要把"主机测试通过"当作真机验收）
