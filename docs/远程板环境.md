## 下次到实验室：先连接并检查输入

1. 给板子、机械臂和网络上电。Windows连接板端，启动或复用只读会话：

   ```powershell
   ssh rm '/home/rm/EthanTao/environment.sh start-readonly'
   ssh rm '/home/rm/EthanTao/environment.sh status'
   ```

   脚本只启动PICO真机只读链；遇到其他会话、地址变化或端口占用会拒绝，不会自动替换。当前已在运行时直接复用。

2. 头显与板端WiFi接入同一局域网，打开已有XRoboToolkit App，填写板端地址 **192.168.0.115:63901**，启用 **Controller + Send**。该WiFi地址是本次实查值；重启或换网络后用 `ssh rm 'ip -br -4 address show wlan0'` 重查。

3. 先松开右Grip，在Windows查看5秒输入：

   ```powershell
   ssh rm '/home/rm/EthanTao/environment.sh input'
   ```

   应看到有效帧、递增的设备时间戳、`synthetic_frames=0`，Grip随实际手柄变化。没有头显连接时0帧正常。该工具只订阅，不发送命令；只读模式下机械臂不会执行目标。

4. 现场核对侧装坐标、TCP/附件/场景、固件与速度单位，完成低速跟随、松Grip、断流及急停验证。将实际证据保存到正式现场验证文件。旧安装角查询 `[0,-90,0]°` 只校正过查看窗口，生产模型仍需现场标定。

## 现场通过后：切换同一链路的执行模式

Windows `启动真机.cmd` 现已默认使用 **EthanTao**。保留原准入要求：显式提供板端UDP地址、真实现场验证文件及人工确认。验证文件须位于 `ros2_ws/src/rm65_servo_teleop/config/`；示例文件保持false，不能凭环境启动成功改为true。

先运行以下预览，替换为真实验收文件名：

```powershell
.\启动真机.cmd -UdpIp 192.168.10.100 -HardwareValidation ros2_ws/src/rm65_servo_teleop/config/hardware_validation.lab.yaml -LiveAck "RM65 LIVE VALIDATION" -CheckOnly
```

预览通过、现场人员确认后，先结束当前只读会话，再去掉 `-CheckOnly` 启动执行。不要并跑两个同名会话或UDP接收者：

```powershell
ssh rm 'sudo -n docker stop --time 20 rm65-servo'
.\启动真机.cmd -UdpIp 192.168.10.100 -HardwareValidation ros2_ws/src/rm65_servo_teleop/config/hardware_validation.lab.yaml -LiveAck "RM65 LIVE VALIDATION"
```

以上执行命令是现场步骤，本轮远程没有运行。源码/配置或SDK选项变化时启动器会重新构建；匹配时复用准备镜像。首次连接先松Grip，反馈与TF新鲜后再按住右Grip；松开停止跟随，每次重按重新建立当前实测TCP锚点。当前没有B/Home或启动自动回位。
