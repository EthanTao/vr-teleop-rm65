## 2. 按主题的核心决策

### 2.1 输入参考系与坐标系语义（2026-09-09）

**结论：SDK 坐标系是"启动锚定世界系"** —— 原点 = 启动应用时的头戴位置；头显、手柄、手势、全身动捕共享同一世界坐标系；位姿为七浮点 `x,y,z,qx,qy,qz,qw`；pybind 与 ROS 透传层**不做坐标变换**（文档语义 == 代码收到的语义）。

推论：

- "转头 → 手柄坐标变 → 机械臂误动"在文档语义下**不成立**。
- 真实残余问题是**操作者身体平移/前倾**（固定世界系下的固有行为）。
- 若要抗走动/抗前倾，正确做法是**手柄 − 头显每帧相对化**：

  ```
  T_rel(t) = T_head(t)⁻¹ · T_ctrl(t)
  ```

  锚点与 delta 建立在 `T_rel` 上，平移增量与姿态增量必须同步改。**当前未采用**。
- 轴向极性（手性、Z 正方向）**以实测为准** —— 官方中英文 README 自身矛盾。

### 2.2 侧装映射矩阵（2026-09-09 冻结）

- 仿真入口与真机控制器**均引用** `R_HEADSET_TO_WORLD_RM65_SIDE_MOUNT_HARDWARE = [[0,1,0],[1,0,0],[0,0,-1]]`。
- `R_HEADSET_TO_WORLD_RM65_SIDE_MOUNT = [[0,-1,0],[-1,0,0],[0,0,-1]]` 是 2026-07-13 的仿真验证矩阵，**当前无任何运行代码引用**；真机在 `invert_tcp_xy=True` 时有效映射与之等价。
- 两矩阵**仅水平 X/Y 两轴符号相反**（水平面差 180°）。数值验证：`HARDWARE 矩阵 + delta X/Y 取反 ≡ SIDE_MOUNT 矩阵`，随机 100 样本最大误差 `0.0`。
- **原则（第 12 条）**：仿真 = 手感标定场，仿真映射是"直觉参考系"（上抬→升高、前推→伸远、右推→向右，按真实侧装语境验收），**不能用真机适配矩阵反向定义仿真手感**。
- 机器人按 URDF **竖立显示**，映射保持代码原状（手柄映射矩阵不因显示而改）。
- 2026-09-09 用户确认当前 `_HARDWARE` 关系无问题 → **冻结**。
- ⚠️ 2026-09-18 仿真口述观测（左右→X、上下→Y）与代码推导（上下→X、左右→Y）在 X/Y 上**正好互换，尚未判定**；真机观测栏为空。**实测定案前不要盲改矩阵。**

### 2.3 真机安全控制（2026-09-09 第一版）

**解决的问题**：原链路四个缺口 —— `move_v=30` 偏激进；只限目标位置不限速度/加速度；TCP 同步查询与下发互相阻塞致周期抖动堆积；限速器、跳变检查、UDP latest-only 反馈未接入推荐入口（旧单文件入口可绕开）。

**核心思想**：默认低速、命令有界、反馈独立、异常立即锁存、**不能自动恢复**。

- **UDP 作独立反馈通道**：机械臂主动把关节角/关节速度/TCP 位姿/错误码推到运行程序主机的 `8089` 端口；程序只读**最新一帧，不排队补执行**；丢包用 `0.20 s` 新鲜度看门狗兜底。**缺 `joint_status.joint_speed` 时启动失败，不降级为"无超速检测继续运动"。**
- **两类停止语义**：正常松 Grip → `set_arm_slow_stop`（软停止）+ 清空锚点与限速器，再按 Grip 须用**最新 UDP 实测 TCP 位姿重建锚点**；异常 → `set_arm_stop`（硬停止）+ **故障锁存**，须松 Grip + 反馈新鲜 + 关节 `≤1°/s` + 按 B 解锁，**不能靠松/按 Grip 自动清**。
- 旧入口 `teleop_realman_rm65_hardware.py` 在 `dry_run=False` 时直接报错拒绝启动。
- 启动顺序：只读预检 → `--dry-run` → 首次小范围（`--max-offset-m 0.03`）。
- 关节超速阈值：各关节型号最大速度的 `10%` —— J1/J2 `18°/s`，J3~J6 `22.5°/s`。
- 修改范围**仅真机路径**，仿真、侧装矩阵、共用几何公式未改。

### 2.4 官方连续 IK 链路（2026-09-10）

**新增可选真机链路**（须显式选择，默认不变）：

```
XR 目标位姿 → 笛卡尔速度/加速度与工作空间限制
  → rm_algo_ik_remote(T_target, q_udp) → RM65-B 关节范围检查
  → 单周期关节步长检查 → movej_follow
```

- `q_udp` = 当前周期 UDP 关节反馈作 seed，**降低跳到另一 IK 分支的风险**。
- SDK 缺失、IK 返回失败、非法数值、越关节范围、单周期步长过大 → 硬停止 + 故障锁存。
- 仿真侧接入同一链路：`--ik-backend placo|official`（默认 `placo`）。official 下 Placo **不参与 FK/IK**，只作状态容器与可视化。
- `--official-ik-frames-verified` / `--official-ik-j3-soft-limit-verified` 仅表示操作者已现场核对 work/tool frame 与 J3 非零软限位；**程序不代替核对、不写现场软限位**。
- 官方仿真：J3 须在 `±5°` 排除区外，运行中进排除区或单周期跳变过大 → 保持上一帧并打印 `[OFFICIAL IK HOLD]`。

**责任边界（2026-09-09）**：真机链路只发笛卡尔目标，**不发关节角或 `joint_refer`**；`move_r` 只影响笛卡尔段交融，**不负责选 IK 构型**。

### 2.5 关节运动连续性（2026-09-15）

**核心原则：每一步参考上一步已接受的关节目标，同时检查机械臂实际走到哪里。**

- 上一步目标保连续，"目标 vs 实测"差距确认未偏离太远。
- **"已接受" = 通过检查并成功提交，不代表机械臂已到位。**
- 发送失败**不推进**目标；松开 Grip、复位或故障恢复后**重新从实际关节位置开始**。
- 仿真同步该原则，并修复"复位发送失败后仍可能被判为完成"。
- 仅适用于电脑算关节角的 `official_ik_movej_follow` 模式。

### 2.6 奇异区域保护的演进（三个版本，务必理解差异）

#### v1（2026-09-18）—— 已被取代

- 新增 `hardware/singularity_avoidance.py`（URDF 关节链 FK、几何雅可比、奇异度评估、方向门控、DLS 阻尼关节步）+ `cartesian_command_limiter.set_speed_scale()` + 8 个 CLI 参数。
- 运动学模型用**仓库内官方 URDF 关节链**（`d1=240.5`、`a2=256`、`d4=210`、`d6=112.03 mm`），因为官方 MDH 表**按字面无法建链**。校验：与 URDF 逐项一致，解析雅可比与有限差分最大误差 `2.35e-8`。
- 定标发现：**只看 J3/J5 的判据会漏掉肩部奇异** —— `J2=-25°, J3=55°, J5=60°` 时 ratio 仅 `0.00109`（J4/5/6 轴线交点距 J1 轴仅 3.2 mm），而 J3/J5 都是健康中间值。故 `severity = max(雅可比比值斜坡, |J3| 斜坡, |J5| 斜坡)`。
- 无阻尼伪逆 vs DLS 对比（10 mm 最难方向位移）：肩部奇异 `208.6°` vs `0.12°`；边界/肩部 `429.8°` vs `0.07°`。

> ⚠️ **v1 有四个致命问题**（2026-09-19 核查确认），其"退出永远放行""冻结目标即停止"等表述**不作为当前安全保证**。

#### v2 = 当前默认（2026-09-19）—— `damped_ik_movej_follow`

核查确认 v1 存在五个问题：① DLS 只预测关节变化，**实际仍发送原始笛卡尔目标**，无法约束控制器内部逆解分支；② 固定幅度探针能从 J5 正小角穿过零位到负侧再被误判为退出；③ HOLD 仅冻结目标而**未取消在途轨迹**，同时缩小减速度会延长停止过程；④ 结构 URDF 的法兰/基座雅可比直接处理控制器工作/TCP 帧目标，**缺少一致的帧语义**；⑤ B 正常回位和自检**没有共用**完整的奇异保护发送门槛。

修复要点：

- 新增 `hardware/damped_ik.py`；**实际下发检查后的六关节目标 `(6,)`**，而非只用 DLS 预测。
- 新运动段从实测关节开始，后续延续上一已接受目标，保留相对最新实测反馈的单周期偏差预算；失败/HOLD/松 Grip/重新建锚点清除旧目标，**避免跨段沿用**。
- 小幅局部方向检测**替代跨零探针**；四个有序路径采样点检查风险，**不允许 J3/J5 穿零**。
- 机械限位预留 `5°`，已在余量内允许退回，**但退出仍须符合全部约束 —— 不能保证任意方向均可退出**。
- HOLD 请求**有确认的软停止**，清空目标/速度参考并等待 UDP 实测静止；停止未确认则锁存故障。
- 降低速度上限**不再同步降低**笛卡尔制动加速度。
- 正常 B 回位、自检、解锁后 Grip 跟随**共用发送门槛**；新段若机械臂仍在停止中先等静止。
- `singularity_avoidance.py` **保留离线结构分析用途，不再负责批准真机运动**。
- 新增 `--dls-work-from-base` / `--dls-flange-to-tcp`（默认单位变换）；启动与发送前核对 FK/UDP，**超过 `5 mm / 2°` 拒绝**；**没有用单个位姿自动对齐掩盖模型/坐标系问题**。

本机合成 FK + 40 次完整发送门槛计算耗时：中位 `5.54 ms`、P95 `7.86 ms`、最大 `8.75 ms` —— 但这**不是官方 SDK / 远程板基准**，运行时仍保留 `20 ms` 超时拒绝门槛。

**仿真手感优化**：管线变为

```
XR 数据 → MotionFilter → Placo IK → JointConstraints → Meshcat
```

- `MotionFilter`：逐分量死区（`abs(v) < deadband` 归零）+ EMA（`y_t = α·x_t + (1-α)·y_{t-1}`），平移与旋转用不同 α。**Grip 按下时 `reset()` 清 EMA 历史**，松开冻结。
- `JointConstraints`：关节限位 + 可选速度限制（`|Δq| ≤ max_joint_velocity · dt`，默认关）。

### 2.10 DLS 周期超时性能归因（2026-09-22，十余轮实测）

**问题**：Dry Run 每次按 Grip 都硬停止锁存，`[SAFETY STOP] DLS computation exceeded control period`；`period_max=280.35ms`。

**归因链（全部实测，逐条排除）**：

| 量 | 值 |
|---|---|
| 每周期 FK 位姿数 | 正常跟踪 **74**，空输入 **13**，最坏（多因子重试）**222** |
| 裸官方 FK | `0.147 ms` |
| 适配器组合调用 | `1.2 ms` → 重写后 `0.385 ms` |
| `DampedIK.step`（容器） | `89–110 ms` → 重写后 **`35.6 ms`** |
| 整周期（容器） | — → **`38.2 ms`**（预算 20 ms，**1.9 倍**） |
| 一次周期 numpy 原语运算数 | `2695` → 重写后 **`559`** |

**74 次的确切构成**（`hardware/damped_ik.py`）：

| 阶段 | FK 次数 | 占比 |
|---|---|---|
| 路径过滤 `path_allowed` 4 个采样点 × 12 | **48** | 64.9% |
| 逃逸方向探测 `metrics(q + delta*0.01)` | **12** | 16.2% |
| 种子雅可比中心差分 6×2 | 12 | 16.2% |
| 种子位姿 | 1 | 1.4% |
| 候选步终点 | 1 | 1.4% |

**结论一：逃逸相关 12+48 = 60 = 81%，DLS 本体只有 13 次（18%）。** 每周期建 **6 次完整雅可比 + 6 次 SVD**，而 DLS 本体只需要 1 次 —— **5/6 的雅可比与 SVD 是为奇异保护付的**，其中 48 次是为"沿路径逐点重算整个雅可比"付的。最坏情况因子循环逐个重试 `1+12+12+192 = 217` 次 ≈ `267 ms`，与 `period_max=280.35ms` 几乎重合。

**结论二：瓶颈是"每次调用里的 Python/numpy 工作量"，不是 SDK、不是线程、不是次数。** 决定性证据：**容器上纯 Python 合成链（1.125 ms）比官方 SDK（0.147 ms）还慢 7.7 倍**；同一段纯 Python 本机 `0.119 ms` vs 容器 `1.027 ms`（约 9 倍）；单次 numpy 级运算在该容器约 `40 µs`（本机约 `1–2 µs`）。

**结论三：同一段代码，代价按"量化后步长是否为零"分档，差 3 倍**（无输入时步长被 `0.001°` 量化还原后全部 `continue`，`path_allowed` 0 次）。

**结论四：数学上限** —— 即便每次压到裸 SDK 成本 `0.147 ms`，`20 ms / 0.147 ms ≈ 136` 次是绝对上限，而最坏需要 222 次 → **必须降次数，不能只降单价**。

**已完成的"运算层重写"**（未触碰控制流程、判定条件、阈值、锁存或发送策略）：

- 四元数运算（`_quaternion_multiply` / `_quaternion_conjugate` / `shortest_world_rotation_vector`）**全改纯 Python 标量**，去掉 `np.dot`/`np.cross`/`np.concatenate`/`np.linalg.norm`/`np.arctan2`。
- 位姿缓存改以"已校验的 6 元组"为键（去掉 `tobytes()`）；`jacobian` 把中心差分 12 个点位姿一次构造为 `(12,6)` 模板。
- 兑现：四元数等价性 **16018 例最大相对差 0.0**；新 `jacobian` 与旧实现**最大绝对差 0.0**；运算数 **2695 → 559（−79%）**；本机 `step` **11.13 → 6.67 ms**；适配器单次开销 **0.0655 → 0.0175 ms**。
- **施工中抓到的真实缺陷**：`stencil[0::2, range(6)] += step` 是高级索引网格化，会把 6 个扰动加到同一行（Jacobian 全行相同），必须写 `stencil[2*rows, rows]` 成对索引。

**关键关系：两个乘数缺一不可。**

| 方案 | 估算 |
|---|---|
| 只做运算层（74 × 7.5 × 41 µs） | ≈ 23 ms，仍略超 |
| 只降次数（14 × 36 × 41 µs） | ≈ 21 ms，同样卡在门口 |
| **两项都做**（14 × 7.5 × 41 µs） | ≈ **4.3 ms**，才真正进预算 |

**2026-09-23 实施与验证更新**：用户明确授权以实时性和有界退化优先，实际落地了比原 S2/S4 更保守的方案：不引入零空间自运动，不在危险区退回昂贵搜索；实时路径仅做一次数值 Jacobian，使用常数时间 J3/J5 局部门控，SVD ratio 单独进入硬区且无法廉价证明改善时直接保持。默认 `18 ms / 16 FK / 3 candidates`，单帧预算失败保持、连续 3 帧 slow stop。离线计数为无输入 13、正常 14、结构硬上限 16；`407 passed`。目标容器随后完成 1000 周期 Dry Run：14 FK/周期且全部 `tracking`，独立 `DampedIK.step` median `7.368 ms` / P95 `8.894 ms` / max `14.829 ms`，完整 `_send_motion` 准入链 median `10.169 ms` / P95 `11.782 ms` / max `14.397 ms`，未出现 `hold_budget` 或 Safety Stop。该证据确认计算与准入时序，不确认真实发送、XR 主循环、机械臂跟踪或物理安全。

## 5. 进行中的计划

### 5.1 降低每周期 FK 调用（2026-09-22 历史提案，2026-09-23 已落地保守变体）

**状态**：产品代码已落地 bounded-search 保守变体；正常 14 / 硬上限 16 次 FK，并通过目标容器 1000 周期 Dry Run 计算/准入时序验证。真实 `movej_follow`、XR 主循环、机械臂跟踪和物理安全待验收。下述零空间、一阶奇异值预测和分阶段表是历史提案，**并未原样实现**。

**三个核心思想 → 同一个乘数的三处**（把"用完整雅可比判"换成"用一阶预测判 + 关键点精确核"）：

| 思想 | 对应的浪费 | 目标 | 降次数 |
|---|---|---|---|
| ① **Singularity Avoidance**（提前知道危险） | 用 6 次完整雅可比去**发现**危险，而不是用廉价信号提前预警 | 危险信号改为角域/结构量预测 + 雅可比低频刷新 | −60 |
| ② **Velocity Scaling**（防止突然炸） | 逃逸探测为回答"要不要提速"付 12 次 FK；`scale` 每周期独立取值可来回跳 | 一个平滑、单调、有变化率限制的标量替代探测 | （含在上行） |
| ③ **Null-space Optimization**（根治 74 次搜索） | 4 因子 × 4 采样点的搜索，是在用数值方式"找"一个本来就存在的方向 | SVD 域直接选步（最小范数 + 可证单调的零空间修正），一次通过 | 因子重试 222 → 单次 |

**关键设计**：

- **①** 四个采样点在同一条极短线段上（Δ 量级 `1e-3 rad`），故 `J(q+αΔ) ≈ J(q) + α·(J(q+Δ) − J(q))` 成立。端点精确 + 中间点用奇异值一阶扰动预测；**只要 `severity > 0` 或预测 ratio 低于降速阈，该分支退回原精确判据** —— 清晰区省 48 次，**危险区一分不省**。J3/J5 零位符号判定本来零成本，完全不变。
- **②** `improving` 改为一阶量、零 FK；`scale` 变成显式一阶平滑 + 单调：**降速立即生效，升速有变化率上限**。所有阈值一个不改，改的只是"何时允许回到高速"。
- **③** `Δq = V·diag(s/(s²+λ²))·Uᵀ·e + N·k`，`k` 只依赖已算出的 SVD，在零空间找"最能把 `σ_min` 抬起来且不增加末端误差"的一小步。因零空间分量数学上不改变末端误差，候选步天然满足"末端误差不增"，**因子重试不再必要**。

**统一后每周期结构**：① 廉价预警（0 次 FK）→ ② DLS 本体（13 次，唯一必需）→ ③ 步长平滑（0 次）→ ④ 候选选择（0~1 次）→ ⑤ 端点核验（0~1 次）→ ⑥ 危险兜底（仅危险区付费）。**典型约 13~15 次 FK**（现在 74），**最坏情况与典型同阶**（不再有 222 次）。

**分阶段**：

| 阶段 | 内容 | FK | 风险 |
|---|---|---|---|
| S1 | 逃逸探测复用已算出的 `u, s, vt` 做一阶估计 | 74 → 62 | 低 |
| S2 | 路径过滤：端点精确 + 中间点一阶预测，危险区退回精确 | 62 → 14~26 | 中（**改保护判据，需明确批准**） |
| S3 | `scale` 变化率限制 | 不变 | 低 |
| S4 | 零空间修正 + 取消因子重试 | 最坏 222 → ≤20 | 中（**改搜索形式，需单独评审**） |
| S5 | 环境侧排查"单次 numpy 运算 40 µs"的根因 | — | — |

**每阶段硬性纪律**：① 先写对拍脚本、**看它失败**，再接线；② 对拍用例按真实调用序列构造（**第九轮的教训**）；③ 任何"未通过逐位对拍"的数值路径**一律回退**，不留在产品路径里；④ 阈值、锁存、20 ms 超时、发送策略**全部不变**；⑤ 改完追加工作日志。

**必须由用户先确认的三件事**：

1. S2 改 `path_allowed` 的**判据形式**（保护判据改动，提案默认不做）。
2. S4 引入零空间修正 —— 需明确"允许机械臂在危险区做**自运动**以脱离奇异"是期望行为。
3. 危险区是否允许"**更慢但完整**"（即放宽 20 ms 判据为"仅清晰区要求 20 ms"）—— 这决定 S2 是否需要"危险区退回精确"这条兜底。

**明确不做**：不用 URDF / 结构链的雅可比批准任何真机运动；不改 `slowdown_ratio=0.04`、`stop_ratio=0.01`、`15°/5°`、`min_speed_scale=0.05`、`escape_speed_scale=0.1`、`max_damping=0.08`；不改 20 ms 超时拒绝语义、故障锁存与解锁流程、关节/速度/TCP 边界、锚点与 seed 策略、发送策略；**不触碰批量帧合成**。
