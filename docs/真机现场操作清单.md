若仅 `tailscaled` 为 inactive，执行 `sudo systemctl start tailscaled` 后重查。若提示未登录或网络不通，按提示处理账户/网络；不要重置原配置。Tailscale 不通时，Windows 与板端接入同一局域网后，也可直接 SSH 到板端 WiFi IP。

python -B scripts/tools/inspect_moveit_environment.py --ssh-host $BoardHost --container rm65-servo --sudo-docker --output "$FieldDir/inventory.json"

历史准备镜像：控制 `5cf5d95b4b8d`，独立外设 `b7ca980329cd`；这些是 10 月 29 日证据，不是当前身份自动认证。若报依赖缺失、SDK=OFF 或版本不一致，保存输出后修复镜像，先不执行。

隔离依赖检查只创建无网络、无设备映射的一次性容器，不启动 ROS 控制图。若存在真实执行中的会话，先依现场停机规程结束该会话，再继续，避免额外负载。

## 3. 启动或复用唯一只读链，查真实反馈

```powershell
ssh $BoardHost '/home/rm/EthanTao/environment.sh start-readonly'
ssh $BoardHost '/home/rm/EthanTao/environment.sh status'
python -B scripts/tools/check_robot_readiness.py --host $BoardHost --output "$FieldDir/runtime-before-pico.json"
```

工具不覆盖/停止现有会话、不同步源码、不重建镜像、不使能运动。已存在匹配只读会话时直接复用；发现正在执行或无法识别的会话时跳过运行探测。它还核对运行容器镜像 ID、准备镜像及当前本机源码摘要，检查控制器、节点和 `base_link→tcp` 变换；报告始终 `motion_authorized=false`。仅源码标签不符时先查文件差异，不能据此直接覆盖板端环境。

通过标准：

- `mode=hardware-dry-run`、`hardware_writes=false`；
- `fresh_feedback=true`，包号递增，`0 ≤ source_age_ms < 200`，控制器错误为空、六轴错误全 0；
- `joint_state_broadcaster` 与 `rm65_arm_controller` 均 active；必要节点齐全，TCP 变换年龄在 `[0,0.2)` 秒；
- 只读模式下按手柄，实体臂不执行手柄目标。

无会话或端口占用时按报错检查。不要再开旧程序、另一个 UDP 接收器或单独 PICO sidecar。`start-readonly` 拒绝已有异常会话时，先核实容器身份与模式，不能批量停止容器来消除报错。

## 4. PICO 填 IP，验证真实输入和 Grip

头显与板端 WiFi 接同一局域网；XRoboToolkit App 中填**第 1 步实查的板端 WiFi IP**，端口 **63901**，打开 Controller + Send。上次 `192.168.0.115` 仅供参考。不要填 Windows IP、控制器 `192.168.10.18` 或反馈网口地址。

```powershell
ssh $BoardHost '/home/rm/EthanTao/environment.sh input'
```

在 5 秒观察窗口内先松右 Grip，再按下、松开；可多运行两次分别观察。通过标准：有效帧持续到达、设备时间戳递增、`invalid_frames=0`、`synthetic_frames=0`；松开值不高于 `0.15`、按下超过 `0.20`，输入状态与动作一致。0 帧就检查 App Send、IP/端口、同网和追踪状态。

```powershell
python -B scripts/tools/check_robot_readiness.py --host $BoardHost --require-input --output "$FieldDir/runtime-with-pico.json"
```

全部 PASS 后仍只代表只读软件链与真实输入已观察到，不代表安装标定、持续时序或停止已经合格。

## 5. 先在只读状态检查手柄映射和断流

打开两个额外 PowerShell 窗口，复用同一实际 SSH 地址（变量不自动跨窗口继承）。每个窗口先 `ssh rm` 或 SSH 实际局域网地址，进入**板端终端**，再执行：

```bash
sudo -n docker exec -it rm65-servo bash
source /opt/rm65_ws/install/setup.bash
```

窗口 A 执行 `ros2 topic echo /rm65/input_status`；窗口 B 执行 `ros2 topic echo /rm65/target_pose`。`Ctrl+C` 只结束观察命令。

1. 右 Grip 松开：输入应 disabled。按住不移动：应以当前实测 TCP 建立新锚点，目标不跳去 Home 或旧锚点。
2. 按住 Grip，手柄沿单一方向缓慢移动约 1cm；每个方向松开再重按，分别记录目标 XYZ 的增量符号。不要每帧跳动超过配置 5cm。
3. 当前代码映射为 XR `+X→base +Y`、`+Y→base +X`、`+Z→base −Z`，位置比例 1；这只是代码预期。将 XR 实测轴向与实体侧装 base 轴向一并核对后才能判断实际操作方向是否正确。
4. 小角度转动，观察目标四元数连续变化；当前旋转比例 0.25。转动头部不应引起大幅目标变化。
5. 松 Grip：disabled；再次按住：锚点更新至当时实测 TCP。
6. 保持 Grip，关闭 App 的 Send：输入应因超时 disabled。恢复 Send 并保持 Grip，不应直接重新跟随；先松开再重按才能恢复。

此时实体不动是预期结果。若目标跳变、方向不符或恢复后自动续跟随，保留报告和日志，先修输入/坐标问题，不进入运动。

## 6. 核对时序与记录

在板端本地终端或 SSH 中：

```bash
sudo -n docker exec rm65-servo ps -eLo pid,tid,cls,rtprio,comm
sudo -n docker exec rm65-servo bash -c 'ulimit -r; ulimit -l'
sudo -n docker stats --no-stream rm65-servo
df -h /home/rm/EthanTao
```

Windows 保存日志：

```powershell
ssh $BoardHost 'sudo -n docker logs --timestamps --since 10m rm65-servo' 2>&1 | Out-File -Encoding utf8 "$FieldDir/runtime.log"
```

保持真实 PICO 只读输入至少 60 秒再查日志；记录周期超时条数/最大值、反馈超时、记录写入失败和 CPU/内存。观察到 FIFO 权限失败时记录线程调度类、rtprio 与容器权限，结合板端实际配置修复后复测；不能直接放宽 20ms 周期或 200ms 新鲜度线。

历史 20ms 周期曾耗时约 49.1ms，FIFO 权限告警尚未解决；一次短窗口没报错不能当作长期时序验收。现场若仍有重复超时或反馈失效，先停在只读阶段。手/相机并发负载还需单独复测。

## 7. 用多个静止姿态核对 base、TCP、官方 FK 和单位

由熟悉该臂的现场人员使用**厂商已批准的示教流程**低速选择至少 3 个分散且远离奇异/碰撞的姿态，避免伸直和腕部轴线重合。姿态切换时先松 Grip、退出本项目只读会话，再使用示教器；实体静止、示教器结束运动后重新启动只读链采样。

```powershell
# 仅对已经确认是本项目 hardware-dry-run 的容器执行
ssh $BoardHost 'sudo -n docker stop --time 20 rm65-servo'
# 完成厂商示教操作并静止后
ssh $BoardHost '/home/rm/EthanTao/environment.sh start-readonly'
ssh $BoardHost '/home/rm/EthanTao/environment.sh status'
```

每个姿态记录：示教器六轴角度及单位、真实 UDP 六轴、官方 FK/UDP TCP、当前工具/工作坐标系、模型 `base_link→tcp`、TCP 实体定义及照片。查看模型 TCP 可在第 5 步容器终端运行：

```bash
ros2 run tf2_ros tf2_echo base_link tcp
```

统一到**同一 base、同一工具 TCP、米/弧度和相同姿态约定**后再比较。当前 `d6=0.1612m`、工具平移/旋转、`mount_rpy=[0,0,0]` 均为待核实候选；不能因为画面看着正确就确认。

用示教器已知的小幅低速运动记录角位移/时间与 UDP qdot，核对 SDK/固件速度单位；保留控制器型号、固件和 SDK 版本兼容证据。单帧静止 qdot=0 不能证明速度单位正确。历史 5mm/2°仅为明显帧错误筛查线，不是插接精度合格线；实际验收容差需随现场任务记录。

## 8. 补碰撞模型与独立停止证据，再建立现场文件

执行前确认机械臂、手、相机支架、工具、桌面/工件和现场障碍的碰撞几何与实际安装一致。当前模型尚不完整；清空工作区并不能把缺失附件几何视为已验证。需要改模型/配置时先修改并重新构建、核验全部关联文件和现场姿态。

**首次验收的顺序限制：正式执行要求 `stop_verified=true`，当前没有跳过此项的受限试动模式。** 需要由实验室负责人依据厂商规程完成或提供与当前控制器/SDK匹配的停止接口测试证据，包括返回值、真实反馈与实体停止。没有这些证据时停在本步，不能填写 true 来启动第一次试动。之后第 10 步还要单独验证本项目 Grip/断流联动，厂商停止测试不替代它。

所有前置实测项完成后，从模板创建现场文件；这条复制命令不会批准运动：

若文件已经存在，先保存历史证据再更新，不能盲目覆盖。填写 `operator`、`validated_at`、`evidence`，逐项填写实测结论；未完成项保持 false。证据注明各项对应报告/照片/视频/日志路径。

在现有只读容器中打印对应模型与部署哈希，不启动第二套节点：

把核验后的 `model_sha256` 和 `deployment_sha256` 原样填入现场文件，并核对驱动提交。若本机与板端配置已不同，不能用旧镜像哈希签署新配置；先完成一致性与重建核验。任何模型/配置/驱动补丁/IP变动都要重新核验。

## 10. 受监护的低速小范围实体验证

使用第 7 步已确认的姿态和净空。当前配置名义 TCP 速度界为 0.05m/s、0.25rad/s，单轴速度界为型号上限的 10%；这些不是实测速度或硬加速度保证，现场先确认能接受这些界限。首次按住 Grip 时保持手柄静止；每次只做一个方向约 5–10mm 的缓慢平移，旋转另起一段做约 1–2° 的小动作，逐项录像和留日志。

| 顺序 | 操作 | 必须观察到的结果 |
| --- | --- | --- |
| 1 | 上电/启动并松 Grip | 不自动回位、不追旧目标 |
| 2 | 按 Grip，手柄静止 | 新鲜实测 TCP 锚定，无明显跳动 |
| 3 | 逐方向小幅平移，再单独旋转 | 方向、比例与只读核对一致，无异常关节快动 |
| 4 | 运动中松 Grip，重复 3 次 | 停止请求、SDK结果与实体静止分别确认，记录时间与余移 |
| 5 | 再按 Grip | 从当前实测位置重新锚定，无补执行旧目标 |
| 6 | 最小动作中关闭 App Send | 超时停止且锁存；恢复输入不自动续动；松开再按恢复 |
| 7 | 按实验室急停规程验证实体急停与复位 | 人工确认实体静止；复位/重启不自动续动 |

观察 `/rm65/transport/status` 的 `stop_request`、`native_stop_ack`、`stop_result`、后续反馈与原生发送结果；`stop_result success` 不能单独当作实体停稳。软件静止阈值为每轴 ≤1°/s，只是准入判定，还要观察实体和测余移。不得把 200ms 输入期限或 0.5s 停止确认超时直接当作合格的物理停机性能。

实体方向反、突跳、松手不停、停机未确认、输入恢复自动续动或异常声音时，由监护人员按现场规程急停，结束该次验收。不要通过远程强杀进程来替代急停。UDP拔线、桥崩溃等故障注入需要另有针对性的现场方案，本轮不把剪断控制反馈作为随手测试步骤。
