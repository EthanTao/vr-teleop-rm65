## 让 Dry Run 显示「手柄动了之后算出来的参数」

### 背景与原因

现场用菜单 2（真机 Dry Run）复核映射时，控制台只有机械臂自身状态（`anchor reset from UDP`、`[DLS] hold_singularity ratio=0.00254 scale=0.000`），看不到手柄位移对应的计算结果，无法判断是映射、死区、限速还是奇异保护在起作用。根因有两条：

1. `--log-motion-debug` 虽已存在，但菜单 2 的容器命令没有带这个开关，一键启动根本开不出预览；能打印的也只有笛卡尔量，没有 DLS 算出的关节目标。
2. `hold_singularity` 只报状态和比值，不解释是「奇异值比进了硬停区」还是「J3/J5 贴零位」，现场只能猜。

- `xrobotoolkit_teleop/hardware/damped_ik.py`：`DampedStep` 新增仅用于诊断的 `detail` 字段；`step()` 在保持/拒绝时填具体原因（`hold_at_target` 已到位、`hold_joint_margin` 关节软限位余量、`hold_singularity` 区分奇异值比硬停区与 J3/J5 硬区，并列出候选被否掉的门槛）。正常跟踪路径不构造该字符串，实时开销不变。
- `xrobotoolkit_teleop/hardware/realman_rm65_safe_teleop_controller.py`：
  - `_process_xr_pose` 在开启调试时另存轴映射后、未缩放/死区的手柄相对位移；缩放前后表达式拆成局部变量，数值不变。

## 修复：重新握 Grip 时被上一段的陈旧命令参考误判为跟踪误差

### 背景与现象

现场日志：

```
[SAFETY] re-arm acknowledged; press Grip again to move
[SAFETY STOP] RM65 tracking error exceeded limit: position=0.254m, rotation=1.160rad
```

跟踪检查比的是「上一次下发命令位姿」与「UDP 实测 TCP 位姿」，限值 `0.12 m / 0.80 rad`。代码里 `_run_teleop_cycle` 在**新一段的锚点重建之前**就调用 `_checked_feedback(..., check_tracking=True)`，而 `_last_commanded_pose6` 只由 `sync_command_reference` 更新、`clear_fault()` 不会清它。于是：上一段结束后机械臂被挪动过（故障后用手持示教器/拖动挪出奇异位形，或按过 B），再次握 Grip 时先拿**旧段落的命令参考**去比**新实测姿态**，必然超限——但此刻本段一个运动目标都还没下发，门限没有在保护任何东西。DLS 自身的关节步长检查（相对实测关节 ≤ `max_joint_velocity_rad_s × 0.10 × dt`）把命令流限制在实测附近约 3 cm 内，所以 0.254 m 只可能来自机械臂被外部移动，不可能是命令流累积。

### 修改文件与内容

- `xrobotoolkit_teleop/hardware/realman_rm65_safe_teleop_controller.py`：`_run_teleop_cycle` 里进入 `_reset_anchor` 之前的那次反馈检查改为 `check_tracking=was_active`——新一段的第一周期不做跟踪比对，因为该段尚未下发任何目标；紧接着的 `_reset_anchor` 会把命令参考同步到实测姿态。`_start_reset` 同样补上 `sync_command_reference`，让 B 复位段也从实测起步（否则 B 复位后的第一个 tick 也会拿旧参考比对新姿态）。运动过程中的每周期检查、`0.12 m / 0.80 rad` 门限、DLS 关节步长检查全部原样保留。
- `tests/test_realman_safe_controller.py`：新增 3 条——`test_first_grip_re_anchors_instead_of_faulting_on_a_stale_reference`（无修复时该用例失败，已实测确认）、`test_active_segment_still_latches_a_tracking_error`（运动中的门限必须仍然生效）、`test_reset_start_replaces_the_previous_command_reference`。
- `docs/真机安全与故障处理.md` §3：补充该报文在比什么、以及「刚重新握 Grip 就报」与「运动过程中报」的处置区别。

### 验证状态

- 本机 `python -m pytest tests -q`：422 passed（新增 3 条）。其中新用例在临时还原旧行为后确实失败（`assert 1 == 0`），证明它复现了现场现象。
- Black（`--target-version py310`）与 `git diff --check`：通过。

### 风险边界

## 让「命令连续性」门槛说清是哪条关节、差多少，并预告剩余余量

### 背景与现象

现场 dry run 报 `[SAFETY STOP] DLS rejected motion: DLS joint command continuity / measured feedback step exceeded limit`。该守卫是既有且刻意的设计（`test_feedback_budget_prevents_command_runaway` 同时覆盖 dry-run 与真机）：DLS 目标必须同时落在「上一已接受命令」和「UDP 实测关节」的一个控制步长内，步长预算 = `max_joint_velocity_rad_s × 0.10 × 0.02 s`，即 J1/J2 `0.360°`、J3–J6 `0.450°`。dry run 下真机不动、实测冻结，命令跟着手柄前进，因此探索窗口天然只有一个步长；但原报文既不说哪条关节、也不说差多少，更没提 dry-run 这一必然性。

### 修改文件与内容

- `xrobotoolkit_teleop/hardware/realman_rm65_safe_teleop_controller.py`：DLS 连续性检查改为按关节拆分并复用官方 IK 的措辞与标签——`DLS J<n> step exceeded limit (command continuity|measured feedback): <实际>deg > <预算>deg`；仅在 dry-run 且违反的是实测那一侧时追加 `(dry run never moves the real arm; release and re-grip to re-baseline)`。判定逻辑、遍历顺序与锁存行为均未改变（`test_feedback_budget_prevents_command_runaway` 的 `"step exceeded"` 断言原样通过）。
- 调试快照新增 `measured_rad`，控制台预览第二行新增 `gap_deg`（当前关节目标与 UDP 实测关节的最大差），直接预告距锁存还剩多少余量。
- `tests/test_damped_ik.py`：新增 `test_dls_continuity_guard_names_the_joint_and_the_dry_run_hint`；预览用例补 `gap_deg` 断言。
- `docs/真机安全与故障处理.md` §7：补该门槛在比什么、步长预算的具体数值、dry-run 探索窗口的必然性、处置方式，以及预览字段表的 `gap_deg` 行。

- 离线演练（假臂 + 冻结实测 + 手柄匀速漂移）：`gap_deg` 由 `0.000` 递增到 `0.035`，40 个周期后锁存，报文为 `DLS J2 step exceeded limit (measured feedback): 0.404deg > 0.360deg (dry run never moves the real arm; release and re-grip to re-baseline)`——与现场现象一致，且现在自带解释与处置。

## 真机平移映射改为 15 cm 内 1:1

### 背景与改动

用户的 Dry Run 显示手柄主要轴位移 74.1 mm、目标平移 15.7 mm；用户明确要求在约 15 cm 范围内采用 1:1 平移映射。旧默认平移比例 0.25，之后还有 3 mm 连续径向死区与 3 cm 单次 Grip 包络，三者都会使目标小于手柄位移。

- `xrobotoolkit_teleop/hardware/realman_rm65_safe_teleop_controller.py`、`scripts/hardware/teleop_realman_rm65_safe_hardware.py`：真机平移比例默认改为 1.0，平移死区改为 0，单次 Grip 平移目标包络改为 0.15 m。侧装坐标变换、旋转比例及开关、速度/加速度限幅、关节步长、UDP 与故障锁存判据均未改。
- `config/realman_rm65_side_mount_teleop.json`：参考快照同步新默认；运行入口仍不自动加载该 JSON。
- `tests/test_realman_mapping.py`、`tests/test_realman_safe_controller.py`：更新入口断言，增加 1 mm、74.1 mm、150 mm 的目标平移 1:1 与 200 mm 输入截到 150 mm 的回归检查。
- `README.md`、`CLAUDE.md`、`docs/真机安全与故障处理.md`、`docs/项目交接.md`：同步当前参数及首次真机验收边界。

### 验证与边界

新增回归用例在旧默认下先失败（1 mm 输入被旧死区清零）；修改后映射与安全控制相关 41 项通过，完整离线测试 424 项通过。运行 `python teleop.py` 时硬件脚本会使用新默认并在启动前执行现有代码同步。首次尝试仅同步模式时，自动审批要求本次远程目的地的明确授权；用户在当前对话授权后，`python teleop.py --mode sync-only` 成功将 5 个变更文件同步到 `rm` 上的 `xrobo-vr-teleop:/workspace`。通过远程只读检查确认硬件入口及控制器默认值均为平移比例 1.0、单次 Grip 包络 0.15 m、平移死区 0.0；未启动机器人脚本或发送运动目标。上述验证覆盖本地源码、假臂测试及远程静态参数，不证明 XR 实测、真机跟随或物理安全。

Dry Run 不发送运动目标，UDP 实测关节保持原处；平移 1:1 后，原有“目标关节相对实测反馈不得超过一个周期步长”的锁存可能在更小手柄位移下触发。真机仍经 TCP 限速、DLS、关节限值/步长、工作空间、反馈新鲜度与故障锁存；15 cm 是锚点目标包络，不是每周期允许瞬移 15 cm。去掉平移死区会更直接反映 XR 静止噪声，首次真机运动仍需低速、小位移、净空、急停与现场监护；必要时显式用 `--max-offset-m 0.03` 收紧单段范围。
