## 3 唯一控制流程

键盘/页面按钮生成标记为manual的合成XR，或PICO提供原始XR → 同一InputAdapter有效性/Grip/映射/实测锚点 → 同一PoseTracking / Servo → 同一JTC → MuJoCo仿真或受控官方驱动。三个根入口分别为 `启动无手柄仿真.cmd`、`启动PICO仿真.cmd`、`启动真机.cmd`；manual仅限仿真，不发布关节命令或另行求解IK。默认 sim 使用 MuJoCo，GenericSystem 仅供 `--simulator mock` 诊断；共同模型和控制参数在 `ros2_ws/src/rm65_servo_teleop/config/`。操作见[手册](仿真操作手册.md)，最新验证见[当日日志](logs/2026.10.28.md)。

2026-10-27完整测试初跑因WSL墙钟校时跳变失败；按Ubuntu官方说明关闭专用WSL中重复的timesyncd、保留Hyper-V宿主校时后，原断言完整14组通过。此环境配置仅适用于该WSL，不应用到原生Ubuntu/板端；恢复方法与证据见[环境维护](本机仿真部署.md#环境维护)。

当前日常仿真只打开MuJoCo；RViz作为可选TF/模型/目标调试窗口，用 `python teleop.py --mode sim --target wsl --rviz` 显式打开。`--rviz` 仅支持WSL的sim模式且不能与 `--no-viewer` 同用，物理计算和Servo运动保护仍正常运行。

自研代码仍负责设备边界、输入协议和记录，这是接入所必需；不再实现另一套位姿控制、IK 或插值。当前没有 B/Home、启动自动回位或旧后端回退。

原 `RM65ControlCore` 属于本项目自研代码，已退出正式链路；不是 RM65 官方控制框架。官方部分是上游 ROS 驱动、模型和 SDK，新控制框架是 MoveIt Servo / ros2_control。
