## 1. 开发意图

把 **PICO 头显 + XRoboToolkit** 的 VR 手柄输入，映射到 **Realman RM65 六轴机械臂**的遥操作控制。机械臂为**侧装**（底座固定在垂直面，非水平地面安装）。

### 设计原则（按优先级）

1. **仿真先行、真机后置** —— 所有映射矩阵、scale、姿态跟随先在 Docker 仿真里验证，确认运动方向与手感合理后再动真机。
2. **仿真 IK 可选** —— 默认 RM65 URDF + Placo IK；`--ik-backend official` 使用睿尔曼官方 FK 建锚点、官方连续 IK 求关节，Placo 只用于 Meshcat 显示。
3. **真机不走 Placo IK** —— 显示 URDF 的 FK 不可替代控制器 TCP。真机默认为 DLS 受限关节跟随（`damped_ik_movej_follow`），使用官方 FK、显式工作/工具帧变换、DLS 局部关节步长与 UDP 检查。
4. **侧装专用映射** —— 不复用 UR5 桌面安装的 `R_headset_world`。仿真入口与真机控制器当前**均引用** `R_HEADSET_TO_WORLD_RM65_SIDE_MOUNT_HARDWARE`（代码为准，2026-09-09 定案并冻结）。
5. **代码-文档不一致时以代码为准**；历史计划类文档不改写。
6. **仿真映射必须符合人体直觉** —— 仿真是手感标定场，不能用真机适配矩阵反向定义仿真手感；方向以**逐轴实测**为准。
7. **可交接、可复现** —— 远程板 + 容器路径、端口、已知坑位写进本文档。
8. **代码改动须记入工作日志** —— 在 `docs/` 下按日期命名，含日期、修改文件、背景/原因、改动内容、验证状态。

### 当前阶段判断

仿真链路已打通并在持续优化。真机默认 DLS 链路已通过源码/主机测试、静态帧一致性检查和目标容器 1000 周期 Dry Run 时序验证：完整 `_send_motion` 准入链 median **10.169 ms**、P95 **11.782 ms**、max **14.397 ms**，在当前测试条件下满足 18/20 ms 预算；但**真实 `movej_follow`、XR 完整主循环、机械臂跟踪、方向手感与物理安全仍未完成最终验收**（历史优化提案见 [plans/2026.9.22-降低每周期FK调用.md](plans/2026.9.22-降低每周期FK调用.md)）。

> ⚠️ **不要跳过仿真、预检和 dry-run 直接上真机。**

## 3. 架构

```text
PICO 头显
  │  WiFi → 直连远程板「192.168.0.115:63901」(PC Service)
  ▼
远程板 realman
  容器 xrobo-vr-teleop
    ├─ RoboticsService :63901   ← 头显直连
    ├─ 仿真: Placo / 官方连续 IK → Meshcat :7000
    └─ 真机: DLS 受限关节跟随 → TCP 8080 → RM65 (192.168.10.18)
    └─ RM65 实时 UDP :8089      ← 独立安全反馈
      ▲
      │ SSH -L 18081→7000（Meshcat 反代到本机浏览器）
开发机（Windows）
```

**仿真路径**
```
XR delta → 侧装旋转矩阵 → 滤波 → 默认 Placo IK → 关节约束 → Meshcat
                            或 → 官方 FK 锚点 + 官方连续 IK → RM65-B 关节/J3/步长检查 → Meshcat
```

**真机路径**
```
XR delta → 侧装映射 → Grip 锚点 → 笛卡尔速度/加速度限幅
  → 官方 FK + 工作/工具帧变换 → 6×6 数值雅可比 → SVD 风险检测 → DLS 局部关节增量
  → 限位/局部路径/实测偏差/耗时检查 → movej_follow（默认）
RM65 实时 UDP → 关节速度/限位/错误/跟踪误差 → 软停止或硬停止 + 故障锁存
```

### 3.1 仿真与真机的一致性边界（2026-09-18 代码走查结论）

> **上游输入一层相同，输入调理以下全部分叉；安全保护层只有真机有。**

| 层 | 仿真 | 真机 |
|----|------|------|
| XR 读取 | 共用 `common/xr_client.py::XrClient` | 同左 |
| 侧装矩阵 | `R_HEADSET_TO_WORLD_RM65_SIDE_MOUNT_HARDWARE` | **同一个** |
| delta 计算 | `_process_xr_pose` 继承自基类 | **独立实现一份**（漂移风险点） |
| 旋转比例 | 无旋转缩放 | `rotation_scale_factor=0.25` |
| 单次包络 | 锚点偏移无上限 | `max_offset_m=0.03` / `max_rot_offset_rad=0.20` |
| 滤波 | `MotionFilter` 逐分量死区 + EMA | 连续径向死区（保方向）+ 跳变检查 |
| IK/命令 | Placo IK（本地求关节） | **本地不做 IK**，DLS 求受限关节目标 |
| 限速/调度 | 仅 `JointConstraints` | `CartesianCommandLimiter` + `FixedRateScheduler` 50 Hz 绝对截止 |
| 安全层 | **无 watchdog、无锁存**（XR 掉线停在原地） | UDP 反馈校验 + 故障锁存 + 解锁状态机 |
| 复位 | 线性 alpha 插值 | smoothstep + 限幅器 + 到位容差 + 超时判故障 |

**唯一"同一套算法"的组合**是仿真 `--ik-backend official` + 真机 `--motion-command official_ik_movej_follow`（两端都用 `rm_algo_ik_remote`，`max_joint_speed_ratio` 都是 `0.10`）。**但即使该组合也不等价**：

| 差异点 | 仿真 | 真机 |
|--------|------|------|
| seed 来源 | 内部上一已接受关节 | 新段首帧 = UDP 实测，其后 = 上一已接受目标；另加对实测状态的独立步长校验 |
| 锚点来源 | 官方 FK | UDP 实测 TCP 位姿 |
| J3 保护 | 硬性 `±5°` 排除区 | **无软件排除区**，改用人工确认 `--official-ik-j3-soft-limit-verified` |
| 启动门槛 | 无 | 必须显式传 `--official-ik-frames-verified` |
| 失败语义 | 打印 `[OFFICIAL IK HOLD]` 并保持当前关节 | 锁存故障 + 需松 Grip / 按 B 解锁 |

> 2026-09-19 起真机使用 `hardware/damped_ik.py`，仿真仍为 Placo / 官方连续 IK，**尚未接入新 DLS 后端**。旧 `hardware/singularity_avoidance.py` 仅供离线结构分析，**不能用其 URDF 雅可比批准真机 TCP 运动**。

### 已验证结论

- **仿真手感**：`scale_factor=1.5`，Grip 阈值 `0.2`。
- **官方参数边界**：RM65-B 工作半径 610 mm、RM65-6F 为 627 mm；这是**本体最大工作半径，不是安全遥操作空间**。
- **零位不是安全 Home**：官方将 `[0,0,0,0,0,0]` 列为边界奇异示意点；侧装 Home 必须现场验证。
- **关节步长限幅（仿真）曾导致映射异常**，已回退。
- **Placo IK + URDF 不适合直接上真机**；默认 DLS 依赖匹配版本的官方 FK，工作/工具帧不一致时**拒绝发送，不自动回退**。
- **SSH 反代 Meshcat** 是标准查看方式：`18081 → 容器 7000`。
- **`meshcat.geometry.Label` 不存在于任何已发布版本**（含 0.3.2），已改用球体指示灯（绿=就绪 / 橙=复位中）。
- **官方 MDH 表按字面无法建链**（`alpha(0)=0` 会推出 J1 与 J2 同轴）；改用仓库内官方 URDF 关节链。

### 未完成 / 待验收

1. **真机最终验收（首要）**：逐轴核对运动方向、`invert_tcp_xy` 是否足够、平移时手腕是否翻转。
2. **DLS 真实运动链待验收**：计算与安全准入时序已在目标容器通过 1000 周期 Dry Run；仍需在急停、净空和现场监护下验证真实 `movej_follow` 发送、XR 完整主循环、复位、跟踪与长时间运行。
3. **逐轴实测未定案**：2026-09-18 仿真口述观测与代码推导在 X/Y 上正好互换，真机观测栏为空，映射方向一致性尚无法判定。
4. `config/*.json` **未被代码自动加载**，参数靠 CLI 传入。
5. 真机/仿真 `scale_factor` 未对齐（仿真 `1.5` vs 真机 `0.25`）。
6. URDF mesh 二进制未补齐（`assets/realman/*/meshes/`）。

## 5. 可复现流程

### 5.1 前置条件

- 本机可 `ssh rm`（已配置 SSH 免密）
- 远程容器 `xrobo-vr-teleop` 存在且可 `docker exec`
- PICO 与**远程板**同一局域网（能 ping 通 `192.168.0.115`）
- 头显 XRoboToolkit：**Controller + Send** 开启，状态 **WORKING**

### 5.2 建立 SSH 隧道

```bash
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=20 -o ServerAliveCountMax=3 \
  -L 18081:127.0.0.1:7000 \
  -L 63901:127.0.0.1:63901 \
  rm
```

也可用 `scripts/tools/start_meshcat_viewer.sh` / `.bat` 自动完成。隧道窗口需**保持打开**。

> 隧道里的 `63901→63901` 仅供**本机调试**；头显**直连远程板** `192.168.0.115:63901`，不依赖这条转发。

### 5.3 启动仿真（单实例）

```bash
ssh rm "sudo docker exec xrobo-vr-teleop pkill -9 -f teleop_rm65_sim.py; \
  sudo docker exec xrobo-vr-teleop pkill -9 -f meshcat.servers.zmqserver; sleep 1; \
  sudo docker exec -d xrobo-vr-teleop bash -lc '
    source /opt/conda/etc/profile.d/conda.sh && conda activate xrobo &&
    export LD_LIBRARY_PATH=\$CONDA_PREFIX/lib:\${LD_LIBRARY_PATH:-} &&
    export XROBO_GRIP_THRESHOLD=0.2 XROBO_DEBUG=1 &&
    python -u /workspace/scripts/simulation/teleop_rm65_sim.py \
      --home-joint-deg J1 J2 J3 J4 J5 J6 \
      > /workspace/logs/remote_sim_rm65.log 2>&1
  '"
```

**一键替代**：`python teleop.py --mode sim --home-joint-deg J1 J2 J3 J4 J5 J6`

检查期望：`control_mode=pose`，`Open Placo/Meshcat: http://localhost:18081/static/`，**仅一个** 7000 监听。

```bash
ssh rm "sudo docker exec -i xrobo-vr-teleop bash -lc \
  'grep -E \"control_mode|Viewer URL|Open Placo\" /workspace/logs/remote_sim_rm65.log | tail -3; ss -tlnp | grep 700'"
```

操作细节与调参见 [仿真操作手册](仿真操作手册.md)。

## 7. 下一步工作（接手者优先级）

### 7.1 首要：真机验收

仿真已优化，接下来在真机做最终验收，逐项核对并记录：

| 检查项 | 期望 | 不符合时 |
|--------|------|----------|
| 手柄前/后/左/右/上/下 | 末端沿**侧装坐标系**合理方向运动 | 查 `invert_tcp_xy` 是否需单轴调整，或改侧装矩阵 |
| 旋转手腕 | 末端姿态跟随，无明显乱翻 | 查 Grip 锚点与姿态坐标映射 |
| 平移并旋转手腕 | 末端同步跟随位置与姿态 | 默认 `suppress_rotation_during_translation=False`；若出现危险乱翻，停止测试并显式改 `True` |
| Grip 松开 | 机械臂停止跟随 | 查 Grip 阈值参数 |
| 复位按钮 | B 键回到程序启动时记录的 TCP 位姿 | 启动前先确认实体姿态安全，再查 `reset_button` / `reset_duration_s` |

**验收标准**：团队确认真机运动方向与"现场侧装 RM65 的物理直觉"一致后，**冻结参数**。

### 7.2 DLS 周期预算：计算链已达标，真实运动待验收

旧 74-FK 路径曾在目标容器实测 `DampedIK.step` **35.6 ms**、完整周期 **38.2 ms**，超过 20 ms 预算。2026-09-23 落地的保守 bounded-search 将正常跟踪降为 14 次 FK、结构硬上限降为 16 次；目标容器随后完成 1000 周期、全部 `tracking` 的 Dry Run：独立 `DampedIK.step` median **7.368 ms** / P95 **8.894 ms** / max **14.829 ms**，完整 `_send_motion` 准入链 median **10.169 ms** / P95 **11.782 ms** / max **14.397 ms**。测试姿态位于奇异减速区（`ratio=0.03189`、`scale=0.730`），未出现 `hold_budget`、Safety Stop 或 100 ms 级长尾。

因此，**当前结论是计算与安全准入链在该实测条件下满足 50 Hz 预算**。基准以 `dry_run=True` 阻止目标和停止命令下发，尚未覆盖真实 `movej_follow` 网络发送、XR 每帧取值、机械臂实际跟踪、方向手感或物理安全；这些仍属于真机最终验收，不得由本节时序数据替代。

- 方案与归因：[决策与结论汇总.md](决策与结论汇总.md) §2.10、§5
- 正式设计：[plans/2026.9.22-降低每周期FK调用.md](plans/2026.9.22-降低每周期FK调用.md)
- 原阶段执行约束与对拍纪律见 [决策与结论汇总.md](决策与结论汇总.md) §5.2；它们用于审计历史实施过程，**不代表当前调用链或待执行任务**。

## 8. 常见问题

| 现象 | 原因 | 处理 |
|------|------|------|
| Meshcat 只有网格无机械臂 | 多实例 / 端口错位 | 杀旧进程；隧道 `18081→7000`；浏览器只开 18081 |
| `18081` 无法访问 | 隧道未建或板子离线 | 确认 `ssh rm` 通（宿舍用 `ssh rm-ts`）；重建隧道 |
| `ssh rm` 超时 | Tailscale backend stopped | `tailscale up`；LAN 不通时检查是否已回退 Tailscale |
| `grip=0.00` 不动 | 头显未开 Send/Controller | 头显里打开并确认 WORKING |
| 仿真 import 报错 | 用了 base Python (3.13) | 用 `/opt/conda/envs/xrobo/bin/python` 或一键脚本 |
| 映射突然错误 | 容器内旧代码 | `docker cp` 后重启仿真 |
| SSH 隧道断开 | 远程重启 / 网络 | 重建隧道 + 重启仿真 |
| 真机卡死、扣 Grip 不动 | 故障锁存 | 见 [真机安全与故障处理](真机安全与故障处理.md) §4 解锁四步 |
