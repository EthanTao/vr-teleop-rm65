# 2026.9.25 工作日志

## 真机控制核心接入仿真

### 背景

原有仿真默认使用 Placo，官方 IK 仿真也不运行真机默认的 DLS 安全准入链；真机 Dry Run 的实测反馈不随命令运动，连续性守卫只允许约一个周期的探索。用户选择让仿真与真机运行同一控制核心。

### 修改文件与内容

- `xrobotoolkit_teleop/hardware/realman_rm65_safe_teleop_controller.py`：将现有控制状态机命名为 `RM65ControlCore`，保留 `RealmanRM65SafeTeleopController` 硬件入口继承它；映射、限速、DLS、反馈检查、步长、故障锁存和判据未放宽。增加仿真预览标签 `SIM`。
- `xrobotoolkit_teleop/simulation/rm65_shared_control_simulation.py`：虚拟关节执行端、基于同一官方 FK 帧的反馈端、Meshcat 关节显示端共用 `RM65ControlCore`。反馈立即跟随已接受的关节命令，且命令按真实接口的 0.001° 单位量化。
- `scripts/simulation/teleop_rm65_sim.py` 与 `teleop.py`：增加显式 `shared-dls` 仿真后端；Placo 与官方 IK 后端保留。
- `scripts/simulation/capture_rm65_calibration.py`、`scripts/tools/fetch_rm65_dls_calibration.py`：提供只读采集控制器软件信息、DH、工具帧的路径；`config/rm65_dls_calibration.json` 在 `.gitignore` 中忽略，但启动器会按现有同步机制上传本地快照。
- `tests/test_rm65_shared_control_simulation.py`：对拍真机/仿真同一 DLS 目标的关节输出；验证帧不一致时仿真同样故障锁存且不发命令。
- `README.md`、`CLAUDE.md`、`docs/仿真操作手册.md`：补充入口和证据边界。

### 适用边界

`shared-dls` 要求当前控制器 DH/工具帧快照，缺失即拒绝启动。本次已读取并同步现场快照。它验证控制决策和虚拟关节目标；虚拟反馈立即跟随命令，不证明 UDP 时延、伺服跟踪、碰撞或真实运动安全。真机首次运动仍按独立低速现场验收流程执行。
