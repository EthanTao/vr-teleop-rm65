# RM65 真机故障解锁（操作手册）

> 适用：`scripts/hardware/teleop_realman_rm65_safe_hardware.py`（推荐真机入口）。
> 依据代码：`xrobotoolkit_teleop/hardware/realman_rm65_safe_teleop_controller.py`
> （`_latch_safety_fault`、`_enter_rearm`、`_handle_rearm`、`_feedback_allows_rearm`）。
> 更新日期：2026-09-19。代码为准，本页只做操作说明。

## 1. 快速卡片（卡死后照做）

```
① 松开 Grip（扳机）—— 一点都别扣
② 按一下 B 键 —— 松开再按，不是长按
③ 等这行字出现：
   [SAFETY] re-arm acknowledged; press Grip again to move
④ 再扣一次 Grip —— 机械臂才恢复跟随
```

没出现 ③ 就说明条件没到，**先找原因，不要反复猛按 B**。

## 2. 为什么会「卡死」

程序里有两类停止，表现完全不同：

| 现象 | 触发 | 怎么恢复 |
|------|------|----------|
| 松手就停，扣上还能动 | 正常松开 Grip → 软停止 `set_arm_slow_stop` | 不用解锁，重新扣 Grip 即可（会用最新实测位姿重新建锚点） |
| 怎么扣都不动，终端打 `[SAFETY]` | 安全故障 → 硬停止 `set_arm_stop` + **故障锁存** | 走第 3 节的四步解锁 |

会触发硬停止并锁存的情况：UDP 反馈超时（默认 0.20 s）、关节超速/越界、控制器错误码、TCP 跟踪误差超限、XR 追踪超时或单帧跳变、目标越出 XYZ 边界、通信失败。

**锁存 ≠ 只停一下。** 锁存后程序不再下发任何运动目标，锁一直保持到人工解锁为止。

> **DLS HOLD 与故障锁存不同。** `[DLS] hold_*` 请求软停止，等待实测静止，再尝试受限的退出方向；单纯 HOLD 不需要 B。停止未确认、帧不匹配、反馈失效等会锁存。不能保证把手柄反向移动就一定能退出。详见[奇异区域保护](奇异区域保护.md)。

## 3. 解锁四步（顺序不能变）

### 第 1 步：完全松开 Grip

故障锁存的那一刻，软件已经把「握持中」状态强制清掉了，但它还必须**亲眼看到** XR 上报的 Grip 值 ≤ `grip_off_threshold`（默认 `0.15`）才会记为「已松手」。

- 扣着不动，后面按 B 一律无效。
- 阈值可用 `--grip-off-threshold` 改。

### 第 2 步：按一下 B 键

- 必须是**一次新的按下（上升沿）**。如果发生故障时 B 正好被你按住，那次不算，要松开再按。
- 按钮名默认 `B`，可用 `--reset-button` 改。
- 此状态下（`_rearm_required=True`）程序每个周期只处理解锁判断，**不会下发运动指令**，所以这时候扣着 Grip 也不会动。

### 第 3 步：B 按下瞬间必须同时满足三条

| 条件 | 默认值 | 参数 |
|------|--------|------|
| UDP 反馈线程无错误 | — | — |
| 最新反馈帧足够新 | ≤ `0.20 s` | `--udp-feedback-timeout-s` |
| 反馈无错误码、关节角在限位内 | — | — |
| 六个关节速度全部够慢 | ≤ `1 °/s` | `--rearm-stationary-speed-rad-s` |

任一条不满足，终端打印：

```
[SAFETY] B ignored: wait for fresh, error-free, stationary joint feedback
```

**这不是 B 键坏了，是条件没到。** 等机械臂真正停稳、反馈恢复正常，再按一次。

### 第 4 步：看到确认行才算成功

```
[SAFETY] re-arm acknowledged; press Grip again to move
```

此时故障锁存被清除、锚点被清空。**再扣一次 Grip**：第一个握持周期只做「用最新 UDP 实测 TCP 位姿重新建锚点」，不会立刻下发运动目标。这只能说明锚点不会直接沿用旧值，不能据此保证后续关节不突变。新默认 DLS 路径从实测关节起步，检查每周期步长和局部奇异风险后才允许发送。

## 4. 按了没反应 / 解锁完又卡

| 现象 | 原因 | 处理 |
|------|------|------|
| 一直打 `B ignored: ...` | 机械臂还没停稳，或反馈断了 | 等停稳；查 8089 UDP 反馈是否在推送（容器端口映射、`tcpdump -i any udp port 8089 -n`） |
| 按 B 完全无打印 | B 不是新的按下沿（一直按着）；或按钮名不对 | 松开 B 再按；确认 `--reset-button` |
| 解锁成功但立刻又锁存 | **根因没修**：网络抖动、XR 丢失、控制器报警仍在 | 先看 `fault_reason` 属于哪一类，修好链路/清掉控制器报警再解锁 |
| 机器人本体报错 | `RM65 reported error codes: [...]` | 先在睿尔曼侧清除控制器报警，否则第 3 步永远过不了 |

> ⚠️ **解锁只清锁存，不修根因。** 不修根因的话，按 B 要么被拒，要么解锁后同一原因再次触发硬停止。

## 5. 别乱按 B

**没有故障的时候，B 键不是解锁，是「回启动姿势」。**

- 按下 B 会让机械臂按 `--reset-duration-s`（默认 3.0 s，为最短插值时长）尝试回到**程序启动时记录的 TCP 位姿**。
- 复位先软停止并清空锚点，会打断当前握持；每个回程目标也经过 DLS 门槛，受阻时不会硬穿奇异区域，持续无法到达会超时锁存。
- 启动位姿是程序开机时从 UDP 抓的实测姿态，程序**不会**根据工作半径自动生成安全 Home Pose——所以按 B 之前必须确认回程路径上没有人、没有障碍。

结论：**只在需要复位、或终端明确处于故障锁存状态时才按 B。**

## 6. 相关参数速查

| 参数 | 默认 | 作用 |
|------|------|------|
| `--reset-button` | `B` | 复位/解锁按钮 |
| `--reset-duration-s` | `3.0` | 回启动位姿的时长 |
| `--grip-on-threshold` / `--grip-off-threshold` | `0.2` / `0.15` | Grip 使能/松开判据 |
| `--udp-feedback-timeout-s` | `0.20` | 反馈新鲜度看门狗 |
| `--rearm-stationary-speed-rad-s` | `1 °/s` | 解锁允许的最大关节速度 |
| `--scale-factor` / `--rotation-scale-factor` | `0.25` / `0.25` | 手柄平移 / 旋转到机械臂的比例 |
| `--max-offset-m` / `--max-rot-offset-rad` | `0.03` / `0.20` | 单次 Grip 的平移 / 旋转包络（约 3 cm / 11.5°） |
| `--max-xr-step-m` / `--max-xr-rot-step-rad` | `0.05` / `0.26` | XR 单帧跳变上限，超限即锁存 |
| `--enable-singularity-avoidance` | 开启 | 默认 DLS 模式必须开启；旧模式须显式关闭，且无此保护 |
| `--singularity-slowdown-joint-deg` / `--singularity-stop-joint-deg` | `15` / `5` | J3、J5 的降速起点 / 危险区起点（度） |
| `--singularity-slowdown-ratio` / `--singularity-stop-ratio` | `0.04` / `0.01` | 雅可比 σ_min/σ_max 的降速起点 / 危险区起点 |
| `--singularity-escape-speed-scale` | `0.10` | 退出方向的请求比例下限；仍受步长、限位和路径检查约束 |

## 7. 上机前自检清单

- [ ] 急停在手可达位置，工作区内清空
- [ ] 启动前确认**当前实体姿态**安全（程序以开机实测姿态为 Home，不会自动避障）
- [ ] `python scripts/hardware/preflight_realman_rm65.py --arm-host 192.168.10.18 --arm-port 8080` 只读预检通过
- [ ] 首次先用 `--dry-run`，再做低速小范围实测（默认包络已是 `--max-offset-m 0.03`，无需额外收紧）
- [ ] 故意触发一次软停止（松 Grip）与一次硬停止，确认日志关键字与第 3、4 节一致
- [ ] 先用离线测试验证奇异区边界，再用 `--dry-run` 核对当前姿态的 FK/UDP 一致性与时序；不要为测试主动把真机推入奇异点
