## 真机与仿真逻辑对照（纯代码走查，未改代码）

### 背景

现场提问「真机现在和仿真是一样的逻辑吗」。本次不凭记忆、不引入新功能，逐文件读两端入口与控制器（仿真 `scripts/simulation/teleop_rm65_sim.py` + `simulation/placo_teleop_controller.py` + `simulation/realman_official_ik_teleop_controller.py`；真机 `scripts/hardware/teleop_realman_rm65_safe_hardware.py` + `hardware/realman_rm65_safe_teleop_controller.py`；共用 `common/base_teleop_controller.py`、`utils/geometry.py`、`hardware/realman_official_ik.py`），把「同 / 不同」按层记下来，供后续判断仿真能否作为手感标定场。

### 结论

**上游输入一层相同，输入调理以下全部分叉；安全保护层只有真机有。**

### 1. 相同的一层（XR 输入 → delta）

| 环节 | 依据 |
| --- | --- |
| XR 数据读取 | 两端同用 `common/xr_client.py::XrClient` |
| 侧装映射矩阵 | 仿真 `teleop_rm65_sim.py:69` 与真机 `realman_rm65_safe_teleop_controller.py:174` 均引用 `R_HEADSET_TO_WORLD_RM65_SIDE_MOUNT_HARDWARE` |
| 四元数重排 + 旋转、delta 运算 | 两端各写一份 `_process_xr_pose`（仿真继承 `base_teleop_controller.py:96`；真机独立实现 `realman_rm65_safe_teleop_controller.py:298`），共用 `utils/geometry.py` 的 `quat_diff_as_angle_axis` / `apply_delta_pose` |

即：几何常量与 delta 数学是共享的，但「读手柄算 delta」这段是两份独立实现——仍是 `CLAUDE.md` 第 11 条要防的漂移点。

### 2. 输入调理层：真机多一环，且参数不回读仿真

真机在共用 delta 之上另有（`realman_rm65_safe_teleop_controller.py:321-343`）：

- 旋转比例 `rotation_scale_factor=0.4`（L322-325）——仿真无旋转缩放，`delta_rot` 直接用于目标姿态；
- 单次握持包络 `max_offset_m=0.05 m` / `max_rot_offset_rad=0.35 rad`（L330-334）——仿真锚点偏移无上限；
- 连续径向死区 `continuous_radial_deadzone`（L335-336，保方向）vs 仿真 `MotionFilter` 的逐分量死区 + EMA（`simulation/motion_filter.py:52-57`）——两种不同滤波；
- XR 跳变检查 `max_xr_step_m` / `max_xr_rot_step_rad`、平移快时旋转增益归零、`invert_tcp_xy`、`freeze_rotation`（L337-342、L512-539）——仿真侧无对应物。

比例本身未对齐：仿真 `scale_factor=1.5`（`teleop_rm65_sim.py:24`），真机 `0.4`（`teleop_realman_rm65_safe_hardware.py:14`）。`VR_TELEOP_HANDOFF.md` 记录的「1.5 vs 1.2」已过期，现为 1.5 vs 0.4。

### 3. 主干（IK / 命令）层：默认不是同一个后端

- 仿真默认 `ik_backend=placo` → `PlacoTeleopController`，本地 Placo IK 求关节（并加 `joints_regularization` 软任务，`teleop_rm65_sim.py:98-100`）。
- 真机默认 `motion_command="movep_follow"`（`teleop_realman_rm65_safe_hardware.py:41`）→ **本地不做 IK**：锚点 TCP 位姿 + delta → 限幅 → `send_movep_follow_xyz_quat`（`hardware/interface/realman_rm65.py:422`）直接下发笛卡尔目标，关节解算在 RM65 控制器内部。

唯一「同一套算法」的组合是仿真 `--ik-backend official` + 真机 `--motion-command official_ik_movej_follow`：两端都用 `hardware/realman_official_ik.py::RealmanOfficialRemoteIK`（`rm_algo_ik_remote`），`max_joint_speed_ratio` 也都是 `0.10`（`teleop_rm65_sim.py:32`、`teleop_realman_rm65_safe_hardware.py:57`）。**但即使该组合也不等价**：

| 对照项 | 仿真 official | 真机 official_ik_movej_follow |
| --- | --- | --- |
| seed 来源 | 仿真内部上一已接受关节（`realman_official_ik_teleop_controller.py:101`） | 新段首帧 = UDP 实测，其后 = 上一已接受目标（safe controller L556）；另加对实测状态的独立步长校验（L586-596） |
| 锚点来源 | 官方 FK `official_ik_solver.forward`（同文件 L68-72） | UDP 实测 TCP 位姿（L481-483、L499-510） |
| J3 保护 | 硬性排除区 `±5°`（`simulation/realman_official_ik_guard.py:59`）+ 初始构型检查（L65-66） | 无软件排除区，改用人工确认 `--official-ik-j3-soft-limit-verified` |
| 启动门槛 | 无 | 必须显式传 `--official-ik-frames-verified`（L133-139）才允许 |
| 失败语义 | 打印 `[OFFICIAL IK HOLD]` 并保持当前关节（L84-89、L109-111） | 锁存故障 + 需松 Grip / 按 B 解锁 |

### 4. 只有真机有的一层

`CartesianCommandLimiter` 线/角速度与加速度限幅（L214-219）、`FixedRateScheduler` 固定 50 Hz 绝对截止调度（L484、L1037-1040）、UDP 独立反馈校验（反馈新鲜度、关节超速、跟踪误差、错误码，L375-448）、故障锁存与解锁（L362-367、L749-765）。仿真侧只有 `JointConstraints` 关节限位裁剪 + 可选速度限制（`simulation/joint_constraints.py:51-60`）与官方 IK guard，**无 watchdog、无锁存**：XR 掉线仿真停在原地，真机硬停并锁存。

复位形式相同（B 键上升沿、插值回启动位姿），但真机为 smoothstep + 限幅器 + 到位容差 + 超时判故障（L685-728），仿真为线性 alpha 插值（`placo_teleop_controller.py:190-206`）。

### 5. 已知未定案项（阻碍「仿真当标定场」）

仿真侧手柄轴向本身尚未实测定案：`坐标系语义.md` §7.3 记录 2026-09-18 口述观测（左右→X、上下→Y）与代码推导（上下→X、左右→Y）在 X/Y 上正好互换，真机观测栏为空。该结论在实测定案前，仿真与真机的方向一致性无法判定。

### 验证

- 纯代码走查 + 日志记录，**未改任何代码**，未运行测试（本机无 meshcat / XR SDK）。
- 上述行号与参数值均在本次会话中逐条读文件核对，非记忆转述。

## 真机奇异点保护（检测 + 自动减速 + 阻尼 IK，2026-09-18）

### 背景

### 运动学模型：为什么不用官方 MDH 表

`docs/rm65-ontology-parameters.md` §3 转抄的官方 MDH 表中 `alpha(0) = 0`，按 MDH 定义会推出 `z1 ∥ z0`，即 **J1 与 J2 同轴**，与 RM65 物理结构矛盾——该表按字面无法直接建链（α 列存在错位/转抄问题，待另行核对官方页面）。本次改用仓库内**官方 URDF** 的关节链：

- `assets/realman/RM65-official/urdf/RM65-official-arm.urdf`：每关节固定 `<origin xyz rpy>` + 绕本地 `z` 旋转；连杆量级与官方表一致（`d1=240.5`、`a2=256`、`d4=210`），官方表缺失的末杆偏置由 URDF 给出 `d6=112.03 mm`。
- `test_hardcoded_chain_matches_the_vendor_urdf` 直接解析 URDF 复核模块内常量（xyz 完全一致，rpy 差 `7.35e-6 rad`，即 URDF 只写 4 位小数）；`test_kinematics_match_the_urdf_derived_chain` 复核 FK/Jacobian（差 `≤7.5e-6`）；`test_analytic_jacobian_matches_finite_differences` 复核解析雅可比（最大误差 `2.35e-8`）。
- 该模型**只用于可操作度判断**：绝对位姿不得与真机 TCP 反馈比较（`CLAUDE.md` 第 2 条）。判定量是无量纲的 `σ_min/σ_max`（条件数倒数）。

### 判据与阈值（本次定标数据）

`σ_min/σ_max` 实测（官方链，`J1=0, J2=-30, J3=55, J4=0, J6=0`）：

| 位形 | 比值 | 说明 |
| --- | --- | --- |
| J5 = 30° / 20° | 0.0104 / 0.0083 | 正常姿态 |
| J5 = 15° / 10° / 5° / 1° | 0.0069 / 0.0051 / 0.0029 / 0.0006 | 腕部奇异（J5→0） |
| J3 = 15° / 10° / 5° / 2° | 0.0134 / 0.0090 / 0.0045 / 0.0018 | 肘部奇异（J3→0） |
| **J2=-25°, J3=55°, J5=60°** | **0.00109** | **肩部奇异：J4/5/6 轴线交点距 J1 轴仅 3.2 mm，而 J3/J5 都是「健康」的中间值** |

最后一行是本次最关键的数据：只看 J3/J5 的旧判据**完全漏掉**这类位形，只有雅可比判据能抓到。故 `severity = max(雅可比比值斜坡, |J3| 斜坡, |J5| 斜坡)`。

默认阈值（真机入口与控制器一致）：

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| `--singularity-slowdown-ratio` | `0.004` | 低于此比值开始降速（约对应 J5/J3 ≈ 15°） |
| `--singularity-stop-ratio` | `0.0012` | 低于此比值进入危险区 |
| `--singularity-slowdown-joint-deg` / `--singularity-stop-joint-deg` | `15` / `5` | 官方 J3/J5 判据的降速 / 危险起点 |
| `--singularity-min-speed-scale` | `0.05` | 危险区内往里的速度上限（≈5%） |
| `--singularity-escape-speed-scale` | `0.50` | **离开**奇异点时的速度下限（保证能出来） |
| `--singularity-max-damping` | `0.08` | DLS 最大阻尼 λ（按 severity 线性加载） |
| `--singularity-report-interval-s` | `2.0` | `[SINGULARITY]` 打印限频 |

`0.004 / 0.0012` 是按实测分布选的：舒适位形比值 0.005–0.07，「可用工作区」扫描（J2 −60…0、J3 20…90、J5 20…90）448 个采样中 clear 422 / slowdown 21 / danger 5。

### 算法（每控制周期，仅真机路径）

1. **检测**：UDP 实测关节 → 几何雅可比 → SVD → `σ_min/σ_max`、`score = -log10(ratio)`，叠加 `|J3|`、`|J5|` 得 `severity ∈ [0,1]` 与 `zone ∈ {clear, slowdown, danger}`。
2. **自动减速**：`speed_scale = 1 - severity × (1 - 0.05)`，通过 `CartesianCommandLimiter.set_speed_scale()` 统一缩放线/角速度与加速度上限（目标不变，因此天然平滑、不会突跳）。
3. **阻尼 IK（DLS）**：`dq = Jᵀ(JJᵀ + λ²I)⁻¹·v`，λ 随 `severity` 线性增大。实测效果（10 mm「最难方向」位移）：

   | 位形 | 无阻尼伪逆 | DLS（λ=0.08） |
   | --- | --- | --- |
   | 肩部奇异 `[0,-25,55,0,60,0]` | **208.6°** | **0.12°** |
   | 边界/肩部 `[0,-40,90,0,20,0]` | **429.8°** | **0.07°** |

   即用户描述的「普通 IK 在奇异点附近突然给出很大的关节速度」被阻尼压到每周期预算以内。
4. **方向门控（只拦往里、不锁死出来）**：用**无阻尼最小二乘方向**做 1° 关节空间探针判断「这条命令是否让奇异度变深」（阻尼步会主动抑制危险方向、无法用来判方向，故探针与阻尼分离）；`danger` 区且判为往里 → `hold`：目标冻结在当前已发命令位姿，靠既有加速度限制平滑停住；判为离开 → 至少给 `escape_speed_scale` 放行。
5. **关节步长预算**：`step_scale = min(1, 预算/峰值预测步长)`，其中预算复用既有 `max_joint_velocity × max_joint_speed_ratio × dt`；命令先按单周期位移（`v_max·dt` 与 `ω_max·dt` 取同一比例缩放，保持方向）折算再预测。
6. **官方 IK 路径**：`_solve_joint_target()` 里对厂商解出的关节目标直接做 `joint_gate`（我方模型能精确评估目标位形），判为往里则**本周期不下发**、返回「已处理」而非故障；离开则照常下发。

**clear 区不介入**：`current` 与 `probe` 都在 clear 时强制 `speed_scale = 1.0`（既有的关节超速 watchdog 仍在该区兜底）。随机 3783 个 clear 位形 × 1 mm/0.005 rad 随机方向：最差 0.097、p5 = p50 = 1.000、`hold` 0 次——正常遥操作手感逐位不变。

### 工程语义与安全边界

- 保护**只减速、只拦「往奇异点里走」**，永远不会增加命令；`hold` 由冻结目标 + 加速度限制实现，不是硬停、**不锁存故障**（终端是 `[SINGULARITY]` 而非 `[SAFETY]`），无需按 B 解锁，把手柄往回带即恢复跟随。
- 不改动：几何映射、Grip 锚定/门限、包络、死区、XR 跳变检查、UDP watchdog、超速锁存、软/硬停止、B 键复位语义、官方 IK 的坐标/软限位门槛。B 键复位是显式操作，**不**受奇异点缩放影响。
- 诊断：`--log-motion-debug` 会多打一行 `singularity: ...`；`--motion-log-path` 的 jsonl 每周期新增 `singularity_zone / sigma_min / sigma_ratio / predicted_ratio / severity / speed_scale / damping / step_scale / inward / hold / reasons` 字段。
- 关闭方式：`--no-enable-singularity-avoidance`（构造控制器时 `enable_singularity_avoidance=False`），关闭后限幅器恒为 1.0，行为与改动前一致。该写法已用 tyro 1.0.16 实测确认（`--enable-singularity-avoidance, --no-enable-singularity-avoidance` 解析为 `True / False`）。
- `teleop.py` 未改：与幅度参数同一决定，启动器不传奇异点参数，自动继承真机入口默认值。
