# RM65 真机 IK 工程工作流

## 范围

处理本仓库的真机 IK 链路，包括目标位姿生成、官方 IK 与 DLS 路径、关节命令安全门控、发送以及反馈相关的代码和诊断。当前不处理数据采集或数据集构建；以后有明确需求时再扩展或另建 skill。

使用中文报告。优先交付可核对的结论、核心调用链和设计理由，以及按项目惯例写入的当日工作日志。最终说明不必逐行讲解代码，但要给出改动位置和验证依据。

## 开始前

1. 阅读适用的 `AGENTS.md`、`CLAUDE.md`、`docs/真机安全与故障处理.md`、`docs/决策与结论汇总.md` 中与本次任务有关的部分，以及最近的工作日志；检查 `git status`。保留已有未提交工作，不覆盖或顺手清理无关改动。
2. 找到当前实际使用的真机入口、配置来源和运行参数。不要仅凭文件名或历史记录认定某个脚本仍是入口；区分代码默认值、配置快照和运行时覆盖值。
3. 在修改前画出本次问题涉及的调用链：操作者输入或目标位姿 → 坐标变换与约束 → IK 求解 → 轨迹或关节安全检查 → 命令发送 → 最新反馈。明确每段的输入、输出、单位、坐标系、线程或周期，以及故障时的行为。固定六轴 Home 回位有独立分支，先核对其预检开关与实际发送路径，不要默认它经过 DLS。
4. 先复现或取得可比基线。记录报错层级、触发条件、关键日志和计时；将已验证事实与待验证假设分开。无法复现时，说明缺少的输入或环境，不把猜测写成根因。

## 协作与证据方式

- 先确认用户实际启动的入口、后端、运行参数、输入状态和当前工作树，再沿“操作者输入 → 激活条件 → 坐标与目标 → 限幅 → IK → 安全准入 → 命令 → 最新反馈/显示”定位。仿真、Dry Run、远程容器和真机路径分别取证；不要把其中一条路径的根因套到另一条。
- 优先用用户提供的原始日志和最小可比实验定位具体分支。指出判据比较的是哪两个量、数值和周期各是多少、拒绝后程序做了什么。清楚标明现场事实、源码行为、离线复现和推测；证据不完整时只把结论落到证据支持的层级。
- 运动实验必须确认操作者确实执行了指定输入。若用户说明某轮没有按要求操作，该轮不用于判断；重跑后观测整个过程中的关节/末端状态，不以启动成功、求解器没有报错或终点回到近似位置代替运动证据。
- 用户认为限制过严时，先定量查明是哪项保护拒绝了什么量。比较命令步长、相对实测反馈的偏差、反馈年龄和目标变化等相关变量，不先假定是奇异区。先提供能够复现触发行为的数据和最小改动建议；任何改变安全阈值、锁存、停止或准入行为的改动，仍遵守下节的明确授权及差分验证要求。
- 进度沟通简短及时，先说已确认的发现和仍未知之处；只询问会改变下一步的必要信息。已有授权且范围明确时继续完成授权工作；涉及用户补充的安全授权时，按项目安全约定说明具体动作和依据，不重复询问已给出的授权。
- 交付按项目惯例写入当日工作日志，分别写清本机测试、仿真、Dry Run、真实命令发送和实体运动各自验证了什么及未覆盖什么。最终用中文先给结论，再给最关键证据、限制和下一步，并链接实际改动与记录位置。

## 不可擅自改变的行为

- 默认保持现有安全判据及其阈值、采样方式、超时、故障锁存、退化行为、命令发送顺序和发送策略不变。优化计算量或代码组织时，先证明这些语义保持一致。
- 若任务确实需要改变上述任一项，先列出旧行为、新行为、风险和验证方案，并取得用户明确同意后再实施。性能提升本身不能作为放宽安全门控的理由。
- 对安全判定做旧版与新版的差分检查；特别关注旧版拒绝而新版允许的样本。出现这种差异时停止该阶段的优化，定位原因并向用户报告，不继续叠加修改。
- 保持实时路径的计算有确定上界。超预算或求解失败时沿用现有保持、减速停机或故障处理语义，不让一次求解无限延长控制周期。
- 用户已授权本项目所需的所有只读检查，包括读取远程板和容器中的状态、日志、配置与文件；执行这些检查无需逐条请示。远程板上确有必要的只读 `sudo` 命令也在此授权范围内，但先尝试无需 `sudo` 的方式，并核实具体命令不会改变状态或输出无关凭据。只读检查不得借机重启服务、改写文件、同步代码或触发运动。
- 真实机器人运动、执行器使能、远程代码同步及改变远程运行状态前，核对当前会话是否已有针对该目的地和动作的授权；没有时先完成本地可做的分析、改动和验证，再请求明确授权。任何可能写入或改变状态的远程 `sudo` 命令仍需对具体命令和目的取得明确授权。

## 分阶段处理

1. **定位瓶颈或故障。** 分开测量目标生成、FK、Jacobian、DLS 线性代数、候选解筛选、安全检查、反馈读取和日志开销。记录运行环境、样本数量、分位延迟、最长耗时和控制周期；不要只用平均值说明实时性。
2. **提出最小改动。** 说明改动要减少的计算或修复的分支、可能影响的路径，以及保持不变的安全语义。一次只引入便于比较的一类优化，避免同时修改算法、阈值和发送逻辑。
3. **实现并审查。** 检查数值稳定性、关节限位、奇异位形附近的行为、解的连续性、超时与异常分支；核对输入目标与最新反馈是否混用。不要用输出位姿变化直接推断操作者手部运动，应沿输入、变换、目标、限幅命令和反馈逐段追踪。
4. **验证。** 运行与改动对应的主机测试和差分测试；能访问目标容器时再做目标环境的计时与 Dry Run。主机测试、目标容器计算或准入检查、Dry Run、真实发送和实体机器人运动分别记录。一次通过不能代替其他层级的证据。
5. **记录与交付。** 按仓库现有位置和格式更新当日工作日志。写明问题、核心调用链、改动理由、关键测量、验证命令及结果、未验证边界和下一步。最终回复先给一句结论，再用短段落说明核心逻辑、证据、风险或限制；只在必要时展开代码细节。

## 遇到阻碍时

优先完成不依赖远程板或真机的部分。若本地或远程环境不可用，保留可复现步骤和已经取得的证据，明确说明哪些结论尚未验证；不得把模拟、Dry Run 或历史日志称作本次实体机器人验收。
